# M3 VAD 시작 여유·200ms 왼쪽 문맥 비교

2026-11-03 작업 계획. [이전 150개 비교](../../../results/summaries/m3-segmented-accuracy-20261102.md)에서 문맥 0의 VAD CER가 5.56%로 전체 발화 5.16%보다 높았다. 이번에는 아래 한 후보를 결과 확인 전에 고정한다. 기존 원시·모델·환경·입력/정답·음량·VAD 임계값은 유지한다.

[실측 보고서](../../../results/summaries/m3-vad-context-20261103.md): 159/159 성공. 200ms 후보는 KSS 5.42%·합성 장문 7.58%로, 문맥 0의 5.56%·6.37%에 비해 자료별 손익이 달라 일괄 채택하지 않았다. 아래 조건은 결과 전에 고정한 계획이다.

## 고정한 후보와 대조군

| 조건 | 소유 구간 | ASR payload |
| --- | --- | --- |
| `full_batch` | 원본 전체 | 원본 전체 |
| `bounded_vad_5s` | 기존 VAD, 소유 상한 5초 | 소유 PCM만 |
| `bounded_vad_5s_context200ms` | 위 VAD와 같은 소유 구간 | 소유 시작 전 최대 3,200프레임의 실제 원음부터 소유 끝까지 |

문맥은 기존 `SegmentPipeline(context_frames=3200)`의 유한 버퍼를 그대로 사용한다. 음성 시작에서 여유를 주는 효과와 연속 구간에서 왼쪽 문맥을 주는 효과가 같은 정책에 포함되므로 두 원인의 독립 효과를 주장하지 않는다. 원본 시작에서는 0프레임으로 잘라 적용한다. 인위적인 무음·추가 미래 입력은 붙이지 않는다. 소유 구간은 겹치지 않고 최대 80,000프레임, 문맥 포함 payload는 최대 83,200프레임이다. VAD 상태는 원본 발화마다 reset하고 분할 중에는 유지한다.

단일 공백 연결·중복 전사 제거 없음·금칙어 없음·전체 WAV fallback 없음·빈 검출의 원본 전체 정답 채점을 유지한다. 문맥의 중복 음성 때문에 삽입 오류가 늘어날 가능성도 그대로 측정한다. 같은 입력의 문맥 0/200ms 조건에서 소유 경계가 같은지 확인하고, 소유 프레임 합과 문맥 포함 payload 합을 구분한다.

## 입력과 순서

SenseVoice INT8 1T·한국어·ITN false·`ko_cer_v1`·identity를 유지한다. 각 실행은 새 프로세스/모델 1회 로딩/같은 첫 발화 ASR 워밍업 3회이며 VAD 조건은 VAD만 추가 3회 워밍업한다. 조건/자료별 1회다.

1. KSS 개발 50개(164.919초/756자) 전체에서 full → VAD0 → VAD200 순서로 평가한다. 최악 사례만 고르거나 개선 발화만 남기지 않는다.
2. 기존 M2-3 합성 장문 32.0675/60.6133/120.5869초 3개(정답 총 910자)를 별도 manifest로 묶고 같은 순서로 평가한다. 원본 WAV/정답은 복제·변경하지 않는다. 강제 5초 방출이 실제로 발생하는지와 중복 문맥의 오류를 검사한다. 실제 방출이 없으면 미확인으로 보고한다.

두 자료는 CER/RTF를 합치지 않는다. 합성 장문은 KSS를 연결한 스트레스 입력이며 자연 긴 대화나 독립 평가가 아니다. 첫 발화가 서로 달라 워밍업 입력/시간도 자료별로 구분한다. 자연 장문의 확보와 사람이 검수한 음향 경계는 별도다.

## 검증·계측·판정

Host에서 실제 과거 원시의 재채점 불변, mock의 13초 강제 분할/겹침·문맥 바이트·초기 지연 시작·빈 검출/실패·전사 반복을 검사한다. RP5에서 기존 main push→동기화→새 ID→`operational` 열 감시 아래 6개 실행, 총 159개 발화 평가를 수행한다. 현재 저전압/새 저전압 이력·필수 계측 누락·프로세스 실패·외부 제한 미확인은 성공으로 간주하지 않는다. 기본 펌웨어 열 보호/팬·클럭·전압 설정을 유지한다.

CER S/D/I·자료별 성공률·전체 및 5초 초과/사전 회귀 사례·모든 발화의 개선/악화·실제 hard_limit 수를 보고한다. 모델 로딩/워밍업/ASR/VAD 신경망/파일 파이프라인 비용과 공존 RSS를 분리한다. 단회 운영 조건의 시간 차이를 고정 클럭 성능 순위로 부르지 않는다. 실제 Streaming·endpoint·Refine 확정 지연·드롭·백로그는 null이다.

어떤 후보가 개발 CER를 개선해도 자동 배포하지 않는다. 장문·추가 삽입 오류·회귀를 같이 판단하고 기존 평가 결과는 보존한다.

## 명령

```bash
.venv/bin/python scripts/edge_asr.py tools thermal-run \
  --temperature-policy operational --output <새_실행> -- \
  .venv/bin/python scripts/edge_asr.py tools probe-segmented-accuracy \
  --manifest data/evaluation/kss-dev50/manifest.jsonl \
  --condition bounded_vad_5s_context200ms --output <새_실행>
```

모델 없는 재채점은 기존 `tools summarize-segmented-accuracy`를 사용한다. 과거 문맥 0 요약 형식은 유지하며 200ms 후보에서만 문맥 프레임/총 payload 프레임 항목을 추가한다.
