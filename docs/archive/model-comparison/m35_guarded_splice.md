# M3-5 연속 Zip 구조 후보의 제한 교체 재생

2026-11-03 사전 계획. [M3-4 진단](../../../results/summaries/m34-continuous-token-20261103.md)의 기존3개 완전한 실제 로그와 구조 후보34개를 사용한다. **모델/음원 없이 저장 이벤트만 재생**해 literal 교체의 CER·개별 악화·복사 보존·반복/문장부호 경계를 확인한다. 새 ASR 추론·1배속 입력·실시간 배포·UI 실행은 하지 않는다.

## 고정 정책

| 정책 | 동작 |
| --- | --- |
| `zip_only` | 같은 원시 스냅샷의 연속 Zip 문자열을 그대로 유지 |
| `guarded_replace_v1` | 원래 `structural_candidate`가 실제로 준비된 시점에 검증된 문자 범위만 Refine 원문으로 교체 |

M3-4의 보류66개를 추가로 허용하거나 음향 정렬로 승인하지 않는다. EOF 최종 결과를 보고 과거의 교체를 고르지 않는다. native audit의 실제 직렬 순서와 `assessed_ns`를 사용하고, candidate는 원래 이벤트에 나타났을 때만 검토한다. 정답은 선택/출력 확정 뒤 채점에만 접근한다.

세션(worker 해시)/원본/작업 ID·소유 좌표/payload 해시·실제 수신 성공을 대조한다. 원래 구조 규칙을 같은 스냅샷에서 다시 계산하고 토큰/시각·문자 범위·원래 Zip 조각이 같아야 한다. 비어 있는 문자 범위나 Refine은 보류한다. 새 confidence/길이/문구 임계값은 도입하지 않는다.

교체는 **변하지 않은 원본 토큰 ID와 문자 범위**에 고정한다. 결과를 갱신할 때마다 원본 Zip에서 조립하며, 이미 교체한 문자열에서 다시 위치를 찾지 않는다. 후보 밖 prefix/suffix·VAD 미대응 문자와 이후 새로 생긴 Zip 문자를 그대로 복사한다. 삽입문 길이가 달라도 다른 구간의 좌표를 이동시키지 않는다.

토큰/문자 범위가 겹치면 먼저 유효하게 등록한 교체를 유지하고 나중 것을 거부한다. 중복은 재삽입하지 않는다. 접두부 수정/스냅샷 오류는 해당 원본의 교체를 폐기하고 현재 Zip으로 복원한다. 후보 철회·앵커 불일치·범위 변경·누락/실패/드롭/빈 Refine은 이유를 기록하고 Zip을 유지한다. 새로운 생산 서비스 timeout이나 무한 세션 관리 구조는 만들지 않는다.

Refine 문자열을 **literal**로 삽입한다. 공백/문장부호 추가·삭제, 반복 제거, 문자열 검색으로 범위를 고치는 처리, 모델별 유리한 후처리는 없다. 이 때문에 중복/어색한 경계가 생겨도 그대로 채점하고 원문에 남긴다. 이 정책은 연구용 재생에만 쓰며 기본 실행 모드로 채택하지 않는다.

## 보존과 평가

조립 결과에 원본 Zip 복사 부분과 Refine 부분의 provenance를 기록한다. 비선택 원본 부분의 실제 출력 조각을 원본과 매번 비교하고, 문자 소유 합/해시를 확인한다. **복사 보존 성공이 인식 삭제 오류0을 뜻하지는 않는다.** 선택 범위 내부의 의미 손실·중복은 원본 단위 CER의 S/D/I와 개별 사례로 따로 평가한다.

기존 `ko_cer_v1`과 같은 정답을 사용한다. KSS50/합성120초1개/디지털무음6개를 각각 집계하고, 개선/동률/악화·S/D/I·오류 delta를 공개한다. 후보 밖 문자열은 보존하며 빈 정답 CER는 null이다. 개별 가설·교체 원문·타임라인/판정·보존 증거는 Git 제외 경로에 그대로 저장한다.

추가 경계 진단은 조립된 출력의 Refine 앞/뒤 정규화 접미사-접두사 공통 길이와 인접 문장부호 쌍을 기록한다. 2자 이상은 고정된 표시용 집계이며 **교체 선택/필터에 사용하지 않는다**. 우연히 같은 글자가 반복될 수 있으므로 실제 중복 단어/오류로 확정하지 않는다. 문장부호를 제외하는 CER가 숨길 수 있는 경계도 함께 보고한다. 표시 안정성은 원문 변경과 정규화 접미부 수정량으로 기록한다.

재생 시각은 기존 audit 처리 완료를 가용 시점으로 삼은 trace 값이다. 새로운 실시간 입력/ASR/실제 병합 dispatch/UI 지연이 아니며 실제 지연은 null이다. Host/RP5 replay wall·플랫폼은 별도 `execution.json`으로 기록하고 NN RTF/CPU/RSS로 사용하지 않는다.

## 실행과 완료 조건

기존3개 기록×2정책=각 기기6정책 재생,57개 원본×2=114개 채점이다. 독립114개 발화가 아니다. Host 모의 계약/전체 회귀/원시 체크섬·재집계 → 같은 입력 Host 재생 → main push/RP5 pull → RP5 회귀/같은 모델 없는 재생 → 결과/원시·환경 보존 대조 순서다. 기존 모델·가상환경·패키지·원음/manifest·M1/M2/M3 원시는 변경하지 않는다.

새 ID는 `m35-guarded-splice-20261103-01`; 재생은 `results/merge-replays/`, 계획/감사는 `results/maintenance/` 아래 같은 ID다. 원시 내부/기존 출력 경로 쓰기를 거부한다. 미완료/손상된 M3-4 원시를 성공 평가로 취급하지 않는다. 실제 파일 checksum·진단 재집계·교체 불변조건과 Host/RP5 의미 산출물 일치를 완료 조건으로 한다. 악화가 있어도 결과를 숨기거나 규칙을 사후 조정하지 않는다.

```bash
.venv/bin/python scripts/edge_asr.py tools replay-splice \
  --run results/preflight/m34-continuous-token-20261103-01/kss-dev50/vad0 \
  --policy all --output <새_재생_폴더>
```

재생 결과가 유효하더라도 음향 정렬/실제 UI 성공으로 표시하지 않는다. 정확도·개별 악화·경계/보존 조건을 확인한 뒤에만 별도1배속 실제 병합을 설계한다. 문장부호 처리/경계 확대를 추가 비교할 때는 새 사전 정책/실행 ID를 사용한다.

## 실행 결과

위 고정 정책으로 [Host/RP5 재생](../../../results/summaries/m35-guarded-splice-20261103.md)을 완료했다. 각279개 단위 테스트·6정책 재생을 통과했고 의미 산출물39개가 일치했다. KSS CER11.64→8.33%, 합성11.18→10.60%였으나 KSS5개가 악화돼 자동 교체는 보류한다. 비선택 원문 보존이 선택 범위 내부의 인식 안전성을 뜻하지 않음을 확인했다. 새 ASR/실시간 입력/실제 교체/UI는 실행하지 않았다. v1 규칙은 바꾸지 않으며 다음 입력/문자 범위 검증은 별도 계획으로 진행한다.
