# M3-2 파일 ID 단위 선택 정책과 저장 실측 로그 재생

2026-11-03 사전 계획. [온라인 VAD 실측](../../results/summaries/m31-online-vad-20261103.md)에서 Refine의 전체 CER는 개선됐지만 KSS8/50개는 Zip보다 나빴다. 이번에는 **저장한 실제 출력만 재생**해 선택·오류/지연 도착 처리·수정/악화율을 검증한다. 새 ASR 추론/마이크/UI·실시간 입력 공급·모델 다운로드는 하지 않는다.

## 범위와 제한

기존 Zip partial은 원본 파일 전체의 누적 문자열이며 단어/문자별 오디오 시간이 없다. VAD 좌표만으로 그 문자열의 해당 부분을 자르거나 일부를 대체할 수 없다. 문자 수를 오디오 시간 비율로 나누거나 정답으로 정렬하지 않는다.

이번의 `source_id`는 **원본 파일 단위**다. Streaming partial을 그대로 표시하다가 파일 종료와 제출 작업 집합이 확정되고 모든 Refine이 도착한 뒤 전체 파일의 결과를 선택한다. 120초 파일에서는 중간 Refine도 파일 끝까지 선택되지 않는다. 이 한계를 첫 Refine 준비→선택 대기로 별도 기록하며 VAD 구간별 실시간 병합이 완료됐다고 표시하지 않는다.

## 고정 정책

| 정책 | 파일 최종 선택 |
| --- | --- |
| `zip_only` | Streaming 최종 유지 |
| `refine_complete` | 제출된 Refine이 모두 성공했고 연결 전사가 비어 있지 않으면 Refine |
| `agreement_only` | 위 조건과 함께 Zip/Refine이 `ko_cer_v1` 정규화 후 같을 때만 Refine |

선택은 정답·CER·발화별 유리한 모델 목록을 사용하지 않는다. `agreement_only`는 정규화 CER를 바꾸지 않는 보수 대조군이며 정확도 개선 방법으로 포장하지 않는다. Refine은 소유 프레임 순서대로 단일 공백 연결하며 중복 제거·금칙어·임의 점수/문자 길이 임계값은 없다. 부분 문자열 교체나 신뢰도 추정은 이번 범위가 아니다.

작업 누락/실패/드롭·빈 Refine·VAD 미방출은 이유를 기록하고 Zip을 유지한다. 이는 **새 병합 정책의 명시적인 fallback**이다. 과거 ASR 평가의 VAD 미검출=빈 가설/전체 정답 채점 규칙과 원시는 바꾸지 않는다. 파일 종료 뒤 결과 배출이 끝났다는 caller의 명시적 `finish`를 사용하며 새 production timeout/SLA를 임의로 정하지 않는다.

## 상태와 지연 도착

병합기는 한 writer가 이벤트를 직렬 적용한다. 세션+파일 ID+작업 ID와 소유/문맥/실제 payload 해시를 확인하고 다른 파일의 결과를 덮지 않는다. Refine 도착 순서가 뒤바뀌어도 소유 좌표로 연결한다. 작업 등록이 끝나기 전에는 현재까지 도착한 결과만 보고 일찍 확정하지 않는다.

파일의 선택이 확정된 뒤 늦은/중복/이전 세션 결과는 무시 사유를 남긴다. 역행 partial·알 수 없는 원본·잘못된 작업 소유·중복 소유 범위·payload 불일치를 거부한다. 원본별 revision/phase/model/reason을 가진 변경 이벤트를 내보내며 표시 문자열 변화와 선택 메타데이터 변화는 구분한다. 무제한 live 세션의 메모리 관리나 실서비스 비동기 전송까지 구현하지 않는다.

## 입력과 평가

모델/가중치/환경은 유지하고 기존 본6회(`m31-online-vad-20261103-01`)와 별도 디지털무음3회(`m31-online-silence-20261103-01`)를 모두 사용한다. 9개 기록×3정책=27개 재생, 171개 원본 평가×3=513개 선택 평가다. 반복된57개 원본이며 독립513개 발화가 아니다. KSS50/120초 합성1/디지털무음6을 별도로 집계한다. 개발·스트레스 자료이며 최종 독립 평가로 부르지 않는다.

원시 체크섬·기존 `summarize-concurrent` 재집계가 맞고 입력/Refine이 완전한 기록만 받는다. 정책에 전달하는 이벤트에서 정답/채점 필드를 제거하고 결정이 모두 끝난 뒤 `ko_cer_v1`로 채점한다. 정답을 바꿔도 선택/표시 타임라인이 같아야 한다. 원문은 수정하지 않고 원본별 개선/악화/동률과 빈 정답의 비어 있지 않은 출력 수를 함께 남긴다.

Zip partial/최종의 실제 반환 시각과 Refine child의 `ended_ns`를 **가용성 대리 시각**으로 정렬한다. 기존 기록은 parent가 매 결과를 받거나 UI에 그린 시점을 저장하지 않았다. 따라서 첫 표시·파일 끝/Zip 최종 뒤 선택 대기는 trace에서 유도한 값이며 새 실시간 실측/화면 지연으로 표시하지 않는다. 처리기 자체 실행 wall은 별도 메타데이터에 두고 NN/1배속 입력을 실행하지 않았음을 기록한다.

안정성은 원문 변화 횟수, 정규화 공통 접두사 뒤 지운 접미부, 최종 정규화 변경 횟수로 정의한다. 접미부 문자수는 Levenshtein 오류수나 렌더링 비용이 아니다. CER·워밍업·CPU/RSS·음향 지연을 과거 값에서 소급 변경하지 않는다. 실제 병합 dispatch/UI/마이크/단어 정렬 지연·VAD 부분 교체 CER는 null이다.

Host 전체 테스트/9기록 재생 → main push → RP5 소스 동기화/단위 테스트/동일27정책 재생 → 의미 결과 비교·기존 모델/환경/원시 보존 감사 → 보고서 순서로 실행한다. 새 경로는 `results/merge-replays/m32-merge-replay-20261103-01`, 감사는 `results/maintenance/m32-merge-replay-20261103-01`이다. 원시 내부/기존 출력 경로 쓰기를 거부한다.

```bash
.venv/bin/python scripts/edge_asr.py tools replay-merge \
  --run results/preflight/m31-online-vad-20261103-01/kss-dev50/vad0 \
  --policy all --output <새_재생_폴더>
```

파일 단위의 안전한 선택과 회귀를 확인한 뒤, 실제 VAD 구간별 Zip 전사 경계/시간 정렬을 확보하는 다음 실측을 설계한다. 기존 로그에 없는 문자/단어 시간을 만들어 넣지 않는다.
