# Q8 토큰 후보 검증 후속 평가 — 2026-11-19

선별한 8개 확정 PCM에서 관측한 native 호출 비용 7.25~8.77% 감소는 전체 평가로 확대할 근거로 삼습니다. 마침표 추가 한 건만으로 탐색을 종료하지 않고, 원시 출력 차이와 `ko_cer_v1` 오류를 구분합니다. 이전 결과와 판정은 [원래 보고서](../../results/summaries/optimization/token-draft-20261119.md)에 보존합니다.

먼저 `token-draft-full-20261119-01`에서 기존 긴 자연발화·낭독의 확정 PCM 233개를 그대로 사용합니다. 동일한 `token-draft-20261119-01` bridge·Q8·생성2/음성3스레드·고정 text prefix 캐시에 후보 검증 끔/4개 묶음만 바꿉니다. 자연발화는 끔→켬, 낭독은 켬→끔 순서이며 각 실행 전 같은 PCM으로 3회 워밍업합니다. 후보는 이전 1배속 실측에서 해당 확정 호출 전에 종료한 같은 구간의 마지막 부분 호출 토큰만 사용합니다. 새 모델이나 미래 정답 토큰을 후보로 제공하지 않습니다.

전체 원음 순서의 정답 3,192자에 대해 확정 결과를 연결해 CER를 계산하고, 문장부호·공백만 다른 구간과 정규화 후에도 다른 구간, 빈 전사·반복·UTF-8 실패를 따로 기록합니다. 동일 PCM·모델/빌드 해시와 후보의 시간적 선행을 검사합니다. 호출 비용·단계별 시간·발열은 진단용이며 이 결과를 1배속 자막 지연으로 해석하지 않습니다.

정확도와 완료율이 유지되면 같은 구간의 이전 부분 토큰을 확정 호출에 전달하는 선택 기능을 연결하고, 기존 `listener_q8_headroom.toml`·긴 음원12개·WAV1배속·gap0으로 끔/켬을 다시 비교합니다. 이때 첫 표시, 최신 입력 반영 공백, 구간 끝→확정, 총 추론 비용, 드롭·오래된 결과 표시·수정 부담·열 제한을 함께 판단합니다. 공유 기본 설정은 이 검증까지 유지합니다.

Host에서 `final_token_draft_block` 선택 설정과 `qwen/token_drafts.py`의 요청별 전달을 구현했습니다. [후보 설정](../../configs/gguf_final_draft.toml)은4개 묶음, 1배속 대조는 같은 파일의 묶음 크기만1로 바꾸어 전달/기록 비용까지 맞춥니다. 부분/일반 batch에는 후보를 적용하지 않습니다. 같은 구간의 성공·협력적 취소 토큰만 최대 `max_new_tokens`개 보관하며, 새로운 모델·음성 cache·대기열은 추가하지 않습니다. 고정 llama.cpp·ORT 헤더를 지정한 Host485개 전부·Ruff186파일·M1 원본 해시 검사를 통과했습니다. 이 검사는 RP5 정확도·지연 실측과 별개입니다.

## 1배속 측정 전 판단 수정

전체 PCM 측정 도중 자연발화는 오류257→255, 낭독 후보는 기존127보다 많은131자 오류를 기록했습니다. 문장부호뿐 아니라 단어도 바뀌었으므로 원시 동등성은 성립하지 않습니다. 마지막 낭독 직렬 대조를 완료해 정확도 유지 조건의 통과 여부를 그대로 기록합니다.

사용자가 비용 절감의 실용적 의미를 확인하며 계속 진행하도록 요청한 취지에 따라, 정확도 유지 조건을 통과하지 못하더라도 모델 실패가 없는 소폭 CER 차이는 **채택 조건 미통과 상태를 보존한 탐색적 1배속 대조**로 이어갑니다. 이 단계는 기본 채택이나 무손실 가속 인증이 아닙니다. 고정 후보 진단과 달리 실제 실행에서 나온 자기 부분 토큰을 사용하므로, 실제 자막 지연·계산량·CER의 절충을 직접 측정할 필요가 있습니다. 사후에 정확도 조건을 통과한 것으로 바꾸지 않으며 실행 전에 별도 판단 영수증에 고정 PCM 요약 해시와 사유를 남깁니다. 공유 기본은 유지합니다.
