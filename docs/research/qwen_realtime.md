`realtime-controls-20261110-01`에서 첫 파일럿과 같은 manifest·38.7835625초 입력·Q8·2T·VAD·5초·워밍업·온도 운영 정책을 사용합니다. 순서는 새 부분 on → `--no-partials` off 대조이며 완전 무음도 그대로 처리합니다. 두 실행의 최종 PCM 해시·경계·전사와 지연을 비교합니다. 다음에 `--silence-policy skip-zero`만 바꾼 부분 on 실행으로 EOF 무음 오인식을 확인합니다. 완전0 PCM 생략은 `skipped_silence`로 남기며 입력 손실이나 성공한 ASR 호출로 세지 않습니다. 기존 기본값은 `preserve`입니다.

진단에서 두 VAD의 경계·PCM은 같았고 최장 원음 앞6초의 peak는 약0.012였습니다. 후속 `q8-on-zero-gain12`는 `--vad-gain-db 12`만 추가해 비교합니다. 증폭·클리핑은 VAD 입력에만 적용하며 ASR로 전달하는 PCM은 identity 원음입니다. 기존 기본값0dB는 보존합니다. 같은 소규모 목록의 오류가 늘지 않을 때 양자화 파일럿의 공통 경로로 사용하며 전체100개 정확도 채택을 뜻하지 않습니다.

12dB 후보는 실제 오류52→67개로 악화돼 채택하지 않았습니다. 다음 `q8-on-zero-threshold03`은 증폭0dB·부분 on·완전0 생략을 유지하고 `--vad-threshold 0.3`만 바꿉니다. 기본0.5는 보존합니다. 같은3개에 추가 실패 없이 오류가 줄 때 양자화 공통 조건으로 사용하고, 악화되면 기존0.5로 비교합니다.

`realtime-quant-20261110-01`은 같은3개·2T·부분 on·완전0 PCM 생략에서 Q8→Q6_K→Q5_K_M→Q4_K_M 순으로 실행합니다. 같은 VAD 조건·최종 구간 PCM 해시를 확인하고 결과·실패·첫 자막·파일 시각 앵커·확정 지연·CPU/RSS/열을 비교합니다. file type/tensor 혼합 dtype·모델 SHA는 자산 명세에 고정합니다. 새 BF16 원본 SHA는 `12b2894d9a7c98cd8f26670f5a47ab738f42bcc98df21e109be493870c71ba50`이며 각각 독립 변환합니다. 추가 오류·실패·빈 출력이 있는 후보는 채택하지 않습니다.3개는 선별 파일럿이며100개·독립 데이터·장시간 검증은 최종 선정 전 별도 단계입니다.

연속 입력 경로를 확인한 뒤 같은100개 순서·분할·업데이트 간격·2T에서 **텍스트 모델 Q8_0→Q6_K→Q5_K_M→Q4_K_M**을 비교합니다. 오디오 mmproj는 우선 같은 Q8_0 파일을 유지합니다. 낮은 비트가 RP5에서 더 빠르거나 한국어 정확도를 유지하는지는 실측으로 판단합니다. 스레드·빌드·KV 설정은 동시에 바꾸지 않습니다.

고정한 ggml-org 배포 revision에는 text/mmproj의 Q8_0·BF16 파일이 있습니다. 낮은 비트는 같은 BF16 원본에서 각각 독립 생성하고 변환 도구·명령·tensor dtype·SHA를 기록합니다. Q8을Q6으로, 그 결과를 다시Q4로 누적 재양자화하지 않습니다.
