# 음성·자막 청취 도구

`listen-qwen3`는 같은 연속 입력 이벤트 계약으로 **라이브 청취와 기록 재생**을 제공합니다. 원음·정답·실제 부분/확정 자막, 원음별 지연, 전체 연결 CER를 함께 확인합니다. 모델·스레드·캐시·갱신 간격은 실행 기록에서 읽으며 화면에 고정하지 않습니다.

## 개발 PC·노트북에서 열기

현재 환경의 개발 PC 터미널에서 실행합니다. 먼저 Host 변경을 main에 push하고, RP5에 같은 소스를 동기화합니다. 다른 추론이 실행 중일 때는 새 평가를 시작하지 않습니다.

```bash
.venv/bin/python scripts/edge_asr.py tools listen-qwen3 \
  --ssh rp5 --port 8765 \
  --profile configs/listener.toml \
  --run results/optimization/opt3/realtime-prefix-cache-20261112-01/full100/on \
  --run results/optimization/opt3/realtime100-onnx-20261110-02
```

이 명령은 RP5의 localhost 청취 서버를 기존 SSH로 개발 PC의 `127.0.0.1:8765`에 전달합니다. RP5에는 추가 Python 패키지를 설치하지 않습니다. 개발 PC 브라우저에서는 `http://127.0.0.1:8765`를 엽니다. 노트북에서는 개발 PC에 연결한 VS Code의 **Ports → Forward a Port → 8765**를 사용하고 안내된 로컬 주소를 엽니다. 이미 해당 포트를 쓰고 있으면 다른 `--port`를 지정합니다.

두 브라우저가 같은 실행을 볼 수 있고, 각 장비에서 음량을 조절합니다. 라이브 탭에서 준비한 실행은 다른 화면의 기록 목록에도 나타납니다. 준비·실행 중인 기록을 라이브로 보려면 라이브 모드에서 실행 ID를 선택하는 흐름을 사용합니다. 서버 종료나 브라우저 닫기로 이미 시작한 RP5 평가를 자동 중단하지 않습니다. **이 평가 중단** 버튼은 해당 서버가 실행한 평가만 중단하고 원시를 보존합니다. 종료 제한은 기존 thermal-run의 1800초·4GiB·운영 온도 기록을 사용합니다.

Host에 회수한 기록만 볼 때는 `--ssh`를 생략합니다. 이 경우 Host에서 실제 추론 준비 버튼을 누르지 않습니다.

```bash
.venv/bin/python scripts/edge_asr.py tools listen-qwen3 \
  --run results/optimization/opt3/realtime-prefix-cache-20261112-01/full100/on \
  --manifest data/evaluation/edge100-20261109-01/manifest.jsonl
```

원음 경로는 등록한 manifest에서 ID·SHA로 찾습니다. 다른 자료의 기록은 그 자료의 `--manifest`를 추가합니다. 당시 원음 순서·무음·프레임 좌표·전체 float PCM 해시가 맞아야 재생됩니다. 청취용 PCM16 WAV와 준비 manifest는 `results/listener/`에 별도 보존합니다.

## 화면 사용

화면은 실행 조건·재생 조작·정답/인식 결과·지연/CER·원음별 표 순으로 구성합니다. 연결 상태는 상단에 표시하며 측정 기준과 브라우저 관측 기록은 펼쳐서 확인합니다.

- **기록 재생:** 실행 선택 → 기록 불러오기 → 재생. 원래 자막 발행 시각으로 표시합니다. 일시정지·처음부터·시간 탐색·원음 행 클릭을 지원합니다.
- **라이브:** 구성·전체/앞6개/개별 음원 선택 → RP5 실행 준비 → 워밍업·음원 로딩 완료 → 시작. 준비 후 180초 이내에 시작해야 합니다. 시작 예약은 3초 뒤이며 입력은 독립 프로세스에서 100ms·1배속으로 계속 진행합니다.
- **음원·구성 변경:** 보고 있는 준비/실행을 중단하고 종료를 확인한 뒤 음원·자막·시간축을 초기화합니다. 이후 **RP5 실행 준비**를 다시 누릅니다. 이전 결과는 별도 실행 ID로 보존하며, 같은 실행을 듣는 다른 화면에도 중단이 반영됩니다. 준비 요청·종료 처리 중에는 중복 조작을 막습니다. 새로고침 후 라이브 탭을 열면 이 서버의 진행 중인 평가를 다시 불러옵니다.
- **재생 종료:** 음원이 끝나도 남은 추론을 계속 받아 `음원 종료 · 추론 결과 대기`로 표시합니다. 마지막 정답을 유지하고 확정 전사를 펼쳐 보여줍니다. 추론이 끝나면 정답·전체 확정 전사·CER·지연을 화면에 유지합니다. 새 음원·구성·기록을 선택하거나 다시 준비할 때 초기화하며, 같은 모드 탭을 다시 눌러도 결과를 지우지 않습니다. 기록 재생도 늦은 최종 자막의 발행 시각까지 진행합니다.
- 정답 카드에는 **듣고 있는 원음**, 인식 카드에는 **자막이 처리한 원음 번호·구간·발행 시각**이 표시됩니다. 늦은 결과는 해당 자막의 정답도 별도 표시합니다. 원문은 표시·채점에만 사용합니다.
- 라이브 입력은 오디오 일시정지에 따라 멈추지 않습니다. 소리만 끄려면 음량을 조절하고, 탐색은 종료 후 기록 모드에서 합니다.
- 원음별 표를 첫 표시/4자 지연 순으로 정렬해 늦은 사례를 듣습니다. 아래 통계 카드는 재생 위치의 순간값이 아닌 **전체 실행의 종료 통계**입니다.
- 브라우저 관측 JSON은 접속한 장비에서 다운로드합니다. 시계 추정·수신 시각을 포함하며, 물리 화면·스피커 출력 실측은 아닙니다.

## RP5 USB 마이크

마이크는 **RP5에 직접 연결**합니다. 노트북/개발 PC의 브라우저는 RP5 결과를 봅니다. 브라우저 마이크 권한이나 음성 업로드를 사용하지 않습니다. RP5의 기존 `arecord`와 ALSA `plughw`로16kHz·모노·PCM16을 받으며 장치의 기본48kHz 등 변환은 ALSA가 처리합니다. Python 패키지·시스템 오디오 기본 설정은 바꾸지 않습니다.

2026-11-13 현재 연결된 `USB Audio Device`에서 수집→Qwen 추론→웹 자막→정상 종료→녹음 재생을 확인했습니다. [실제 검사 범위와 한계](../../results/summaries/optimization/microphone-web-20261113.md).

1. **마이크** 탭 → 입력 장치와 실행 구성을 선택합니다. 목록이 비면 **장치 새로 확인**을 누릅니다.
2. 최대 녹음 시간(기본120초·최대600초)을 선택합니다. CER를 확인하려면 읽을 정답을 미리 입력합니다. 비워두면 자유 발화이며 CER는 **미측정**입니다. WAV 목록은 모델 워밍업에만 사용합니다.
3. **RP5 실행 준비** → 워밍업 완료 → **마이크 시작**을 누릅니다.3초 예약 뒤 RP5 마이크에 말합니다. 원음 실시간 스피커 모니터링은 하지 않습니다.
4. 자막·확정 전사·입력 시간·레벨·클리핑·드롭·하드웨어 넘침·온도/제한을 확인합니다.
5. **마이크 입력 종료 · 결과 기다리기**를 누르거나 제한까지 기다립니다. 녹음을 끝내고 남은 추론을 배출하며 화면을 유지합니다. **이 평가 중단**은 강제 중단으로 미완료 기록을 남깁니다.
6. 종료 후 **녹음 재생**을 누르면 기록 재생으로 전환해 녹음과 자막을 다시 확인합니다. 재추론하지 않습니다. 새로고침 후 마이크 탭에서 이 서버의 진행 중인 입력에 다시 참여할 수 있습니다.

마이크의 첫/4자/최종 지연은 **완료된 VAD/ASR 구간**의 프레임 시작/끝 기준입니다. 녹음 시작부터 첫 말을 하기까지의 무음을 발화 지연으로 세지 않습니다. 아직 끝나지 않은 구간은 통계에 추가하지 않으며 자막은 생성 중에도 표시합니다. 하드웨어 ADC 시각·음향 단어 끝·물리 화면 지연은 미측정입니다. 전체 정답은 구간에 나누지 않고 정상 입력 종료 후 전체 확정 전사와 `ko_cer_v1`로 비교합니다. 의도한 문장 외 다른 말도 CER에 포함됩니다.

원음과 결과는 새 `results/optimization/opt3/microphone-날짜-시각-ID/`의 `recording.wav`, `worker.json`, `jobs.jsonl`, `capture.log`, `stream/`, 기존 열 계측에 저장합니다. 입력 큐10개(각100ms)가 넘치거나 장치가 끊기면 손실을 숨겨 이어 붙이지 않고 실패로 남깁니다. 하드웨어 넘침이 관측된 입력도 완료 평가로 처리하지 않습니다. WAV와 마이크는 장비 추론 잠금을 공유합니다.

## 지표·실패·동기화

첫 표시와 4자 표시는 **원음 파일 시작 → RP5 텍스트 이벤트 발행**입니다. 기존 보고서와 같이 성공 호출 중 한 원음에만 귀속된 이벤트를 집계합니다. 미출력은 0초로 채우지 않고 관측 수/전체 수로 표시합니다. 4자는 숫자·문자 기준이며 정답 정확도나 음향 단어 끝 지연을 뜻하지 않습니다. 실시간 카드의 첫 표시는 현재까지의 관측이므로 이후 호출 실패로 종료 통계에서 제외될 수 있습니다.

최종 반환은 **원음 파일 끝 → 마지막으로 겹치는 최종 결과**입니다. 파일 앞·뒤 무음이 포함될 수 있고 음향 발화 끝과 다릅니다. CER는 전체 입력 처리가 끝난 실행의 `final_transcript_score`를 사용합니다. 미완성 부분 자막을 전체 정답과 비교하지 않으며, 실패는 빈 최종 전사로 포함합니다. 미완료·중단 실행은 전체 CER를 표시하지 않습니다. 경계를 넘는 결과를 임의로 나눠 원음별 CER를 만들지 않습니다.

기록 재생은 브라우저에 음원을 미리 불러오고 Web Audio 출력 시간축에 원래 `published_s`를 배치합니다. 라이브는 준비 완료 후 서버 시계에 시작을 예약하고, 브라우저와 서버의 반복 왕복 요청으로 시계 차이를 추정합니다. 표시한 왕복/2는 편도 실측이 아니며 비대칭 경로·오디오 출력·브라우저 스케줄링 오차가 남습니다. RP5 실제 입력 시작은 `clock.json`으로 별도 기록합니다.

라이브 이벤트는 약300ms 간격의 증분 HTTP 관측으로 전달합니다. 화면에 표시한 발행→수신 추정에는 이 관측 대기와 SSH·브라우저 처리도 포함됩니다. 늦은 자막을 앞당겨 재생하지 않습니다. 네트워크 끊김은 표시하고 마지막 cursor부터 다시 받으며 RP5 입력을 역압으로 늦추지 않습니다. 청취 서버 동시 실행의 보드 부하는 기존 무관측 벤치마크와 다르므로 **라이브 청취 측정**으로 구분합니다.

## 조건 변경·코드 위치

[청취 구성](../../configs/listener.toml)은 모델 TOML·입력 manifest·VAD 자산과 연속 옵션만 지정합니다. ONNX 구성은 `token_stream = false`로 지정합니다. 다른 조건은 이 파일을 별도 이름으로 만들고 `--profile`로 등록합니다. CLI는 기존 replay 인자 검증·실행기를 재사용합니다. 새 실행은 고유 `listen-날짜-시각-ID` 폴더에 기록하며 기존 설정·모델·결과를 덮어쓰지 않습니다.

- [viewer/](../../src/edge_asr/qwen/viewer/): `server.py` HTTP/SSH 진입점, `runs.py` 실행·음원 검증·증분 로그, `analysis.py` 기존 정의의 지연 집계, `web/` 공통 화면.
- [replay.py](../../src/edge_asr/qwen/realtime/replay.py): 선택 시작 예약과 실제 입력 시작 영수증. 옵션을 생략하면 기존 평가 경로입니다.
- [streaming.py](../../src/edge_asr/streaming.py): 입력 생산자 준비 후 선택 gate, 이후 기존 1배속·드롭 계약 유지.
- [테스트](../../tests/qwen/test_listener.py): 경계 귀속·실패·부분 행·음원 해시·HTTP·시작 gate 검사.

가변 요청 실행은 조건 표에 `가변 / 첫 … / 새 음성 … / 끝 여유 …`로 표시합니다. 원음별 **최대 갱신 공백**은 입력 중 같은 구간의 표시 문자·숫자 수가 이전 최대를 넘어선 시각 사이의 최대 간격입니다. 파일 시작·끝의 대기를 포함하고, 수정·접두부 재표시는 새 길이 증가로 세지 않습니다. 원음의 무음도 포함하며 의미 완성·부분 정답 정확도·물리 화면 지연을 뜻하지 않습니다. 입력 끝 뒤 대기는 최종 반환 지표로 확인합니다.

2026-11-13 비용 추정 대조는 **고정4초 · 비용 대조100개**와 **음성비용 가변 · 동일100개**를 선택합니다. 설정은 `results/optimization/opt3/realtime-cost-20261113-01/configs/listener-cost-{fixed,audio}.toml`, 기록은 같은 실행의 `full100/{fixed,audio}`입니다. 같은 해시 순서의100개를 사용하며 [공백 감소·철회/연산 증가](../../results/summaries/optimization/realtime-cost-20261113.md)를 함께 비교합니다. 기본은 고정을 유지합니다.

이전2026-11-12 total 가변 대조는 `고정 대조 · 동일 100개`와 `보완 가변 · 동일 100개`입니다. 기록 재생은 `realtime-adaptive100-20261112-01/fixed`와 `/adaptive`를 선택합니다. `현재 Qwen 개발 구성`은 같은100개 자산의 원본 목록 순서이므로 대조에는 각 실행의 짝 프로필을 사용합니다. 이전 기록·구성도 보존하며 다른 평가 묶음의 수치를 섞지 않습니다.
