# 현재 상태 — Qwen3-ASR 최적화

2026-11-10 기준. 목표는 **RP5에서 Qwen3-ASR-0.6B의 한국어 정확도·완료율을 유지하면서 실제 인식 지연을 줄이는 것**입니다. [연구 계획](research/qwen3_optimization.md), [평가 조건](research/qwen_realtime.md), [최신 실측](../results/summaries/optimization/realtime-accuracy-20261110.md).

## 현재 연속 입력 기준

**Qwen 단독1배속 연속 입력**을 주 평가로 사용합니다. ONNX INT8 2T를 출발 기록으로 보존하고, GGUF Q8_0 2T를 주 후보로 입력 처리의 정확도 손실을 진단했습니다. **다음 개발 기준은 Q8·VAD 보정·ASR5초·VAD 판정5초**입니다. 실사용 통과 구성은 아닙니다.

같은 Zeroth60·FLEURS40·891.1448125초·정답3848자·추가 무음0초입니다. VAD0.3·문맥0·부분 첫1초/이후2초·같은 유한 큐에서 추론 중에도 입력을 계속 받았습니다. 모델·런타임·ASR 처리 파형은 보존하고 **VAD 입력만 인과적RMS로 보정**했습니다. 분할이 바뀌어 요청별 좌표·PCM은 달라집니다.

5초 보정은 오류81개·2.10%p를 줄였고 삭제 오류가216→157개로 감소했습니다. 첫 자막 p95는 줄었지만 중앙값은 약0.64초 늘었습니다.8초 복합 구성은 오류가 더 적지만 첫 자막·확정 대기가 커 정확도 참고로 보존합니다. 파일 끝 기준 반환은 원음 입력 끝→마지막으로 겹치는 최종 호출 반환입니다. 음향 단어 끝이나 각 구성의 VAD 구간 끝과는 다릅니다.

두 후보는 원음100개 모두에 자막이 있고 최종 경계 중첩은6→1개로 줄었습니다. 여전히 발화별 corpus CER는null이며 전체 정답3848자를 연결 CER에 포함합니다. 같은 순서 기존 batch 연결 CER7.64%보다 오류가 남아 있고 열 제한도 관측되어 **저지연 실사용 채택은 보류**합니다. 단일 운영 실행이며 한국어 전반의 개선이나 순수 엔진 효과로 일반화하지 않습니다.

## 구현·검증

- 기존 `qwen/realtime/` 실행기와 ONNX/GGUF 어댑터·공통 입력/채점을 재사용합니다. 각 호출은 누적 PCM의 batch 전사이며 청크 간 KV 재사용·토큰 즉시 배포는 미구현입니다. [구조](reference/architecture.md).
- 기존 RMS 구현을 VAD 전용 경로로 재사용하고 VAD 판정 전환과 ASR 구간 상한을 분리했습니다. 기본값·패키지·모델·native 코드는 보존합니다. Host/RP5 각363개 중361개 통과·선택적 native2개 생략입니다.
- 새 진단·6개 파일럿4회·100개 전체 대조2회의 원시85개 및 모델/runtime/VAD 자산5개 해시가 일치합니다. 양쪽에서 재집계한 최종 JSON도 바이트가 같습니다. [원시 경로·검증 상세](../results/summaries/optimization/realtime-accuracy-20261110.md).
- 첫 ONNX 시도의 예기치 않은 재시작과 이후 화면·입력 멈춤 원인은 미확정으로 보존합니다. 새 ONNX02·GGUF 실행은 같은 부팅을 유지하며 입력을 완료했습니다. 시스템 멈춤과 모델 출력 실패를 구분합니다.
- 현재100개는 낭독 개발/회귀 자료입니다. 마이크·자연 대화·잡음·독립 holdout·최종 장시간 검증은 미완료입니다. [데이터 출처·한계](research/fixed100.md).

## 다음 작업

1. **VAD 보정5초를 기준으로 첫 자막 중앙값·부분 중복 추론·큐 대기**를 줄입니다. 정확도·실패·커버리지와 고정 파일 시각 기준 지연을 함께 관리합니다.
2. 남은 분할/문맥 손실과 batch 대비 오류134개의 원인을 진단합니다. 필요하면 prefill/decode·KV 병목을 추가 계측합니다. engine TTFT·음향 단어 시각은 미측정으로 둡니다.
3. Q5/Q6/Q4는 기존 고유3개 선별 결과입니다. 최종 양자화 선정은 같은 연속 조건의 정확도·실패·누락·지연으로 판단합니다.
4. ONNX의 긴 파일 context 거부와1.496초 출력 상한 실패, 시스템 멈춤 원인은 별도 진단으로 다룹니다. 이후 독립 자료·마이크·장시간 운영을 검증합니다.
