# 현재 상태와 다음 작업

2026-11-24 기준. RP5에서 검증한 모델은 Qwen3-ASR-0.6B GGUF Q8이며, Hailo 청취 구성은 Raspberry Pi AI Kit의 Hailo-8L과 CNN HEF를 사용한다. 개발 PC는 입력 준비와 검산을 담당한다. [장비·런타임 기록](reference/environment.md)

## 최근 실측과 남은 문제

고정 100개·891.145초·정답 3,848자, RP5 WAV 1배속 결과다. 확정 구간 수가 달라 지연은 공통 원음 끝을 기준으로 비교했다.

| 지표 | T | P8 |
| --- | ---: | ---: |
| 확정 문자 오류 (CER) | 460 (11.95%) | 374 (9.72%) |
| 첫 본문 / 최신 본문 갱신 공백 p95 | 4.13 / 4.00초 | 9.42 / 6.06초 |
| 공통 원음 끝 → 확정 p95 | 3.06초 | 5.42초 |
| 실패 / 입력 드롭 / 확정 유실 | 0 / 0 / 0 | 0 / 0 / 0 |
| 최고 CPU 온도 / 제한 경고 관측 시간 | 88.10°C / 835.48초 | 91.40°C / 890.13초 |

T는 이전 5초 CNN 구성에서 관측한 5초 초과 갱신 공백을 16회에서 0회로 줄였다. P8은 서울 자연발화의 주석 단어 881개 중 길이·쉼 경계가 단어 안을 가른 사례를 35개에서 7개로 줄였다. 낮은 음량에서의 VAD 누락, 열 보호 중 첫 요청 보류, 긴 부분 전사의 취소 비용은 남아 있다. 제한 경고 시간과 실제 클럭 하락 시간은 별도 지표다. [T 연속성](../results/summaries/optimization/subtitle-continuity-20261123.md) · [P8 경계·자원·장시간 검증](../results/summaries/optimization/boundary-20261124.md)

고정 텍스트 KV와 CNN 묶음은 채택했다. 음성 창 캐시와 확정 토큰 후보는 재현용 선택 구성으로 유지한다. 추가 NPU 이식, 이미 확정한 음성의 일괄 중첩, 인접 확정의 자동 재전사는 지연·오류·추가 호출 비용 때문에 보류했다. [의사결정 근거](research/optimization_history.md)

## 다음 작업의 잠정 순서

1. **11월 25일 시작** — 최신 Q8 CPU와 Hailo CNN의 배치(Batch) 기준을 재측정한다. 같은 PCM·순서·채점으로 전사, 호출 시간, 온도와 실클럭을 기록한다.
2. LiteRT-LM에서 해당 모델의 음성 입력부터 전사까지 실행 가능한지 확인하고, 가능하면 같은 소규모 입력으로 성능과 정확도를 비교한다.
3. 비교 결과로 추론 엔진과 개선 방향을 결정한다. LiteRT-LM 도입은 미정이다.
4. 부분 자막 스케줄링과 발열을 개선한다. 첫 표시와 최신 본문 갱신 공백, 확정 대기를 함께 본다.
5. 선택적 Overlapping Window, 지연 확정 및 경계 복구를 검토한다. 추가 호출 비용과 이미 표시한 확정의 수정도 측정한다.
6. 선택한 경로의 연산을 최적화하고 RP5 1배속 연속 입력으로 통합 검증한다. 동일 원음·순서에서 CER, 표시·확정 지연, 실패·드롭과 열 제한을 확인한다.

배치 수치는 모델 호출 비용 진단에 사용한다. 사용자 체감 개선 여부는 연속 입력 대조에서 판단한다. [배치 평가 기준](research/fixed100_baseline.md) · [연속 평가 조건](research/qwen_realtime.md)

실행별 조건·실패와 원시 경로는 [실험 색인](../results/summaries/optimization/README.md)에 있다. 이전 상태 문서에만 함께 적혀 있던 구조 이행 검증, 당시 검사 수와 중간 판정은 [정리 전 상태 기록](https://github.com/shinjuyeop/edge-asr/blob/619b0422c2f72c6fe4480b39f7ca32e2f848aba4/docs/status.md)에서 확인할 수 있다.
