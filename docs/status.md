# 현재 상태와 다음 작업

2026-11-03 기준. **WAV 실시간 자막 MVP를 사용할 수 있다. 마이크 입력은 장치 준비를 기다리는 상태다.** 현재 명령은 [사용 안내](guides/live_captions.md), 전체 실험의 수치와 근거는 [실측 기록](../results/summaries/README.md)에서 확인한다.

## 지금 가능한 일

| 기능 | 검증 범위 | 근거 |
| --- | --- | --- |
| Zipformer·SenseVoice batch 비교 | RP5 KSS/FLEURS·1/2/4스레드, CER·RTF·CPU/RSS | [M2 비교](../results/summaries/m2-3-comparison-20261028.md) |
| WAV 1배속 Streaming + VAD + Refine | RP5 실제 동시 추론·유한 큐·입력/보정 손실 계측 | [온라인 VAD](../results/summaries/m31-online-vad-20261103.md) |
| 한 명령 자막 표시 | Zip 원문과 구간별 보정 후보 분리, 실제 4회·드롭 0 | [WAV MVP](../results/summaries/m36-wav-mvp-20261103.md) |
| 저장 결과 검증 | 모델 없는 재채점·이벤트/PCM 해시 대조·병합 정책 재생 | [제한 교체 재생](../results/summaries/m35-guarded-splice-20261103.md) |

WAV MVP의 KSS 첫 stdout p50/p95는 0.853/1.459초, 소유 구간 끝→보정 stdout p95는 0.639초였다. stdout은 파일로 캡처했으며 실제 화면·SSH 도착 지연을 뜻하지 않는다. 기존 모델별 전사는 유지됐다. 수치는 해당 개발 자료의 측정값이다.

## 유지하는 결정

- **자동 교체 보류:** M3-5 재생에서 KSS CER는 11.64→8.33%였지만 5개 발화가 악화됐다. 현재 Zip을 유지하고 Refine을 후보로 표시한다. 문자 범위와 실제 입력 음성 범위의 대응을 먼저 검증해야 한다.
- **원음/vad0 유지:** RMS 정규화와 일괄 문맥 확대는 개선과 악화가 함께 나타났다. 모델마다 유리한 전처리를 사후 선택하지 않는다.
- **운영 열 정책:** 기본 펌웨어 보호 아래 온도/감속을 기록한다. 저전압·계측 누락·외부 제한 실패는 거부한다. [정책](research/m3_thermal_policy.md)의 통제 비교와 운영 검사를 구분한다.
- **평가 자료:** KSS 50과 이미 본 FLEURS 100은 개발 자료다. 사용자 청취 메모 5개는 판단 어려움으로 남기고 추측 전사를 정답으로 쓰지 않는다. 보류 화자 8명/18개는 튜닝에 사용하지 않는다.
- **보존과 배포:** Host 개발→main push→RP5 pull·실측. 모델/환경/원본/과거 결과는 유지하고 새 실행 ID를 사용한다.

## 다음 순서와 완료 기준

1. **마이크 연결:** 장치가 준비되면 지원 샘플레이트·입력 레벨을 확인하고 실제 capture를 연결한다. 음성 입력 중 자막이 나오며 드롭/백로그를 측정하면 완료한다.
2. **실제 사용 검증:** 마이크·자연 장문·독립 평가와 장시간 실행을 확인한다. WAV MVP 최장 단일 입력 120.587초나 과거 8분 batch 부하를 상시 운영 합격으로 대신하지 않는다.
3. **자동 보정 판단:** 음성/문자 범위와 개별 악화를 해결하는 별도 정책을 사전에 고정하고 검증한다. 지금 MVP 사용의 필수 조건은 아니다.

화면 렌더링, SSH 네트워크 도착, 음소 정렬 인식 지연, 실제 마이크, 새 MVP의 8분/상시 운영은 미검증이다. Qwen 추가·재학습·새 양자화는 후속 과제로 둔다. 과거 단계별 계획은 [연구 문서 색인](research/README.md)에 보존한다.
