## 지금 사용하는 기준선

**주 평가는 Qwen 단독1배속 연속 입력**이며 [공통 조건·ONNX 출발 기준](research/qwen_realtime.md)을 따릅니다. 같은100개·같은 순서·파일 사이 추가 무음0초로 확보한 ONNX INT8 2T 결과를 출발 기록으로 사용합니다. 이는 실패·누락을 포함한 기존 양자화 배포본과 공통 파이프라인의 출발값이며 FP16 원본이나 실사용 통과 구성을 뜻하지 않습니다. 이후 GGUF도 같은 연속 조건에서 비교합니다.

아래 [고정100개 batch 프로토콜](research/fixed100_baseline.md)·[기존 실측](../results/summaries/optimization/fixed100-baseline-20261109.md)은 모델 정확도와 호출 비용의 **보조 참조**입니다. 기존 Q8 연속100개는 추가 무음1초 조건이므로 새0초 기준과 구분합니다.

| 구성 | 성공 | 성공 파일 CER | 성공 파일 RTF | 관측 최대 RSS |
| --- | ---: | ---: | ---: | ---: |
| ONNX INT8 2T | 99/100 | 9.61% (361/3,758) | 0.7483 | 2570.4MiB |
| GGUF Q8_0 2T | 100/100 | 7.67% (295/3,848) | 0.6225 | 1772.7MiB |

ONNX의23.04초1개는 보수적 context 검사에서 거부됐습니다. 전체100개 주 CER/RTF는 null이고 실패를 빈 가설로 둔 보조 CER는11.72%입니다. 같은 성공99개에서 GGUF CER는7.53%, 처리 합은 ONNX보다 약16.8% 작았습니다. 이번 구성의 실사용 관측값이며 엔진 외 양자화·프런트엔드·재부팅 상태도 달라 재현성 확인이 필요합니다.

ONNX 최고87.55°C·실제1.5~2.4GHz·열 제한, 재부팅 후 GGUF 최고75.45°C·약2.4GHz·현재 제한0을 기록했습니다. 첫 GGUF 미완료 원시는 보존하고 새 실행에서 전체100개를 처음부터 평가했습니다. 네트워크 단절 중 로컬 기록은 계속됐으나 이전 부팅 로그가 없어 단절 원인은 미확정입니다.

ONNX도 기존 공통 연속 실행기를 사용하도록 연결했습니다. Host/RP5 전체359개 중357개 통과·선택적 native2개 생략이며52.278초·80.626초를 기록했습니다. 기존 Q8의100개는 이 변경 전에 실행한 결과입니다. 기존 모델·환경·batch 기준선·실패 원시는 보존했습니다.

100개·고유 원음891.145초+무음100초를1배속 처리했습니다. 확정p95 6.186초, 단일 원음에 귀속 가능한97개의 첫 자막p50/p95는3.90/7.10초입니다. VAD가2개 원음을 방출하지 않아 자막이 없고, 최종 구간3개는 파일 경계를 넘었습니다. 연결 CER541/3848=14.06%(같은 순서 기존 batch294/3848=7.64%)이며 발화별 corpus CER는 귀속 불가로null입니다. 최고76°C·현재 제한0, 관측 최대 RSS1840.67MiB였습니다.

새 ONNX 추가 무음0초 파일럿은3개·35.784초·17호출을 실패/드롭 없이 완료했습니다. 첫100개 시도는 입력26.7초 뒤 예기치 않게 재시작됐으며, 이후 화면·키보드·마우스도 멈춰 사용자가 추가로 수동 재부팅했습니다. 원시를 회수했지만 이전 부팅 journal이 없어 원인은 미확정입니다. 새 실행02는 같은 부팅 ID를 유지하며14,258,317프레임을 모두 처리했습니다.

실행02의 연결 CER는615/3848=15.98%, 전사361회 중1회는1.496초 최종 구간에서128토큰 상한에 도달해 실패했습니다. 실패는 빈 전사로 채점했습니다. VAD 미방출1개·경계 중첩 최종6개가 있으며 발화별 corpus CER는null입니다. 성공213구간 확정p95 7.74초, 실패 포함214구간 반환p95 7.87초, 관측 최대 RSS2096.09MiB·최고85.9°C·열 제한을 기록했습니다. worker/guard는 호출 실패 때문에 실패 상태이며 실사용 채택을 보류합니다. 원시40개 해시·자산11개·Host/RP5 재집계 JSON은 일치했습니다.

## 다음 작업

1. **같은 추가 무음0초·VAD·분할·큐·부분 요청 조건의 GGUF Q8**을 새 실행 ID로 측정해 ONNX 출발 기록과 대조합니다. 최종 구간 좌표·PCM 해시·실패·미출력도 함께 확인합니다. 기존1초 조건 Q8과 새0초 ONNX로 엔진 순위를 정하지 않습니다.
2. 1.496초 출력 상한 실패·VAD 미방출·경계 중첩과5초 분할/문맥0, 부분 중복 추론·확정 대기를 분리 개선합니다. [기존1초 조건의 누락·분석](../results/summaries/optimization/realtime100-q8-20261110.md)은 보존합니다. Q5/Q6/Q4는 소규모 선별 결과이며 최종 선정은 같은 연속 조건으로 판단합니다. 시스템 멈춤 원인은 별도로 확인합니다.
3. 필요하면 KV·메모리 병목을 추가 계측합니다. 관측한 ONNX Run 바깥1%만으로 전체 KV 비용을 단정하지 않습니다. engine TTFT·음향 단어 지연은 별도 계측합니다.
4. ONNX의 실제 prompt/context 예산과 긴 파일 거부는 별도 변경으로 다룹니다. 기존 실패 원시는 보존하며 GGUF 연속 입력 검증의 선행 조건으로 두지 않습니다. 네트워크 장애는 모델 실패와 구분합니다.
