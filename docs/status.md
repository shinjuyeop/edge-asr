# 현재 상태와 다음 작업

2026-11-25 기준. RP5에서 검증한 모델은 Qwen3-ASR-0.6B GGUF Q8이며, Hailo 청취 구성은 Raspberry Pi AI Kit의 Hailo-8L과 CNN HEF를 사용한다. 개발 PC는 입력 준비와 검산을 담당한다. [장비·런타임 기록](reference/environment.md)

## 어떤 구성으로 비교하는가

| 용도 | 모델과 실행 정책 |
| --- | --- |
| 공유 회귀 기준 | Q8 CPU, 생성 2스레드·음성/Prefill 3스레드, 고정 텍스트 접두부 KV. 5초 구간, 첫 1초/이후 4초 갱신은 [대표 명령](guides/qwen3_optimization.md#현재-개발용-대표-명령)과 함께 적용한다. |
| 빠른 청취 T | Q8 + Hailo CNN, 생성 2·음성/Prefill 4스레드. 4초 구간과 짧은 쉼의 문맥을 사용한다. |
| 경계 정확도 P8 | T와 같은 모델·가속 경로. 3.4초부터 쉼의 중심을 찾고 최대 8초까지 문맥을 유지한다. |
| 비교 후보 | P8 부분 예산은 같은 확정 경계에서 새 음성과 계산 비용으로 후속 요청을 고르는 실험이다. P5G는 5초 경계와 뒤쪽 0.2초 여유의 절충안이다. 빠른 Q4는 디코더 속도 대조에 사용한다. [설정별 채택 상태](../configs/README.md) |

## 최근 실측과 남은 문제

고정 100개·891.145초·정답 3,848자, RP5 WAV 1배속 결과다. 확정 구간 수가 달라 지연은 공통 원음 끝을 기준으로 비교했다.

| 지표 | T | P8 |
| --- | ---: | ---: |
| 확정 문자 오류 (CER) | 460 (11.95%) | 374 (9.72%) |
| 첫 본문 / 최신 본문 갱신 공백 p95 | 4.13 / 4.00초 | 9.42 / 6.06초 |
| 공통 원음 끝 → 확정 p95 | 3.06초 | 5.42초 |
| 실패 / 입력 드롭 / 확정 유실 | 0 / 0 / 0 | 0 / 0 / 0 |
| 최고 CPU 온도 / 제한 경고 관측 시간 | 88.10°C / 835.48초 | 91.40°C / 890.13초 |

T는 이전 5초 CNN 구성에서 관측한 5초 초과 갱신 공백을 16회에서 0회로 줄였다. P8은 서울 자연발화의 주석 단어 881개 중 길이·쉼 경계가 단어 안을 가른 사례를 35개에서 7개로 줄였다. 낮은 음량에서의 VAD 누락, 열 보호 중 첫 요청 보류, 긴 부분 전사의 취소 비용은 남아 있다. 제한 경고 시간과 실제 클럭 하락 시간은 별도 지표다. [T 연속성](../results/summaries/optimization/subtitle-continuity-20261123.md) · [P8 경계·자원·장시간 검증](../results/summaries/optimization/boundary-20261124.md)

고정 텍스트 KV와 CNN 묶음은 채택했다. 음성 창 캐시와 확정 토큰 후보는 재현용 선택 구성으로 유지한다. 추가 NPU 이식, 이미 확정한 음성의 일괄 중첩, 인접 확정의 자동 재전사는 지연·오류·추가 호출 비용 때문에 보류했다. [의사결정 근거](research/optimization_history.md)

## Batch 기준과 LiteRT-LM 검증

고정 100개 중 사전에 고른 20개의 전체 WAV를 같은 Q8으로 전사했다. Hailo CNN을 사용하자 호출 합은 113.21→94.58초로 16.5% 줄고 CER는 8.01→9.26%로 높아졌다. 저장된 T/P8에서 파일별로 대응 가능한 18개는 Hailo Batch 74오류, T 89오류, P8 67오류였다. LiteRT-LM v0.20.0의 일반 ARM64 Python 경로는 공개 ASR 번들과 오디오 출력 규격이 달랐다. 공식 Omni 빌드가 시간 상한에서 끝나 한국어 전사와 C의 속도·정확도는 미측정이다. [동일 원음·PCM 비교와 공식 코드 조사](../results/summaries/optimization/batch-litert-20261125.md)

## P8 부분 전사 스케줄링

첫 PCM 상한과 새 음성·실측 비용 기반 후속 갱신을 적용한 후보는 고정 100개에서 P8 확정 158개의 PCM·토큰과 CER 9.72%를 유지했다. 당일 P8과 비교해 새 본문 없는 부분의 계산 합은 58.55→37.62초, 전체 추론은 743.16→735.67초였다. 첫 본문 p95 9.24초와 갱신 공백 p95 5.88초는 목표에 미달했고 서울 자연발화의 공통 주석 단어 표시 p95도 7.02→7.71초였다. 독립 자유대화 24개와 30분 부하에서도 확정 출력은 같았다. 장시간 전체 추론이 저장 P8 대비 10.7% 늘어 후보는 비교 프로필로 유지한다. [전체 RP5 대조](../results/summaries/optimization/partial-scheduling-20261125.md)

## 다음 작업

1. P8과 같은 확정 PCM·토큰을 기준으로 Q8 CPU Decode, 이어서 음성 Prefill의 직렬 점유를 줄일 수 있는지 확인한다. 1배속에서 첫 본문·실제 단어 표시·최종 확정 개선을 함께 검증한다.
2. 쉼 직후의 짧은 경계 꼬리와 낮은 음량에서 누락된 단어는 별도 정확도 과제로 유지한다.
3. LiteRT-LM은 공식 Linux ARM64 Omni 실행 파일이나 재사용 가능한 빌드로 한국어 단일 창을 재현할 때 재개한다. 그 결과로 추가 1배속 비교나 부분 기술 도입의 가치를 판단한다.

배치 수치는 모델 호출 비용 진단에 사용한다. 사용자 체감 개선 여부는 연속 입력 대조에서 판단한다. [배치 평가 기준](research/fixed100_baseline.md) · [연속 평가 조건](research/qwen_realtime.md)

실행별 조건·실패와 원시 경로는 [실험 색인](../results/summaries/optimization/README.md)에 있다. 이전 상태 문서에만 함께 적혀 있던 구조 이행 검증, 당시 검사 수와 중간 판정은 [정리 전 상태 기록](https://github.com/shinjuyeop/edge-asr/blob/619b0422c2f72c6fe4480b39f7ca32e2f848aba4/docs/status.md)에서 확인할 수 있다.
