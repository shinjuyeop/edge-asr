## 유지하는 연속 입력 기준

**Qwen 단독1배속 연속 입력**이 주 평가입니다. 공유 고정 참조는 **GGUF Q8_0·생성2T/음성·prefill3T·VAD 보정·ASR/VAD 판정5초·첫1초/이후4초·토큰 표시/접두부 재표시 보류·고정 text prefix KV**입니다. [configs/gguf_realtime.toml](../configs/gguf_realtime.toml)과 [대표 명령](guides/qwen3_optimization.md#현재-개발용-대표-명령)을 사용합니다. 기존 캐시 끔2/3 원본 `results/optimization/opt3/realtime-split100-20261111-01/configs/split-2-3.toml`과 기본2T·모두3T 설정·모델·환경·bridge는 보존합니다. 실사용 채택은 보류합니다.

사용자 청취 피드백은 잦은 수정보다 빠른 갱신을 선호했습니다. **후속 저지연 개발 비교는 Q8 음성비용 가변**을 기준으로 합니다. 같은 모델 설정에 `adaptive/budgeted/audio`·3초/최대2회·새 음성0.8초·끝 여유0.2초를 명시하며, 공유 고정 프로필은 회귀 참조로 보존합니다. [가변 실행 옵션](guides/qwen3_optimization.md#가변-부분-요청-선별).

커널 진단 뒤 사용자 결정으로 **주력은 Q8 text/audio·생성2T/음성·prefill3T**에 집중합니다. Q4 모델·계측·실측은 별도 연구 후보로 보존합니다. 같은6개에서 첫 요청0.6/0.8초를 새1초 앞/뒤 대조로 선별했고 두 후보가 통과했습니다. 사전 첫 표시 p50 우선 규칙은0.6초를 선택했으며0.8초는 갱신 공백이 더 짧았습니다. 후속100개에서 첫 표시 개선을 확인했지만 첫4자 p95 한 조건이 미달해 공유1초를 유지합니다. [첫 요청 결과](../results/summaries/optimization/realtime-first-request-20261116.md). 이 방향 정리는 모델·공유 설정·기존 수치를 변경하지 않습니다.

개발·검증 절차는 [CONTRIBUTING](../CONTRIBUTING.md), 직접 확인한 Host/RP5 버전과 환경별 용도는 [환경 기록](reference/environment.md)에 정리했습니다. 구조·안내 정리는 아래 실측의 재실행이나 성능 갱신을 뜻하지 않습니다.

동일 프로세스의 후보 종료→기본 복원도 별도2회 실제 전사로 확인했고, Host440개 중436통과·4개 선택 검사 생략 및 모델 없는 명시 native 검사를 구분했습니다. 측정 웹은 **64기록/23프로필**이며 이번100개 앞/후보/뒤를 기록에서 청취할 수 있습니다.

**후속 개발 비교의 엔진 후보로 유지하고 공유 기본은 그대로 둡니다.** 다음은 저장한 같은 음원의 청취 및 사용자 발화가 가능한 때의 짧은 USB 마이크 검증입니다. 첫 자막·첫4자 대기에는 요청 전 대기와 큐/생성 비용이 남으므로 커널 개선율을 표시 지연 전체의 개선율로 해석하지 않습니다. [조건·실패 기록·검증·수치](../results/summaries/optimization/conv-realtime-20261117.md).

## FP16 합성곱4×4 타일 — 2026-11-17

원래 FP16 누적/축약·threadpool을 재사용하면서 합성곱2/3 타일을4×6→4×4로 바꾼 후보가 선별을 통과했습니다. 유효54회 교차 비교에서 encoder11.8~12.8%·전체3.34~3.49% 감소, 추가36회 원래 무-preload 앞뒤 대조에서 **encoder13.2~13.3%·전체4.0~4.5% 감소**를 확인했습니다. 전사/token 동일·실패0, 합성32조건/64비교 출력 비트·경계도 같습니다.

대상 합성곱 작업자 CPU 합은40.13% 줄었고, 원래 내부 반복에 있던12개의 스택 벡터 쌍 저장이 후보에는 없었습니다. 원래 무계측 대조의 확정 PCM 전체는약3.22~3.25→3.11초, 최초 첫 토큰은약21~28ms 감소입니다. 이 고정 PCM 실험에서는 연속 표시 지연/CER을 측정하지 않았습니다. 최고76°C·현재 제한0·보호1113파일 불변, 실패/제외 포함 원시105파일 및 독립 집계를 확인했습니다.

빌드 선언 누락과 긴 입력의 선택 조건 누락을 각각 별도 ID로 보존하고 보완했습니다. **후속 후보로 채택하되 운영 기본은 유지**합니다. 이 단계의 검증 범위는1/3/5청크였습니다. 입력 길이 보완과6개/100개 연속 확대는 위 후속 검증에서 완료했으며 당시 측정 웹은61기록/23프로필이었습니다. [전체 조건·실패 기록·검증](../results/summaries/optimization/conv-tile-20261117.md).

## Q8 CPU·캐시·작업자 진단 — 2026-11-17

기존 커널 추적기에 선택 PMU/작업자 계측을 추가하고 RP5 고정 PCM3개×12라운드의36호출을 완료했습니다. 전사/token 동일·실패0·PMU997,038커널 valid·coverage100%·보호921파일 불변입니다. 출력층/나머지 Q8 GEMV의 계산량은 두 작업자에 약50:50으로 분배됐고, backend stall/cycle은81.40/80.99%·IPC는약0.52·L2 refill/access는약30/32%였습니다.

단순 작업량 불균형보다 가중치 읽기·실행 경로를 다음 실험 대상으로 봅니다. backend stall을 RAM 대기 시간으로 해석하거나 DRAM 대역폭 포화를 확정하지 않습니다. 최고71.05°C·관측 현재 제한0이며 계측 native 비용은끔 대비약1.0~2.5% 증가했습니다. 새 연속 지연/CER 측정·운영 기본 변경은 없습니다.

**다음은 같은 Q8·2/3T에서 가중치 prefetch의 작은 고정 PCM 선별**입니다. 합성 비트/경계·전사/token과 앞뒤 대조를 먼저 확인하고, 이득이 있을 때 원래100개 연속 평가로 확대합니다. 이득이 작으면 encoder FP16 합성곱·투영으로 옮깁니다. 기존 웹61기록/23프로필을 유지했습니다. [전체 수치·범위·검증](../results/summaries/optimization/pmu-q8-20261117.md).

## Q8 GEMV 정수 누적 분리 — 2026-11-16

별도 라이브러리에서 Q8 GEMV의 정수 누적을 둘로 나눴습니다. RP5 합성 72조건의 출력 비트/버퍼 경계가 같았고 기존 PCM 3개×12라운드의 실제 36호출도 전사/token 동일·실패 0이었습니다. 모델·가중치 배치·스레드·운영 엔진은 유지했습니다.

후속/확정 decode 감소는 두 교차 구간에서 0.001%·0.414%, 전체 native 감소는 −0.164%·0.286%였습니다. 사전 3%/1% 기준에 미달해 공유 기본 적용·연속 평가 확대를 하지 않았습니다. 최고 73.8°C·관측 현재 열 제한 0에서도 이득이 작았습니다. 첫 빌드의 upstream 헤더 경고 실패는 보존하고 같은 원래 경고 옵션으로 새 ID에서 재시도했습니다.

**다음은 커널 변형보다 출력층·나머지 행렬의 CPU/캐시·작업 분할을 직접 구분하는 진단**입니다. 메모리 대역폭 병목을 확인한 것은 아닙니다. RP5의 PMU 계측 사용 가능 여부부터 확인하고 효과가 있는 후보만 같은 PCM→연속 입력으로 확대합니다. 기존 측정 웹 61기록/23프로필을 유지했습니다. [전체 결과·계측 범위·검증](../results/summaries/optimization/decode-q8-20261116.md).

## 다음 작업

1. 첫 요청0.6초의100개 확인은 완료됐습니다. 첫 반응 개선과 최종 CER/완료율 유지가 확인됐지만 첫4자 긴 지연 조건 하나가 미달해 공유1초를 유지합니다.0.8초100개는 미실행이며0.6초도 개발 후보로 보존합니다.
2. 주력은 확정 5초 정확도를 유지한 임시 표시 개선입니다. 예산3.0→3.2초 대조와 최신 재프로파일링을 완료했습니다. 다음은 최초 출력4자 미만인 구간에서 후속1회를 보호하는 선택 실험입니다. 입력 경계가 바뀌지 않도록 원래100개 시간축에서 기존 조건과 비교하며 예산·추정식·구간 길이를 한 번에 바꾸지 않습니다. ASR3초·잔여 처리는 별도 후보, 화면300ms 조회도 별도입니다.
3. 엔진 비용은 Q8 decode가 가장 크고 다음 최초 요청 대기에도 영향을 줍니다. Q8 GEMV/출력 행렬의 실제 경로를 좁히고, 첫 token 준비는 encoder FP16 합성곱/투영부터 검토합니다. 별도 빌드의 고정 PCM 전사/token 동등성·비용 확인 후 연속 지연과 최종 정확도를 검증합니다. 음성 prefill·suffix 최적화는 그다음입니다.
4. 마이크 탭에서 정답 문장을 읽어 입력 레벨·클리핑·문장 인식과 첫 표시를 확인하고 장시간 운영을 검증합니다. 정답 없는 짧은 기능 검사를 정확도 평가로 사용하지 않습니다.
5. Q8 생성2T/음성·prefill3T+고정 text prefix KV를 유지하고 반복 대조·장시간 안정성을 확인합니다. batch 대비 추가 오류134개와 부분 정답 정확도도 검토하며 자기 최종 가설 일치·문자 철회·음향 지연을 구분합니다.
6. Q4/Q5/Q6 자산·계측·결과는 별도 연구 참조로 보존합니다. 현재는 Q4 커널 추가 구현이나 양자화 확대를 주력 과제로 삼지 않고, 이후 독립 자료·잡음·장시간 운영을 검증합니다.
