# M3 후속 — RP5 확률 VAD 계약·지속 상태 점검

2026-11-02. **ARM64 모델 로딩과 개발 자료의 출력 계약 비교는 통과했다. 실제 30초 초과 연속 활성 조건은 아직 입증하지 못했다.** 기존 native 기본값과 30초 안전 제한, 전처리 정책 미승인 상태를 유지한다. [상세 JSON·근거 해시](m3-bounded-vad-rp5-20261102.json).

## 환경과 조건

Raspberry Pi 5 Model B Rev 1.0/aarch64, 기존 Python 3.11.18·NumPy 2.4.6·sherpa/core 2.0.1·Python ORT 1.31.1을 사용했다. native의 내장 ORT는 1.28.2로 별도 런타임이다. 기존 k2 Silero v4의 SHA는 `9e2449e1087496d8d4caba907f23e0bd3f78d91fa552479bb9c23ac09cbb1fd6`다. 비교 소스는 `69b162e`, 지속 상태 도구·reset 계측은 `a4744d8`이다.

Host main push 후 RP5에 반영했다. RP5의 GitHub SSH 키 인증이 실패해 HTTPS fetch와 fast-forward merge를 사용했고 기존 origin 설정은 보존했다. 패키지 설치·모델 다운로드·OS 설정 변경은 없었다.

기존 개발 80개(짧은 발화 64, 긴 발화 11, 미검수 잡음 후보 5)에 같은 주석·WAV·공통 PCM을 사용했다. **보류 화자 8명/18개는 추론과 워밍업에서 제외**했다. 사람 검수 정답은 없고 청취 메모 5개도 `판단 어려움` 상태를 유지했다.

순서는 native/identity → bounded/identity → bounded/rms26 → native/rms26. 실행마다 같은 짧은 발화 워밍업 1회, 표본별 1회다. 빠른 WAV 입력의 VAD+전처리+구간 처리이며 ASR·마이크·1배속 큐·Refine 성능이 아니다. 시작은 53°C 이하 3회 연속, 75°C/현재 제한/새 이력/결측에서 중단하는 감시기와 600초 timeout·4GiB 주소 공간 제한을 사용했다. governor는 ondemand로 고정 클럭 환경이 아니다.

## 동일 입력의 백엔드 비교

| 전처리 | VAD 백엔드 | 완료/계획 | 파이프라인 RTF | 평균 프로세스 CPU | 호출 구간 관측 최대 RSS | 감시 최고 온도 |
| --- | --- | --- | --- | --- | --- | --- |
| 원음 | native | 80/80 | 0.02745 | 100.06% | 76.08MiB | 61.15°C |
| 원음 | bounded | 80/80 | 0.03356 | 100.39% | 72.30MiB | 60.60°C |
| 공통 RMS | native | 80/80 | 0.02765 | 100.13% | 75.03MiB | 60.60°C |
| 공통 RMS | bounded | 80/80 | 0.03357 | 100.24% | 72.38MiB | 60.60°C |

총 **320/320개와 워밍업 4회**가 완료됐다. CPU 100%는 코어 하나 정도의 처리량이다. 한 번씩의 관측값이므로 속도·메모리 개선 비율이나 p50/p95를 일반화하지 않는다. 로딩·워밍업은 표에서 제외하며 JSON에 별도 보존했다. 로딩 wall은 native 원음/RMS 약 0.137/0.092초, bounded 약 0.149/0.137초였다. RSS는 세션·입력·수집 비용을 포함한 프로세스 표본이며 정확한 순간 피크가 아니다.

정책마다 **80개 모두** 구간 소유/문맥 경계·이유·오디오 반환 위치·payload/소유 PCM 해시와 예비 채점이 native/bounded 사이에 같았다. 실제 시계의 `emitted_monotonic_s` 등은 동등성 비교에서 제외했다. 과거 native 160개의 출력·채점과도 일치했다. Host에서 전처리와 각 payload 해시를 재검증했다. 이 자료에서의 계약 일치이며 모든 입력의 수치적 동등성을 증명하지 않는다.

짧은 발화의 전체 누락은 두 백엔드 모두 원음 **9/64**, RMS **4/64**로 같았다. 모든 주석 음성 프레임 기준 FN은 원음 8.566%, RMS 6.165%, 알려진 비음성 프레임 FP는 15.786%, 22.087%였다. 배포 예비 주석 기준으로 인식률이나 CER이 아니다. 미검수 잡음 후보는 각 정책에서 1/5개가 구간을 냈지만 확정 FPR로 채점하지 않았다. RMS 정책은 계속 미승인이다.

## 지속 상태: 실행 완료와 30초 활성은 다르다

별도 `probe-vad-duration`으로 두 입력을 각각 native/bounded, identity/rms26, 3/5/8초 상한에서 시험했다. 워밍업 0회·조건별 1회이며 threshold·가중치·양자화를 바꾸지 않았다. 비정상 파생 입력으로 정확도나 자연 장문 성능을 판단하지 않는다.

| 입력 | 준비 방법 | 조건별 실행 | 실제 최대 연속 활성 | 30초 초과 조건 |
| --- | --- | --- | --- | --- |
| 01: 45초 반복 | 첫 개발 long 표본의 가장 긴 예비 speech 구간 0.985초를 반복 | 12/12 완료 | 두 정책 5.892초 | 미충족 |
| 02: 90초 접합 | 01의 미충족 확인 후 개발 long 10개의 예비 speech 1,127구간을 순서대로 접합 | 12/12 완료 | 원음 10.756초, RMS 11.300초 | 미충족 |

01은 목록 순서·주석 길이, 02는 같은 개발 목록 순서·주석만으로 만들었고 모델 출력으로 개별 구간을 고르지 않았다. 02가 사후 공학 입력임을 계획과 manifest에 기록했다. 모든 원본·첫 입력·미충족 결과를 보존했다. 01의 두 전처리는 PCM이 같아 독립적인 음량 조건이 아니다. 02는 서로 다른 PCM이며 새 clipping은 두 정책 모두 0이었다.

bounded에서 각 세션의 실제 신경망 reset 차이는 **1**이었다. 초기 준비 reset과 새 세션 reset을 제외하면 강제 구간이나 자연 종료 때 reset하지 않았다. 45초/90초 입력을 각각 **1,407/2,813개 윈도**로 처리했다. 모든 완료 구간의 소유/문맥 PCM이 참조와 같고 겹침 없이 3/5/8초 상한을 지켰다. PCM 링버퍼 피크는 67,200/99,200/147,200프레임으로 용량 이하였다. bounded 내부의 파형 보관 0과 입력 전체 WAV·프로세스 메모리는 구분한다.

오디오 위치별 관측 RSS 범위는 01에서 bounded 72.67~74.17MiB/native 70.77~77.48MiB, 02에서 bounded 81.08~82.36MiB/native 78.94~88.34MiB였다. 서로 다른 세션과 시작 힙 상태를 합친 범위이며 장기 누수 부재나 메모리 개선 비율의 근거로 쓰지 않는다.

**90초 파일 처리 성공은 90초 연속 활성 성공이 아니다.** 실제 VAD가 중간에 종료해 native 30초 안전 중단도 이번 실제 입력에서는 발생하지 않았다. 지속 확률 mock은 Host에서 검증했지만 실제 신경망의 해당 조건과 동일시하지 않는다. 기본 경로의 안전 제한을 유지한다.

## 냉각·보존·검증

최초 센서는 51.25°C, 팬 2,966RPM, 현재·이력 제한 비트 모두 0이었다. 비교 네 실행 최고 61.15°C, 45초 점검 최고 61.70°C, 90초 점검 최고 66.10°C였다. 모두 외부 제한을 통과했고 관측 중 새 제한 이력은 없었다. VAD 1T 범위의 결과로 **과거 Zipformer 2T 고부하 냉각 실패가 해소됐다는 근거가 아니다**. 팬·히트싱크 접촉·통풍의 물리적 품질은 원격 조회로 확정하지 않았다.

- Host **187개**, RP5 **187개** 단위 테스트 통과. RP5 새 코드 반영 직후의 184개도 통과했다. Ruff 정적·포맷 검사 통과. 단위 mock 검사와 ARM64 실제 모델 실행 기록은 구분한다.
- 기존 `.venv/models/data/results/experiments` 비 Markdown **3,930개**를 전후 SHA-256 대조했다. 변경·누락 0이며 Python 실행 파일·버전과 NumPy/sherpa/core/Python ORT 버전도 같았다. 새 자산·결과만 별도 ID에 추가했다.
- 원시는 RP5와 Host의 `results/preflight/m3-bounded-vad-20261102-01`, `m3-vad-duration-20261102-01/02`에 보존한다. 보존 영수증·계획·전체 테스트·Host 분석 소스/해시는 `results/maintenance/m3-bounded-vad-20261102-01`, 새 WAV/manifest는 `data/evaluation/m3-vad-duration-20261102-01/02`다. 원시·WAV는 Git에서 제외하고 요약과 해시만 버전 관리한다.
