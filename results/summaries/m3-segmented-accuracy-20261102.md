# M3 자연 발화 구간 정책 CER 비교

2026-11-02. RP5에서 같은 KSS 개발 50개를 전체 발화·고정 5초·bounded VAD 상한 5초로 각 1회 평가했다. **전체/고정 창 CER 5.16%, VAD CER 5.56%**이며 모든 150개 평가가 성공했다. 고정 창은 정규화 후 50개 전사가 모두 같았고, VAD는 7개 개선·6개 악화·37개 동률로 총 오류가 3자 늘었다. [상세 JSON·발화별 차이·증거 해시](m3-segmented-accuracy-20261102.json).

## 고정한 조건과 실행

소스 `ca0ab0b`. 기존 SenseVoiceSmall 배포 INT8·sherpa/core 2.0.1·네이티브 ORT 1.28.2, 1T·한국어 `ko`·ITN false·기존 제어 태그 분리·`ko_cer_v1`을 사용했다. VAD는 기존 SHA의 k2 Silero와 Python ORT 1.31.1의 bounded 경로다. 모델·환경·원음·정답은 바꾸지 않았다.

입력은 164.919초, 정규화 정답 756자다. 순서는 사전에 `full_batch → fixed_windows_5s → bounded_vad_5s`로 고정했다. 각 조건은 새 프로세스·모델 1회 로딩·같은 첫 발화 ASR 워밍업 3회·manifest 순서 50개다. VAD 조건은 VAD만 별도 3회 워밍업했고 측정 발화마다 reset 1회, 발화 중 강제 구간에서 reset 0회다.

공통 identity PCM, 문맥 0, 추가 앞뒤 무음 0, 구간 텍스트 순서대로 공백 하나 연결을 유지했다. 중복 제거·금칙어·정답 수정·전체 발화 fallback은 없다. 미검출은 전체 정답에 대한 빈 가설로 채점하는 구현이며, 실제 이번 50개에는 미검출/실패가 없었다. ASR에 전달한 payload를 원본 PCM 슬라이스와 해시로 대조했다. VAD 마지막 계산 창의 512프레임 맞춤 0은 ASR payload에 붙이지 않았다.

CER 분모는 구간이 생략돼도 원본 발화 전체 정답이다. 전체 발화 CER/오류 수는 과거 M2-3 1T 기준선과 같았다. 5초 초과 4개·정답 93자만 따로 보면 전체/고정은 **3.23% (3/93)**, VAD는 **4.30% (4/93)**였다. KSS 한 화자의 개발 자료이고 8초 초과는 없어 독립 평가나 자연 장문 검증으로 일반화하지 않는다.

ASR RTF는 구간별 ASR 호출 비용 합/원본 길이다. 파이프라인 RTF는 전처리·VAD/구간화·ASR·텍스트 연결·구간 검증/계측을 포함한다. WAV 읽기·검증용 참조 PCM 준비·로딩·워밍업·결과 파일 쓰기는 제외한다. 기존 일반 batch의 순수 ASR RTF 또는 직전 Zipformer 연속 부하 수치와 이 파이프라인 RTF를 직접 비교하지 않는다.

전체/고정/VAD의 ASR 호출 합은 각각 **16.243/16.363/14.813초**다. VAD 신경망 호출은 별도 **2.324초**였으며, VAD가 줄인 ASR 시간만으로 전체 속도 향상을 주장하지 않는다. 파이프라인 RTF 차이는 작은 단회 관찰이며 실행 순서·클럭·온도·계측 비용이 있어 속도 우열을 확정하지 않는다. VAD의 RSS는 **ASR+VAD 공존 프로세스**이며 단독 VAD 메모리나 두 모델 동시 서비스 메모리가 아니다.

ASR 로딩은 조건별 1.867/1.869/1.847초, VAD 추가 로딩은 0.088초다. 같은 첫 발화 ASR 워밍업은 0.844/0.845/0.839초이며 VAD만의 워밍업은 0.280초다. 로딩·워밍업 비용은 위 RTF에서 분리했다.

## 구간 결과의 의미

- 고정 창은 원본 모든 프레임을 유지하고 5초 초과 4개에서만 두 구간으로 나눴다. 공백 차이가 있는 원시 전사는 4개였지만 **정규화한 전사는 50개 모두 전체 발화와 같았다.** 이 작은 자료에서 손실이 없었다는 결과이며 일반적인 단어 경계 안전성을 보증하지 않는다.
- VAD는 원본 프레임의 **89.68%**를 ASR에 전달했고 7개 발화가 두 구간이 됐다. 57개 구간 중 자연 종료 13개·EOF flush 44개이며 **hard_limit 방출은 0회**였다. 따라서 이번 비교는 주로 VAD 절취/자연 분할과 문맥 변화의 영향을 보며, 5초 강제 분할의 정확도 안전성을 검증한 결과는 아니다.
- VAD 대 전체의 순변화는 치환 +1·삭제 0·삽입 +2다. 전체 삭제 수가 같아도 발화별 손익이 상쇄되므로 누락이 없었다고 해석하지 않는다. 개선 7개와 악화 6개를 모두 JSON에 남겼다.

큰 회귀 사례는 `kss-train-01041`이다. 전체 오류 2자에서 VAD 6자로 늘었고 삭제가 4자 증가했다. VAD가 선택한 원본 범위는 **8,640~62,415프레임**, 즉 시작 0.540초를 생략하고 파일 끝까지 공급한 EOF 구간이다. 시작 절취와 문맥 변화는 원인 후보지만, 사람 검수 음소 정렬이 없어 음성이 어디서 잘렸는지 확정하지 않는다. `01035`는 삽입 +2, `01011/01016/01025`는 각각 치환 +1, `01031`은 삭제 +1이었다. 반대로 개선된 7개도 각각 오류 1자씩 줄어 총 7자가 개선됐다.

## 실행 환경·검증·보존

사용자가 승인한 `operational` guard 아래 기본 펌웨어 열 보호·팬/클럭/전압 설정을 유지했다. 각 실행은 ≤53°C 3회 연속 이후 시작했고 600초 timeout·4GiB 주소 공간·실제 PID 제한을 확인했다. 시작 전 온도는 **51.80/52.90/51.80°C**, 감시 최고는 **64.45/65.00/65.00°C**다. 현재 제한은 관측되지 않았고 새 제한 이력도 0이었다. 시작 이력 `0xE`는 이전 8분 부하의 이력으로 구분했다. 같은 온도·고정 클럭으로 통제됐다는 뜻은 아니다.

- **Host 209개 / RP5 209개 테스트 통과**(13.736/28.798초). 모델 없는 경계/PCM·빈 검출 삭제 채점·실패 보존·모델 재사용·워밍업·VAD reset·재채점·손상 거부 검사와 실제 ARM64 추론을 구분했다.
- 원시 **33개**를 RP5↔Host SHA256으로 확인했다. 세 조건의 원음/정답/PCM/구간 payload·전사 태그 정리·공통 CER·모든 상태를 교차 검사했다. Host에서 원시 predictions만으로 재채점한 summary와 scores가 모두 일치했다.
- 기존 `.venv/models/data/results/experiments` 비 Markdown **4,128개 변경·누락 0**, Python/패키지/기록한 시스템 설정 불변을 확인했다. 같은 부팅에서 coordinator·guard·worker 종료를 확인했다. 새 가중치/패키지 다운로드·환경 변경은 없다.
- 원시: 양쪽 `results/preflight/m3-segmented-accuracy-20261102-01`. 고정 계획·보존 감사·실행 순서/명령/PID·테스트·전송 체크섬·분석 소스와 Host 재채점: `results/maintenance/m3-segmented-accuracy-20261102-01`. [실행·재채점 명령](../../docs/archive/model-comparison/m3_segmentation_accuracy.md).

## 다음 판단

**현재 문맥 0의 VAD 조건을 정확도 개선 정책으로 채택할 근거는 없다.** 고정 5초는 이 개발 자료의 대조군으로 유지하고 자동 배포하지 않는다. 다음은 VAD 시작 여유 구간/200ms 문맥 후보를 사전에 고정해 회귀 사례와 전체 개발 자료에서 비교하고, 강제 상한이 실제로 발동하는 자연 장문을 별도 확보하는 작업이다. 결과를 본 뒤 유리한 발화만 골라 정책을 확정하지 않는다.

실제 Streaming 첫 자막·VAD endpoint·발화 종료 후 Refine 지연·입력 드롭/백로그·마이크·동시 Hybrid는 미측정이며 null이다. 빠른 파일 입력의 RTF를 실제 Refine 확정 지연으로 바꾸어 표시하지 않았다. 이번 단계는 구간 평가 도구와 개발 자료 비교 완료이며 M3 전체/Hybrid 완료가 아니다.
