# M3 운영 부하 검사: 기본 열 보호 아래 8분 완료

2026-11-02. 사용자 승인으로 80°C만으로 중단하지 않는 `operational` 정책을 추가하고 기존 **Zipformer 2T를 RP5에서 480.042초 연속 실행**했다. **1,203회 완료, 완전한 KSS 50개 순환 24회**이며 실패 없이 정상 종료했다. 고온에서 실제 감속·스로틀링을 관측했다. 이 결과는 열 조건을 통제한 모델 비교 합격이나 실시간 서비스 검증과 구분한다. [상세 JSON·원시 증거 해시](m3-operational-20261102.json).

## 실행 조건과 판정

- 소스 `564c0e8`, 같은 Zipformer 모델·INT8 encoder/joiner·기존 decoder·tail padding 0.66초·KSS 개발 50개·워밍업 3회. 모델 1회 로딩, 워밍업 제외 후 480초 동안 무대기 batch 반복 처리 1회다. 원본 설정/manifest/가중치 해시가 [직전 80°C 검사](m3-thermal80-20261102.md)와 같았다.
- RP5 ARM64, Python 3.11.18, NumPy 2.4.6, sherpa/core 2.0.1, sherpa 네이티브 ORT 1.28.2. 별도 Python ORT 1.31.1을 사용한 실험으로 바꾸지 않았다.
- 시작 전 51.80°C, 현재/이력 제한 0. 기존 53°C 이하 3회 연속 시작 조건·600초 timeout·4GiB 주소 공간·코어 덤프 제한과 실제 PID 제한 확인을 유지했다. SSH와 독립된 기존 guard 하나만 실행했다.
- `policy.stop_mc=null`, 80°C 이상 경고, 온도와 열 관련 제한 비트 1~3/새 이력은 관찰하며 계속 실행한다. 저전압·새 저전압 이력·필수 계측 누락·외부 제한 실패는 성공으로 처리하지 않는다. 펌웨어 열 보호·팬 곡선·클럭/전압 설정은 변경하지 않았다.
- 외부 영수증과 worker 모두 `completed`, `operational_valid=true`, **`control_valid=false`**다. 운영 검사 완료를 기존 통제 비교에 자동 합치지 않는다. 과거 75°C/80°C 중단 결과를 재판정하지 않았다.

## 처리 시간·CPU·메모리

| 집계 범위 | 호출 | 오디오 합계 | 순수 추론 합계 | 진단 batch RTF | 호출 CPU/wall |
| --- | --- | --- | --- | --- | --- |
| 전체 완료 호출 | 1,203 | 3,969.831초 | 479.802초 | **0.1209** | **331.8%** |
| 첫 완료 순환 | 50 | 164.919초 | 17.871초 | 0.1084 | 327.7% |
| 마지막 완료 순환 | 50 | 164.919초 | 20.635초 | 0.1251 | 332.8% |

같은 50개 ID/순서의 마지막 완료 순환은 첫 순환보다 **추론 시간이 15.47% 증가**했다. 마지막 부분 순환 3개는 이 비교에서 제외했다. 한 번의 실행에서 관측한 변화이며 온도만의 인과 효과나 장기 저하율을 확정하지 않는다. 전체 RTF는 완료 호출의 추론 시간 합/오디오 길이 합이다. 로딩·워밍업·JSON 기록·주변 처리 시간은 순수 추론 시간에 넣지 않았다. 연속 부하 구간 자체는 480.042초다.

전체 batch 호출 시간 p50/p95는 0.399/0.609초다. 서로 길이가 다른 같은 목록의 **batch 호출 시간 분포**이며 Streaming 첫 자막·발화 종료 후 Refine 지연이 아니다. 로딩은 2.446초, 로딩 구간 관측 최대 RSS는 280.125MiB, 추론 구간 관측 최대 RSS는 **257.641MiB**였다. 추론 첫/마지막 30초 RSS 표본 평균은 257.141/257.641MiB다. 이 짧은 표본으로 메모리 누수 부재를 확정하지 않는다.

TID 표본은 471개, 동시에 관측된 TID 최대 8개 중 평균 CPU ≥1%는 4개였다. 2T는 프로세스 전체 2코어 상한이 아니다. 스레드의 런타임 역할은 미확정이며 CPU 점유율을 클럭이나 처리량과 동일하게 해석하지 않는다.

## 온도·실제 클럭·제한 상태

| 관측 | 값 |
| --- | --- |
| 시작 전 / 감시 중 최대 sysfs 온도 | 51.80 / **85.90°C** |
| 종료 직후 sysfs 온도 | 77.65°C |
| 팬 관측 최대 | 9,787RPM |
| 첫 현재 열 관련 제한 | 시작 전 표본 후 약 40.237초, 80.40°C, 비트 3 |
| `Currently throttled` 비트 2 관측 | **95개 표본** |
| 주파수 제한 비트 1 / soft temperature limit 비트 3 | 95 / 295개 표본 |
| 저전압 비트 0 / 새 저전압 이력 | 0개 / 없음 |
| 실제 ARM 클럭 p50 | 약 **2.201GHz** |
| 호출에 연결된 표본의 sysfs 주파수 p50 | 2.400GHz |

총 감시 표본은 472개이며 실제 간격 p50/p95는 1.023/1.062초다. 위 비트 수는 before/monitor/after 총 474개 표본을 사용한 **관측 수**이며 지속 시간이나 독립 실험 수가 아니다. 비트 1/2는 같은 표본에서 함께 나타나므로 더해서 스로틀링 횟수로 해석하지 않는다. 새로운 제한 이력은 `0xE`이며 감속·스로틀링·soft limit을 포함한다. 필수 계측과 실제 클럭 조회 누락은 없었다.

sysfs 주파수가 2.4GHz로 남는 동안에도 실제 클럭과 제한 상태가 달랐다. 실제 클럭은 `vcgencmd measure_clock arm`으로 별도 기록했다. sysfs 온도·제한 비트·실제 클럭은 순차 조회이며 표본 사이의 정확한 변화를 복원하지 못한다. 호출 monotonic 시작/종료와의 연결도 그 표본 시각을 기준으로 한 근사다.

## 재현성과 보존

- Host **201개(12.829초)**, RP5 **201개(26.284초)** 단위 테스트 통과. 과거 75/80°C 경계와 운영 감속 허용·저전압/결측 거부·제한 미확인 실패·운영/통제 판정 분리를 mock으로 검사한 뒤 실제 ARM64 부하를 별도 실행했다.
- 원시 **8개**를 RP5와 Host 사이 SHA256으로 확인했다. worker/영수증·호출 ID/순환/음원 길이/시각·경고 로그·해시를 교차 검사했다. 같은 발화의 전사 해시는 모든 반복에서 같았으나 이는 CER 정답 검증이 아니다.
- 기존 `.venv/models/data/results/experiments` 비 Markdown **4,106개 변경·누락 0**. Python·패키지 버전/경로와 기록한 시스템 설정이 같았고, 같은 부팅에서 guard/worker 종료를 확인했다. 모델·원음·기존 실험 결과·패키지 변경이나 다운로드는 없었다.
- 원시: 양쪽 `results/preflight/m3-operational-20261102-01/zipformer-t2`. 사전 계획·보존 감사·launcher·테스트·전송 체크섬·분석 소스: 양쪽 `results/maintenance/m3-operational-20261102-01`. [정책·재현 절차](../../docs/archive/model-comparison/m3_thermal_policy.md).

직전 검사와는 중단 정책·폴링 간격·실제 클럭 조회·호출 시각 필드·소스 리비전이 다르다. 과거 검사보다 오래 실행됐다는 사실을 속도 개선이나 같은 조건의 모델 우열로 해석하지 않는다.

## 결론과 다음 범위

이번 장비·환경의 단독 Zipformer 2T는 **기본 열 보호로 감속하면서도 8분 batch 부하를 완료**했다. 80°C 초과만을 이유로 일반 개발이나 운영 검사를 막지 않는다. 모델 자체 성능을 통제 비교하려면 별도로 열·클럭 조건을 맞춰야 한다.

CER·실제 Streaming 첫 자막·Refine 지연·드롭·백로그·마이크·Hybrid 동시 실행은 이번에 측정하지 않아 JSON에 null로 남겼다. 무대기 batch RTF <1만으로 실시간 합격을 주장하지 않는다. 다음은 준비된 자연 발화 full/fixed5/VAD5 평가 도구를 구현하고 같은 정답으로 구간 정책의 CER 손익을 확인하는 작업이다. 이후 실제 1배속 입력과 동시 실행에서 지연·백로그를 계측한다. 온도/감속은 그 운영 결과에 함께 보고한다.
