# M3 VAD 시작 여유·200ms 문맥 후보 비교

작업 기준일 2026-11-03. **200ms 왼쪽 문맥을 일괄 적용하지 않는다.** KSS에서는 문맥 0 대비 CER가 5.56→5.42%로 1자 개선됐지만, 별도 합성 장문에서는 6.37→7.58%로 11자 악화됐다. 여섯 실행·159개 평가가 모두 성공했다. [상세 JSON·발화별 차이·증거 해시](m3-vad-context-20261103.json).

## 고정 조건

소스 `3e39cfd`. [사전 계획](../../docs/archive/model-comparison/m3_vad_context.md)에 따라 자료별 full → VAD0 → VAD200 순서로 각 1회 실행했다. SenseVoice 배포 INT8 1T·`ko`·ITN false·기존 태그 분리·identity·`ko_cer_v1`·기존 VAD 임계값을 유지했다. sherpa/core 2.0.1의 네이티브 ORT 1.28.2와 bounded VAD의 Python ORT 1.31.1을 구분했다.

기존 `SegmentPipeline(context_frames=3200)`을 재사용했다. 공통 분할기·어댑터·모델 가중치는 변경하지 않았다. 소유 범위/순서는 문맥 0과 200ms에서 53개 입력 모두 같았다. 소유 구간은 최대 5초, 실제 과거 원음을 포함한 payload는 최대 5.2초다. 첫 구간의 시작 여유와 후속 구간의 문맥이 같은 정책에 들어 있으므로 두 효과를 독립적으로 입증했다고 부르지 않는다.

각 실행은 새 프로세스·ASR 모델 1회 로딩·해당 자료의 같은 첫 발화 ASR 워밍업 3회다. VAD 조건은 VAD만 추가 3회 워밍업했다. 원본 발화마다 VAD reset 1회, 분할 중 reset 0회다. 전사는 단일 공백 연결이며 중복 제거·금칙어·정답 수정·전체 WAV fallback은 없다. 빈 검출은 원본 전체 정답에 대한 빈 가설로 채점하는 계약을 유지했고 이번에는 빈 검출/실패가 없었다.

KSS는 같은 원음 164.919초·756자이며 이전 결과를 본 개발 자료다. 전체/VAD0 기준선 CER는 이전 실행과 재현됐다. VAD200 대 VAD0는 **5개 개선·6개 악화·39개 동률**, 치환 -2·삭제 -1·삽입 +2, 순오류 -1자다. 전체 발화보다 오류가 여전히 2자 많다. 작은 개발 자료 차이로 정확도 개선을 확정하지 않는다.

사전 회귀 사례 `kss-train-01041`은 전체/VAD0/VAD200 오류가 **2/6/3자**다. 소유 시작은 8,640프레임(0.540초)으로 같고 후보 payload는 5,440프레임(0.340초)부터 공급했다. 문맥 0의 삭제 4자는 후보에서 0이 됐지만 치환 1자가 증가해 전체 발화와 같아지지는 않았다. 음향 정답 정렬이 없어 실제 음성이 어디서 잘렸는지는 미확인이다. 반대로 `01001`의 삽입 +2 등 다른 회귀도 남겼다.

KSS 소유 프레임은 두 VAD 모두 원본의 **89.68%**, 후보의 고유 payload 원음은 **95.57%**였다. 자연 종료 13개·EOF 44개, 강제 5초 방출 0회다. 같은 원음이 두 payload에 겹친 프레임은 0이므로 KSS의 추가 삽입을 실제 payload 중복 때문이라고 단정하지 않는다.

## 합성 장문과 강제 분할

기존 M2-3 KSS 연결 입력 3개를 그대로 읽었고 WAV/정답은 수정하지 않았다. 총 213.2677초·910자다. KSS 50개와 CER를 합치지 않았으며 자연 긴 대화나 독립 평가로 부르지 않는다.

| 실제 길이 | 정답 자수 | 전체 오류 | VAD0 오류 | VAD200 오류 |
| --- | --- | --- | --- | --- |
| 32.0675초 | 135 | 11 | 8 | 13 |
| 60.6133초 | 256 | 18 | 18 | 19 |
| 120.5869초 | 519 | 44 | 32 | 37 |

VAD200은 VAD0보다 **3개 모두 악화**, 치환 -8·삭제 +13·삽입 +6, 순오류 +11자다. 더 많은 문맥이 항상 유리하지 않았다. 두 VAD의 소유 범위는 같고 원본의 **81.84%**다. 후보가 전달한 고유 원음은 **88.96%**로 늘었다.

자연 종료 73개·EOF 3개·hard_limit 1개이며 실제 강제 방출은 **120초 입력에서 1회씩** 관측했다. 소유 범위는 1,280,960~1,360,960프레임(정확히 5초), 후보 payload 시작은 1,277,760프레임이었다. 관측 최대 소유 80,000프레임·payload 83,200프레임과 유한 버퍼를 확인했다. 한 번의 실제 방출을 폭넓은 자연 장문 안전성 검증으로 확대하지 않는다.

payload 사이에 중복 공급된 원음은 이 강제 분할 뒤의 **3,200프레임**뿐이다. 32/60초 악화도 있어 전체 회귀를 이 중복 하나로 설명할 수 없다. 문맥에 따른 디코딩 변화와 구간 처리의 상호작용은 추가 원인 후보이며 임의의 중복 텍스트 제거로 덮지 않았다.

## 계측 범위·검증·보존

ASR RTF는 구간별 ASR 호출 비용 합/원본 길이, 파일 파이프라인 RTF는 전처리·VAD/구간화·ASR·연결·검증/계측 비용/원본 길이다. WAV I/O·검증용 참조 PCM 준비·로딩·워밍업·파일 기록은 제외했다. VAD 조건 RSS는 두 런타임이 공존하는 주 프로세스 값이다. 평균 CPU는 모든 조건에서 약 100.1~100.2%였다. 로딩/워밍업 비용은 별도 보존했고 합성 장문 첫 32초 입력의 ASR 워밍업 약 14.9초와 KSS 첫 발화의 약 0.84초를 구분했다.

기본 열 보호/팬·클럭·전압 설정을 유지한 `operational` guard를 사용했다. 시작 온도는 **51.8~52.9°C**, 최고 관측은 KSS 전체/VAD0/VAD200 **64.45/64.45/63.90°C**, 합성 장문 **72.15/68.30/66.65°C**였다. 관측 현재 제한·새 제한 이력은 없고 이전 `0xE` 이력은 구분했다. 600초 timeout·4GiB 주소 공간·실제 PID 제한을 확인했다. 같은 온도/고정 클럭 성능 순위로 부르지 않는다.

- **Host 212개(14.421초) / RP5 212개(30.512초) 테스트 통과.** mock 강제 분할·지연 시작·과거 PCM·문맥 상한·빈 검출/실패/반복 전사 검사와 실제 ARM64 실행을 구분했다.
- 과거 세 문맥 0 조건의 실제 원시는 새 코드의 재채점과 summary가 일치했다. 이번 여섯 조건도 Host에서 모델 없이 재채점한 summary/scores가 모두 같았다.
- 원시 **66개**의 RP5↔Host SHA256, 53개 입력/정답·소유/문맥 payload·태그 정리·경계 일치를 대조했다. 이전 결과를 소급 수정하지 않았다.
- 기존 `.venv/models/data/results/experiments` 비 Markdown **4,184개 변경·누락 0**, Python/패키지/기록한 시스템 설정 불변을 확인했다. 같은 부팅에서 coordinator/guard/worker가 종료됐다. 새 모델·데이터·패키지 다운로드나 환경 변경은 없었다.
- 원시와 계획/보존/테스트/감사/재채점은 양쪽 `results/preflight/m3-vad-context-20261103-01`, `results/maintenance/m3-vad-context-20261103-01`에 보존한다. 보고서 작업일은 클라이언트 기준이며 원시 UTC/monotonic 기록은 기기 값 그대로다.

실제 Streaming 첫 자막·endpoint·Refine 확정 지연·드롭/백로그·마이크·Hybrid 동시 실행은 미측정으로 null이다. 추가 문맥 후보의 개발/스트레스 비교 완료이며 M3 전체 완료는 아니다.

## 다음 판단

200ms 일괄 문맥은 실험 후보로만 남기고 기본 정책에 채택하지 않는다. 시작 회귀 일부는 줄었지만 KSS 전체 기준선을 넘지 못했고 합성 장문 회귀가 있었다. 시작 여유와 모든 구간의 왼쪽 문맥을 같은 정책으로 늘리는 접근은 분리 검토가 필요하다.

정확도 정책 선정과 동시 부하 계측은 분리할 수 있다. 다음 M3-1에서는 원음 버퍼를 보존하는 고정 5초/문맥 0을 **비교용 조건**으로 고정하고 Zipformer 1T+SenseVoice 1T부터 첫 부분 출력·Refine 대기·온도·RSS·드롭/백로그를 실제 측정하는 순서가 적절하다. 서비스 채택 선언은 아니며 VAD 절취 정책·자연 장문·독립 평가·마이크 검증은 별도로 남긴다. 단독 batch 수치로 동시 성능을 채우지 않는다.
