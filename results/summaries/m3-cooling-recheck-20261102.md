# M3 냉각 재검증과 자연 발화 평가 준비

2026-11-02. **기존 Zipformer 2T는 현재의 75°C 중단 기준을 다시 통과하지 못했다.** 첫 위반 후 추가 ASR 부하·통제 성능 비교를 중단했다. 팬 고장이나 실제 하드웨어 throttling이 확인됐다는 뜻은 아니다. 자연 발화 구간 정확도 평가는 입력 점검·설계까지만 진행했다. [상세 JSON·근거 해시](m3-cooling-recheck-20261102.json).

## 기존 조건으로 한 번 재검증

RP5 aarch64/Python 3.11.18, NumPy 2.4.6, sherpa/core 2.0.1, Python ORT 1.31.1을 그대로 사용했다. 소스는 `441dd5a`다. `configs/zipformer_eval.toml`의 기존 2T·tail padding 0.66초와 KSS 개발 50개 순서를 유지했다. 2026-10-29 중단 실행과 **설정 값·설정 파일 SHA·manifest SHA·모델/tokens 4개 SHA가 모두 같았다**. 날짜·실내 조건·초기 열 상태·소스 커밋이 달라 속도 향상 비교로 쓰지 않는다.

계획은 모델 한 번 로드·첫 발화 워밍업 3회·480초 연속 호출 1회였다. 기존 감시기의 53°C 이하 3회 연속 시작, 75°C/현재 제한/새 이력/결측 중단, timeout 600초·주소 공간 4GiB 제한을 바꾸지 않았다. 실제 평가 PID의 주소 공간 제한을 확인했다.

| 관측 항목 | 결과 |
| --- | --- |
| 시작 전 감시 표본 | 52.35°C, 팬 2,976RPM, 현재/이력 제한 0 |
| 첫 중단 기준 초과 표본 | **76.55°C, 팬 8,992RPM**, 현재/이력 제한 0 |
| 위 두 표본 사이 | **15.140초** — 모델 로딩·워밍업도 포함 |
| 계획 / 완료 | 480초 계획, **중단**. 완료 호출 33개, 50개 전체 반복 0회 |
| 외부 판정 | `control_rejected`, `temperature_limit`, `control_valid=false` |
| 종료 후 확인 | 기록 PID가 사라져 실제 부하 종료 확인 |

모델 로딩은 2.581초였다. 완료된 33개 호출의 합계 wall은 10.840초, CPU는 35.841초(약 330.6%)였다. 전체 프로세스 평균이나 균형 잡힌 50개 성능 수치가 아니다. 1Hz TID 관측 최대 8개 중 관측 구간 평균 CPU ≥1%인 TID가 4개였다. `num_threads=2`는 프로세스 전체의 2코어 상한이 아니며 런타임 역할·풀/spinning 원인은 확정하지 않는다.

강제 종료 때문에 `worker.json`의 `running`은 그대로 보존했다. `execution.json`의 중단 판정이 우선하며 완료 실행으로 바꾸지 않았다. 중단 전 33개 호출은 원본 manifest 순서·길이를 검증했지만 이번 자료로 CER·통제 RTF·장기 성능 저하율을 새로 만들지 않았다. 이 값들과 실제 첫 자막·Refine 지연은 null이다.

## 팬이 있는데 왜 중단됐는가

사용자는 “안에 팬 있어 케이스 안에”라고 설명했다. **케이스 내부 팬이 있다는 사실만 확인**했으며 제품명, 뚜껑 개방 상태, 히트싱크 접촉과 통풍은 아직 미확인이다. 원격 RPM의 실제 증가를 확인했으므로 팬이 전혀 돌지 않았다고 판단하지 않는다.

로컬 thermal trip은 50/60/67.5/75°C였고 cooling device 최대 상태는 4였다. [공식 RP5 팬 제어 설명](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#raspberry-pi-5-fans)도 기본 최대 속도 기준을 75°C로 설명한다. **현재 실험의 중단선도 75°C이므로 최대 팬 상태에서 열평형이 유지되는지는 관측하지 못했다.** 이 정책과 하드웨어의 실제 제한/고장을 구분한다. 실제 제품이 공식 팬인지도 센서만으로 확정하지 않는다.

[공식 제한 비트 정의](https://www.raspberrypi.com/documentation/computers/os.html#get_throttled)에 따른 현재 비트·새 이력은 관측 표본에서 0이었다. 1Hz 표본 사이의 순간 상태까지 보장하지 않으며, 76.55°C 도달 자체를 실제 throttling 발생으로 부르지 않는다. 팬 곡선·PWM·클럭·governor·전압·75°C 기준을 임의로 변경하지 않았다.

다음 진단은 제품/설치 형태·흡배기 통로·히트싱크 접촉·주변 조건을 확인한 후 같은 기준으로 별도 ID에서 반복하는 것이다. 상태 확인 없이 같은 부하를 계속 돌리거나, 통과를 위해 중단선을 올리지 않는다. 이 미통과를 1T의 기존 성공 기록 삭제나 아직 실행하지 않은 Hybrid의 실패로 바꾸어 해석하지 않는다.

## 자연 발화의 구간 정확도 준비

기존 KSS 원본 **50개 해시**, 제공자 `expanded_script`, `ko_cer_v1` 기준 **756자·164.919초**를 확인했다. 3/5/8초 초과 발화는 각각 34/4/0개다. 새 데이터 다운로드나 불확실한 청취 전사의 정답 승격은 없었다.

다음 첫 평가안은 SenseVoice INT8 1T·ko·ITN false·identity PCM에서 완전 발화, 고정 5초 창, bounded VAD 5초 구간을 비교하는 것이다. 문맥은 모두 0, 구간 텍스트를 순서대로 단순 연결하고 중복 제거/금칙어/fallback을 넣지 않는다. 제공자 전사로 전체 CER 차이는 측정할 수 있지만 실제 음소 끝·구간별 정답·마이크 지연은 여전히 미확인이다. 냉각 미통과 상태에서 이 ASR 실험을 실행하지 않았다.
