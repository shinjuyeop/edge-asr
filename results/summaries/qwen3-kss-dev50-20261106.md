# Qwen3-ASR-0.6B INT8: RP5의 세 모델 KSS 비교

2026-11-06. **Qwen의 별도 ARM64 CPU 환경·실제 전사·공통 batch 통합을 검증했다.** 세 모델 × 1/2/4스레드의 9개 구성이 완료됐으며 채점 대상 450/450회, 워밍업 27/27회가 성공했다. 별도의 첫 실행 1회도 통과했다. Qwen CER는 3.57%로 SenseVoice 5.16%보다 낮지만 7개 발화는 악화됐고 처리 시간·RSS가 컸다. **정확도 개선 후보로 유지하되 실시간 보정 채택과 자동 교체는 보류한다.**

[수치·원시 해시 JSON](qwen3-kss-dev50-20261106.json), [사전 고정한 입력/출력·비교 정책](../../docs/archive/model-comparison/qwen3_batch.md), [배포 경로 근거](../../docs/archive/model-comparison/qwen3_deployment.md).

## 실행 조건

- 측정 소스는 clean main `eec0906c1f61481693fb2f5c870cba059c5ce67f`다. Host 개발·모의 테스트 → commit/push → RP5 동기화·동일 테스트 → 실제 추론 순서로 진행했다. Host에서는 ONNX 그래프 검사와 모의 테스트·재채점만 수행했다.
- RP5: ARM64 / Debian 13 / 4코어 / RAM 8GB. 새 `.venv-qwen3-onnx-20261106-01`의 Python 3.11.18, NumPy 2.4.6, sherpa-onnx·core 2.0.1, native ORT 1.28.2를 세 모델에 동일하게 사용했다. 별도 Python ORT 패키지는 없다.
- 기존 KSS 개발 50개, 합계 164.919초, 최장 5.853초, 정규화 정답 756자. 원음·manifest·expanded_script·`ko_cer_v1`를 유지했다. 입력/정답/소스/런타임 일치를 9개 구성 모두 대조했다. 독립 평가 자료가 아니다.
- 모델/스레드별 새 프로세스·1회 로딩·첫 발화 워밍업 3회 후 50개 순차 추론. **구성별 반복 1회인 탐색 측정**이다. 실행 순서는 사전에 1T Qwen→Zip→Sense, 2T Sense→Qwen→Zip, 4T Zip→Sense→Qwen으로 저장했다.
- operational 열 정책, 시작 53°C 이하·현재 제한 없음 3회, 4GiB 주소 공간·core dump 0·timeout 600초를 모든 구성에 적용하고 실제 PID의 제한을 확인했다. 고정 클럭 통제 비교가 아니다. 기본 펌웨어 보호·governor `ondemand`를 유지했다.
- Qwen은 한국어 고정, KV 512·최대 새 토큰 128·temperature 1e-6·top_p 0.8·seed 42·hotwords 없음이다. ITN 스위치는 미제공이며 native 표기를 그대로 채점했다. SenseVoice의 기존 언어/ITN 정책과 Zipformer flush도 변경하지 않았다.

## 같은 평가기의 결과

모두 성공 50/50, 정답 문자 커버리지 100%다. RTF는 준비된 PCM에서 결과 반환까지의 시간 합 / 음성 길이 합이다. 파일 읽기·모델 로딩·워밍업·채점은 제외한다. 파일 처리 p50/p95는 50개 발화의 nearest-rank 값이며 Refine 반환 지연이 아니다. CPU는 프로세스 기준으로 코어 하나가 100%다. RSS는 모델이 상주한 주 PID의 100ms 및 호출 경계 표본 최대이며 순간 피크를 보장하지 않는다.

Qwen과 SenseVoice는 1/2/4스레드에서 각각 50개 원시 전사가 같았다. Zipformer 4스레드는 `kss-train-01008` 1개 전사가 달라 오류가 88→91자로 늘었고 속도도 낮았다. 원인은 이번 단회 측정으로 확정하지 않으며 해당 결과를 제외하지 않았다. 같은 스레드의 반복 안정성이나 최적 스레드 수를 판정한 결과가 아니다.

모든 구성의 현재 제한 플래그는 관측상 0, 과거 제한 이력은 14→14로 유지됐다. Qwen 4T의 최고 관측은 79.85°C였다. 1Hz 표본 사이의 순간 변화나 장시간 열평형은 미검증이다. 운영 검사는 9/9 유효하고 `control_valid`는 모두 false다.

## 로딩·자산·잘림 확인

[sherpa 배포 아카이브](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25.tar.bz2)는 878,702,423바이트이며 다운로드 SHA-256은 `393f8a14e2f5fb96746aaab342997a40641001fbd5bf9592a080a8329178ee96`로 게시 digest와 일치했다. 기존 모델과 분리한 `models/qwen3-20261106-01/`에 보관했다. frontend FLOAT, encoder FLOAT/INT8, decoder FLOAT/UINT8 및 DynamicQuantizeLinear·MatMulInteger를 실제 ONNX에서 확인했다. 전부 INT8인 그래프나 양자화 생성 절차 전체를 검증했다는 뜻은 아니다.

첫 smoke(`e355604`, 1T, 공식 WAV 3.5265초, 워밍업 없음)는 로딩 5.112초 / 첫 전사 3.402초, 관측 RSS 최대 1422.3 / 1509.0MiB였다. 해당 프로브 시간에는 RSS 수집기 시작·종료 비용이 포함된다. 아래는 공통 평가기에서 별도로 측정한 Qwen 로딩이다.

| 1 | 5.215 | 1418.9 |

모델 파일을 먼저 해시했으므로 저장장치 cold start가 아니다. 로딩은 런타임 import·인식기 준비를 포함하며 워밍업과 분리했다. 세 Qwen 구성의 채점 대상에서 context 상한 최대 209 + 출력 예약 129 = 338로 KV 512 이내였고, 반환 토큰 최대 26으로 상한 128보다 작았다. native stderr는 모두 비어 있었으며 잘림/반복 경고·token 상한 실패는 없었다. native 정리 전 생성 토큰 전체를 수집한 것은 아니다.

## 보정 후보 판단

같은 스레드끼리 비교했을 때 Qwen은 SenseVoice 대비 **18개 개선·7개 악화·25개 동일**, 오류 총합은 39→27자였다. 악화 ID는 `01004`, `01005`, `01008`, `01009`, `01024`, `01026`, `01029`(모두 `kss-train-` 접두부)다. Zipformer 1/2T 대비는 29개 개선·3개 악화·18개 동일, 오류 88→27자다. 원시 전사와 정답은 로컬 결과에 보존하며 이 문서에는 싣지 않는다.

Qwen 2T는 batch RTF 0.6898·파일 처리 p95 3.400초·RSS 1778.8MiB였다. 4T는 RTF 0.6851로 비슷했지만 CPU 382.3%·최고 79.85°C였으며 파일 p95는 3.661초였다. 이 한 번의 결과로 4T를 최적으로 선택하지 않는다. 현재 자막 MVP의 SenseVoice 2T를 유지한다.

후속 검증의 시작점은 원음·동일 `vad0` 최대 5초 구간에서 Qwen 단독과 Zip 1T + Qwen 1/2T + VAD 동시 실행이다. 구간별 CER·개별 악화, 소유 구간 끝→반환/출력, 드롭·백로그·CPU/RSS·온도를 실제로 측정해야 한다. 실시간 지연·드롭·백로그·마이크는 이번 batch에서 측정하지 않았으며 JSON에 null로 남겼다. 동시 부하의 자원·온도와 장시간 안정성·독립 자료 성능도 미검증이다. 문맥 확대·출력 교정·자동 교체 정책을 사후에 추가하지 않았다.
