# M3-6 WAV 실시간 자막 MVP 검증

2026-11-03. **한 명령으로 WAV를 1배속 입력하고 연속 Zip 자막과 구간별 SenseVoice 보정 후보를 분리 표시하는 MVP를 구현하고 RP5에서 검증했다.** 자동 교체는0회이며 [M3-5 악화 사례](m35-guarded-splice-20261103.md)에 따른 보류 결정을 유지한다. 추가 모델·양자화·학습·전처리 튜닝은 없다.

## 실행과 구현 범위

실제 실행 소스는 `17e0a5e5974873afe8349af221185da6b8988031`이다. Host에서 구현/테스트 후 main push·RP5 fast-forward로 동기화했다. [사용 안내](../../docs/guides/legacy/live_captions.md)의 다음 명령을 RP5 기존 `.venv`에서 실행한다.

```bash
.venv/bin/python scripts/edge_asr.py live \
  --wav models/sherpa-onnx-streaming-zipformer-korean-2024-06-16/test_wavs/0.wav
# 기존 정답·해시가 있는 개발 자료
.venv/bin/python scripts/edge_asr.py live \
  --manifest data/evaluation/kss-dev50/manifest.jsonl
```

`captions.py`는 기존 온라인 VAD/연속 Zip 경로를 사용한다. `tools/live.py`는 입력 검사·고유 출력 경로·기존 열 guard·부모 stdout 표시와 재집계를 연결한다. `probe-concurrent --caption-display`는 별도 모드로 추가했고 기존 batch/paced_stream/실험 기본값을 바꾸지 않았다. `ConcurrentReplay.offer_payload()`는 기존 기록과 함께 등록된 작업을 반환하도록 확장했다. guard의 console 전달 callback은 선택 사항이며 기존 호출은 파일 기록 동작을 유지한다.

Zip은 원본마다 연속 상태를 유지한다. `Zip 임시`/`Zip 최종`과 `보정 대기`/`보정 후보·자동 적용 안 함`을 구분하며, 후보에 원본 ID와 원본 시작 기준 음성 구간을 붙인다. 늦은 결과도 원래 ID에 표시한다. 원문을 보존하고 Zip 덮어쓰기·임의 단어 필터·중복 제거는 하지 않는다. terminal 제어 문자는 표시에서만 escape한다.

## 고정한 조건과 실제 실행

- RP5 ARM64·Debian13·Python3.11.18, 기존 numpy2.4.6/sherpa2.0.1. native ORT1.28.2와 Python ORT1.31.1을 구분해 기록했다.
- Zip1T+Sense2T+Silero VAD1T, 기존 가중치·원음·vad0 정책·최대5초 구간. 입력100ms/capture5청크, Refine2작업 FIFO와 drop_newest를 유지했다.
- 모델별 로딩/워밍업3회와 실제 입력 구간을 분리했다. `operational` 열 정책·4GiB 주소 공간/프로세스·600초 timeout·저전압/계측 실패 거부를 사용했다. 온도/감속은 관찰하며 기본 펌웨어 보호를 유지한다. `control_valid=false`인 운영 검사다.
- 사전 순서는 짧은 WAV→KSS50→기존 합성120초→디지털무음6개다. 총4회, 원본 항목58개·오디오303.642375초다. 새 독립 평가가 아니며 기존 개발 입력을 다시 실행했다.
- stdout은 파일로 캡처했다. 실제 모델 추론·독립1배속 입력·parent stdout flush를 측정했으며 물리적 화면 렌더링이나 SSH 네트워크 도착 시각을 측정하지 않았다.

네 실행 모두 `completed`/`operational_valid=true`였다. 생성 이벤트887개와 실제 stdout 기록이 대응했고, 최종 Zip58개·보정 후보101개를 표시했다.

| 입력 | 오디오 길이 / 원본 수 | 첫 Zip stdout | 소유 구간 끝→보정 stdout | 보정 후보 |
| --- | --- | --- | --- | --- |
| 짧은 WAV | 3.5265초 / 1 | 0.843초, n=1 | 0.234초, n=1 | 1 |
| KSS 개발 | 164.919초 / 50 | p50/p95 0.853/1.459초 | p50/p95 0.277/0.639초, n=57 | 57 |
| 기존 합성 장문 | 120.586875초 / 1 | 0.844초, n=1 | p50/p95 0.508/0.627초, n=43 | 43 |
| 디지털무음 | 14.61초 / 6 | null, 관측 없음 | null, 호출 없음 | 0 |

첫 Zip 값은 **오디오 입력 시작 기준**이다. 구간 끝→보정 값은 VAD 종료 판단·방출·큐·추론·반환·출력을 포함한다. 실제 발화 음향 끝 기준 지연·교체 적용 지연으로 부르지 않는다. 단일 관측의 p50/p95는 null로 유지했다.

worker 가용 시점→parent stdout flush의 KSS p50/p95는0.192/2.073ms, 최대38.725ms였다. 합성은0.210/0.847ms, 최대4.756ms다. 이 값은 파이프/부모 출력 경로의 측정이며 사용자 화면의 응답 시간 보증이 아니다. 새 UI/마이크/정렬 지연은 null이다.

## 전사 보존·큐·자원·온도

| 입력 | Zip CER | 구간 Refine 단독 CER | main+Refine 평균 CPU | 동시 표본 최대 RSS | 최고 관측 온도 |
| --- | --- | --- | --- | --- | --- |
| 짧은 WAV | null, 정답 없음 | null, 정답 없음 | 29.83% | 639.72MiB | 61.70°C |
| KSS | 11.64% (88/756자) | 5.56% (42/756자) | 35.26% | 674.78MiB | 61.70°C |
| 합성 장문 | 11.18% (58/519자) | 6.17% (32/519자) | 31.67% | 707.89MiB | 62.25°C |
| 디지털무음 | null, 빈 정답 | null, 빈 정답 | 21.68% | 629.16MiB | 61.15°C |

Refine 단독 CER는 구간 출력을 원본 단위로 평가한 기존 지표이며 최종 병합 전사의 CER가 아니다. 짧은 `--wav`의 자동 manifest 빈 정답은 자리표시자다. 무음 정답이나0% 정확도로 해석하지 않는다.

KSS/합성/무음의 Zip 최종 전사와 모든 Refine 전사는 M3-4의 기존 결과와 바이트 단위 문자열 비교에서 같았다. Zip CER/정답도 같았다. 디지털무음은 Zip6개 모두 빈 전사·Refine 호출0이었다. 입력/Refine 드롭·실패·미반환0, Refine 최종 백로그0초였고 입력 이벤트 최대 큐는 각 실행0.1초였다. 입력 큐 원시 재구성·발화/작업 ID·PCM 해시를 기존 집계기로 교차 확인했다.

CPU는1코어=100%이며 대기를 포함한 실제1배속 측정 구간의 PID 합이다. main에는 Zip/VAD/조정/표시 이벤트 생성 비용이 포함되고, 별도 stdout 부모·guard·producer는 제외한다. RSS는 같은 시각 표본의 합이며 공유 페이지가 중복될 수 있다. 과거 batch CPU323%와 같은 처리 부하로 비교하지 않는다. 기존 진단과 이번 모드는 계측 부가 비용도 다르므로 차이를 최적화 효과로 주장하지 않는다.

모든 열 표본에서 현재 제한·새 제한 이력은0회였다. 이전 이력 `0xE`는 그대로 보존했다. 이번 최장 단일 입력은120.586875초이고, 새 MVP의8분/상시 운영 검증은 수행하지 않았다. 과거8분 batch 부하를 MVP의 장시간 합격으로 대신하지 않는다. KSS의 모델 로딩은 Zip2.449초·Sense1.844초·VAD0.090초였고 각각의 로딩 CPU/RSS와 워밍업은 JSON에 별도 보존했다.

## 회귀·재현·기존 자산 보존

- 최종 Host286개/40.354초, RP5286개/67.845초 단위 테스트 통과. 새7개는 원문/늦은 반환·실패/드롭/빈 결과·ID/해시/중복·출력 escape/전달 실패·모의 실제 IPC·재집계/변조 거부를 검증한다. Host의 초기 구조 검사 실패는 실행 도구를 `tools/`로 옮겨 해결했고 초기 로그도 유지했다.
- RP5 실제 모델4회와 위 모의 테스트를 구분했다. Host에서 모델 없이4개 표시/추론 원시 재집계를 다시 실행해 저장 요약과 일치했다.
- 원시89개(7,533,461바이트)를 RP5에서 Host로 전송한 뒤 양쪽 전 파일SHA256이 일치함을 확인했다. [JSON 요약](m36-wav-mvp-20261103.json)에 전 파일SHA256과 계획/테스트/감사 해시를 기록했다.
- 기존 비 Markdown 파일5,503개 변경·누락0, 모델·가상환경·설치 패키지·시스템 설정 불변을 전후 감사로 확인했다. 기존 M1/M2/M3 원시와 설정을 보존했다. 새 모델 다운로드·환경 설치는 없다.

원시는 `results/live/m36-wav-mvp-20261103-01/`, 계획/실행/테스트/감사는 `results/maintenance/m36-wav-mvp-20261103-01/`에 보관한다. 새 실행은 고유 경로만 사용한다. 단절·중단·실패를 성공값으로 채우지 않는다.

## 완료 범위와 다음 단계

WAV 자막 MVP의 분리 표시 정책·한 명령 실행·RP5 실제 검증까지 완료했다. 사용자는 스피커 없이 같은 명령으로 출력 흐름을 볼 수 있다. 자동 보정의 안전성·마이크·실제 화면/네트워크·자연 장문 독립 평가·상시 운영은 별도다.

다음 우선순위는 실제 입력 장치를 확인하고 WAV 입력 경로를 마이크 capture로 연결하는 것이다. 자동 교체는 입력 음성/문자 범위 대응과 개별 악화 문제를 검증한 뒤 별도 정책으로 판단한다. 현재 기본은 Zip 자막을 보존하고 보정 후보를 구분해 표시하는 방식이다.
