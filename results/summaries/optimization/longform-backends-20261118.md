# RP5 긴 음원 스트리밍 기준선 — ONNX INT8과 GGUF Q8

같은 12개 음원에서 GGUF Q8의 최종 CER는 **12.03%(384/3,192자)**, ONNX INT8은 **14.16%(452/3,192자)**였다. Q8은 자연발화에서 54자, 낭독에서 14자 적게 틀렸고, 두 자료 모두 같은 성공 구간의 확정 지연 p95가 짧았다. 두 엔진에서 확정 233구간의 좌표와 ASR 입력 PCM 해시가 전부 일치했다. 네 실행 모두 전체 입력을 처리했고 드롭은 0건이었다. ONNX 낭독에서 확정 1건이 실패했다. 자연발화는 파일 경계를 넘은 확정이 7개여서 개별 화자 CER를 매기지 않았다. 낭독은 4개 모두 독립 귀속이 가능했다. 추가 무음 없는 여성 낭독 파일은 ONNX 76/206자·Q8 66/206자로, Q8에서도 전체 낭독 오류 127자 중 66자가 이 한 파일에서 나왔다. 조건별 일반화에는 같은 조건의 화자가 더 필요하다.

총 추론은 실제 부분·확정 호출의 벽시계 시간 합이다. 두 자료 합계는 ONNX 631.04초, Q8 565.53초였다. Q8은 부분 요청을 더 많이 실행했는데도 총 추론 시간이 짧았고, 동시에 사용한 평균 CPU 코어 수는 더 많았다. 4코어 사용률은 입력 시작부터 배출까지 주 프로세스와 입력 프로세스의 CPU초 합을 벽시계 초×4로 나눴다. RSS는 주 프로세스 표본 최댓값이다. 최고 온도는 실행 감시 표본, 제한 시간은 실제 입력 중 약 1초 간격의 현재 제한 비트를 적분한 근사치다. 부팅 후 누적 이력은 제한 시간에 합산하지 않았다.

자연발화 약 467초 중 제한 시간은 Q8 약 366초, ONNX 약 100초였다. 네 실행 모두 대기 입력은 최대 1청크였고, EOF에서 입력 큐가 비었다. ONNX 낭독의 확정 큐 대기 p95는 입력을 시간순으로 4등분했을 때 4.21·1.50·2.95·12.86초였다. 마지막 4분의 1에서 반복 생성 실패 뒤의 대기가 늘었고, 입력 큐는 EOF에 비어 있었다. 이 측정에서 가장 긴 단일 연속 입력은 7분 47초이며 더 긴 시간의 열평형·안정성은 별도 검증이 필요하다.

## Q4의 다음 진단을 고를 근거

이전 Q4 최대 3회 기록과도 파일·확정 233구간의 PCM이 일치했다. 해당 Q4는 **15.73%(502/3,192자)**였고 Q8은 **12.03%(384/3,192자)**였다. Q4가 실패한 확정 7개에서만 저장된 Q8 전사로 바꾸고 나머지 Q4 전사를 유지해 재채점했다. 자연발화 오류는 336→338자, 낭독은 166→167자, 합계는 **502→505자**였다. 두 모델이 모두 성공하고도 정규화 전사가 다른 구간은 자연발화 72개, 낭독 37개였다. 이 계산은 저장된 결과에 대한 민감도 분석이며 이중 모델의 지연·열·실제 전환 성공률은 미측정이다. Q4의 스케줄러·빌드가 이번 Q8과 달라 양자화 단독 효과나 속도 차이는 여기서 결정할 수 없다. [기존 Q4 실험](longform-stream-20261118.md)

짧은 잔여 구간은 출력이 비어 있는지만으로 판정하기 어렵다. ONNX는 0.5초 미만 확정에서 자료 전체 정답에 없는 ‘시스템’을 자연발화 5회·낭독 2회 반환했고, Q8은 같은 길이대에서 구두점만 반환한 구간이 있었다. **첫 후속 작업은 두 모델 모두 성공했지만 전사가 달랐던 Q4/Q8 109구간**에서 인접 음성과 원본 전사를 함께 보며, 5초 절단부에 걸친 오류와 구간 내부 오류를 분류하는 것이다. 파일·발화 라벨에 걸친 곳은 귀속 불확실로 남긴다. 경계에 집중되면 중첩·문맥 복원을, 내부 오류에 집중되면 동일 빌드·동일 스케줄에서 decoder 정밀도 대조를 먼저 검증할 수 있다.

이번 긴 음원의 ONNX를 배포 엔진 기준, Q8을 GGUF 개발 기준으로 유지한다. 기존 고정 100개의 직접 대조는 별도 참조다. 당시에는 정답 3,848자, VAD 원음·갱신 1/2초·2스레드로 ONNX 15.98%, Q8 13.23%였다. 이번 긴 음원과 분모·전처리·부분 정책이 달라 수치를 합산하지 않았다. 현재 정책에서의 짧은 음원 성능을 판단할 때는 같은 정책의 고정 100개 짝대조가 필요하다. [고정 100개 동일 조건 비교](realtime100-backends-20261110.md)

## 무엇을 고정했나

RP5(Cortex-A76 4코어, RAM 8GB)의 같은 체크아웃 `aa57ee0`에서 자연발화 ONNX → 자연발화 Q8 → 낭독 Q8 → 낭독 ONNX 순서로 한 번씩 실행했다. 추론 작업은 한 번에 하나만 실행했다. 각 실행은 60°C 이하·현재 제한 해제 상태에서 시작하도록 기다렸고, 고정 냉각과 기존 펌웨어 열 보호 아래에서 `operational` 정책으로 온도와 성능 제한을 기록했다. 매 실행에서 모델을 한 번 로드하고 첫 파일 앞 5초로 첫 추론 1회와 추가 워밍업 3회를 수행했다. 아래 지연의 시작 시각은 워밍업 후 1배속 PCM 입력을 시작한 때다.

- 자연발화는 Seoul Corpus의 서로 다른 8명, 467.428초·2,129자다. 발화 비율이 높은 조건, 간투사, 쉼, 웃음 조건이 각각 2개다. 낭독은 Zeroth-Korean의 서로 다른 4명이 읽은 원본 문장을 화자별로 연결한 4개, 265.229초·1,063자다. 문장 사이에 추가한 무음이 0초/1.2초인 파일이 각각 2개다. 음원당 52.85~70.85초다. [세트 선정·전사 출처](../../../docs/research/longform.md)
- 각 자료 안에서 파일을 추가 무음 없이 이어 붙이고 경계에서 상태를 초기화하지 않았다. 16kHz 모노, 100ms 단위 1배속 입력, Silero VAD 임계값 0.3·`rms26-floor80`, VAD·ASR 최대 5초·이전 문맥 0초, 첫 부분 요청 1초·후속 간격 4초의 고정 정책을 공통 적용했다. 입력 큐 10청크, 대기 확정 최대 4개·교체 가능한 대기 부분 1개, 완전 무음 생략, EOF 배출 제한 30초다. 부분 요청은 실제 부하에 따라 병합될 수 있다.
- ONNX는 배포된 Qwen3-ASR-0.6B의 frontend FP32·encoder INT8·decoder UINT8 혼합 그래프와 sherpa-onnx CPU 2스레드를 사용했다. GGUF는 현재 Q8_0 음성·텍스트, 생성 2스레드·음성/프리필 3스레드, 고정 텍스트 접두부 KV 캐시를 사용했다. 두 구성 모두 한국어·greedy·문맥 512·최대 출력 128이다. Q8은 토큰 콜백을 켠 한 실행에서 완료 결과와 토큰 포함 표시를 모두 집계했다. 스레드·런타임·콜백을 포함하는 실제 운영 구성을 비교했다. [ONNX 설정](../../../configs/onnx.toml) · [GGUF 설정](../../../configs/gguf_realtime.toml)
- `ko_cer_v1`로 각 자료의 정답과 모든 확정 전사를 연결해 계산했다. 실패로 빈 전사가 남은 구간도 정답 분모에 포함했다. 전체 CER는 두 자료에서 독립 계산한 오류 수와 정답 문자 수의 합으로 계산했다. 자연발화 8개를 개별 파일로 강제 분할해 재채점하지 않았다.

## 지연표를 읽는 법

- **첫 표시와 공백**은 원음별로 계산했다. 해당 파일에만 귀속되는 자막이 서버에서 처음 발행될 때까지의 시간, 입력 중 문자가 실제로 바뀌는 사이의 최장 시간이다. 파일 시작과 끝의 공백, 내부 무음이 들어간다. 글자가 그대로인 재발행은 갱신으로 세지 않는다. 파일 수가 8개와 4개여서 이 표의 p95는 각각 그 자료에서 가장 느린 파일이다.
- **구간 내 부분 표시**는 길이 2초 이상인 VAD 소유 구간 중 자기 구간이 끝나기 전에 해당 구간의 부분 전사 문자가 한 번이라도 발행된 수다. **입력 나이**는 표시가 변경된 시각에서 그 요청이 사용한 마지막 음성 프레임 시각을 뺀 값이다. 음향 단어별 지연과 물리 화면 표시 시각은 측정하지 않았다.
- **파일 끝→마지막 확정 응답**은 그 파일과 겹치는 마지막 확정 호출의 응답까지 재며 실패 응답도 집계한다. **구간 끝→확정**은 VAD 소유 구간 끝에서 응답까지이며 두 모델이 모두 성공한 동일 구간만 표에 사용했다. 전체 시도 및 모델별 성공 구간의 분포도 JSON에 보존했다.
- Q8 토큰 표시는 UTF-8 접두부가 처음 보이는 시점부터 집계한다. 한 호출에서 글자를 연속 방출해도 그 호출에 들어간 음성의 끝은 고정돼 있다. 따라서 토큰 사이 시간이 짧아지는 효과와 더 최근 음성을 반영하는 효과를 구분한다.
