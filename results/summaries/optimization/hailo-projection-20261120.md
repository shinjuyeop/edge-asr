# Qwen Q8의 Hailo-8L Conv2·CNN 출력 투영 대조

2026년 11월 20일 RP5 실측 · 11월 23일 Host 기록 검증 · 실행 ID `hailo-projection-20261120-02` · 소스 `f0eca50`. [집계와 원시 기록 해시](hailo-projection-20261120.json)

**저지연 정책에서 Hailo의 주된 이득은 Conv2에서 나왔다.** 같은 100개 한국어 원음의 확정 추론은 CPU 609.15초, Conv2 557.97초, Conv2+Projection 554.45초였다. 결합 경로의 첫 자막 중앙값은 CPU의 7.49초에서 3.58초로 짧아졌지만, 첫 자막 p95는 8.37초에서 7.93초로 줄었다. 운영 기본은 Q8 CPU이며 Conv2를 우선 Hailo 후보로 둔다.

초기 조사에서는 정적 그래프 23개를 파싱 시도하고 Qwen HEF 12개를 실제 Hailo-8L에서 실행했다. DFT·Mel은 왕복을 포함하면 CPU보다 느렸다. 첫 Transformer 블록 일부와 LLM FFN 단일 선형층은 독립 실행까지 확인했다. 전체 Encoder 18층과 LLM prefill·decode, KV 캐시는 CPU가 담당한다. 초기 고정 갱신 정책의 Conv2 추론 합계 1.57% 감소와 이번 가변 정책의 확정 추론 결과는 측정 대상과 조건이 다르다. [초기 단계별 실측 및 Hailo 지원 판정](hailo8l-q8-20261120.md)

## 재현 조건

RP5·AI Kit·기존 냉각을 사용했다. Hailo-8L은 PCIe Gen2 ×1이고 NVMe 부팅 장치는 USB 경로다. CPU 상한과 하한을 1.50 GHz로 맞추고 기존 ondemand governor와 펌웨어 열 보호를 유지했다. 성능 측정은 매번 2초 간격의 연속 세 온도 샘플이 71.5°C 이하일 때 시작했다. 아래 입장 온도는 이후 공통 계측기가 별도로 읽은 값이다. 팬 RPM은 운영체제에서 읽히지 않았다. 입력 중에는 실제 ARM 클럭과 제한 비트를 약 1초마다 기록했다. 장시간 부하에서 펌웨어가 상한보다 더 낮은 클럭을 사용할 수 있다.

- 동일 Qwen3-ASR-0.6B Q8 GGUF·mmproj, 고정 llama.cpp `7d7f028`, [Q8 설정](../../../configs/gguf_realtime.toml). 음성 처리·batch 3스레드, decode 2스레드, 한국어 greedy. 기존 bridge와 CPU 커널을 사용했다.
- [선택 preload](../../../native/gguf/hailo_conv.cpp)는 Qwen의 무편향 두 번째 합성곱, CNN에서 첫 Transformer 블록으로 넘기는 선형 투영, 또는 두 연산을 모두 대체한다. Conv bias·GELU, Encoder 18층, 최종 음성 임베딩 투영, LLM prefill·decode와 KV 관리는 기존 경로에서 계산한다.
- [전 실험](hailo8l-q8-20261120.md)에서 같은 가중치로 만든 DFC 3.34.0 HEF 두 개를 재사용했다. Conv2는 `conv2_linear.hef`, CNN 투영은 `conv_out_row.hef`다. RP5 HailoRT·드라이버·펌웨어는 모두 4.23.0이다. 두 HEF를 함께 쓸 때 같은 VDevice에서 round-robin으로 실행하고, 행 단위 투영은 GGML의 연속 FP32 버퍼에 직접 읽고 쓴다.
- [저지연 스트리밍 설정](../../../configs/listener_q8_headroom.toml)은 첫 부분 요청 0.6초, 새 음성 최소 1.0초, 여유 0.2초, 확정 우선 취소와 토큰 단위 표시를 쓴다. 원음 순서·VAD 0.3·전처리·최대 5초 분할·4칸 입력 큐·원음 사이 공백 0·100ms당 1배속을 맞췄다. 실제로 제출하거나 취소하는 부분 요청의 개수는 남은 처리 시간에 따라 달라진다.
- 최종 정확도는 원래 정답과 전체 확정 전사의 `ko_cer_v1`이다. 첫 표시는 음원 시작부터 그 음원에 유일하게 귀속되는 첫 서버 자막 이벤트까지, 최신 반영 공백은 표시 내용이 바뀌면서 처리한 음성 끝 시점이 전진하는 이벤트 사이의 간격(양끝 포함), 확정 지연은 구간 끝부터 확정 발행까지다. 브라우저 렌더 지연은 측정 범위 밖이다.
- 전력은 입력 구간에 PMIC의 VDD_CORE 전류와 전압을 약 1초마다 읽어 곱한 후 평균했다. 측정 범위는 SoC 코어 레일이다. 보드 전체와 Hailo 자체 소비전력은 미측정이다.

### 첫 자막이 8초대인 이유

이전 고정 갱신(첫 요청 1초·후속 4초)의 CPU p95 8.82초는 100개 원음의 첫 표시를 빠른 순서로 정렬했을 때 95번째 값이다. 그 음원의 첫 표시를 실제 만든 요청은 5초 상한에서 닫힌 확정 구간이었다. 원음 시작→해당 요청 제출 5.508초, 큐 0.528초, 실행 시작→첫 표시 2.785초가 걸렸다. 이전 CPU에서는 16개 원음에서 첫 표시가 확정 요청이었다. 이 과거 실행은 이번 하드웨어 속도비 계산에서 제외했다.

이번 저지연 정책에서도 CPU p95를 만든 구간은 부분 호출 없이 5초 상한에서 확정됐다. 실제 합은 5.989 + 0.003 + 2.383 = 8.375초다. 결합 경로의 p95 음원에서는 5.974 + 0.001 + 1.957 = 7.933초였다. 뒤의 두 사례는 서로 다른 음원이다. 0.6초는 부분 요청이 가능한 가장 이른 시점이다. CPU는 100개 중 61개, 결합 경로는 38개에서 첫 자막이 확정 요청이었다. CPU 스케줄러에는 확정이 너무 가깝다고 판단한 결정 1,685회, 열 상태로 연기한 결정 307회가 기록됐다. 같은 후보를 여러 번 검사하므로 결정 수는 고유 호출 수와 다르다. 자막을 더 일찍 보이려면 첫 표시 이전의 입력 수집과 스케줄러 선택도 개선해야 한다.

### 정확도 차이의 분포

호출 구간이 음원 경계를 넘을 수 있어 전체 확정 전사를 원래 정답에 한 번 정렬했다. 공통 채점기의 대각선→삭제→삽입 동률 규칙으로 오류를 복원하고 정답 문자 좌표로 음원에 귀속했다. 경계 삽입은 다음 음원, 마지막 삽입은 마지막 음원에 귀속했다.

| CPU 대비 후보 | 오류 감소 / 동일 / 증가 음원 | 감소한 오류 / 늘어난 오류 | 순변화 |
| --- | --- | --- | --- |
| Conv2 | 27 / 55 / 18 | 65 / 41 | −24 |
| Projection | 12 / 85 / 3 | 18 / 5 | −13 |
| Conv2+Projection | 27 / 53 / 20 | 66 / 47 | −19 |

결합 경로에서 한 Zeroth 원음의 오류가 21→9자로 줄었고, CPU 오류가 0이던 FLEURS 원음 하나는 5자로 늘었다. 이전 고정 갱신 실험과 이번 실험을 비교하면 CPU끼리, Conv2끼리는 각각 210개 확정 토큰이 전부 일치했다. 같은 평가 자료에서 결과를 재현한 것이며 일반적인 한국어 정확도 개선을 의미하지 않는다.

## 긴 음원과 후속 방향

Host에서 확인한 결합 경로의 자연발화 8개는 정답 2,129자 중 271자 오류(CER 12.73%)였고 입력 드롭·모델 실패는 0건이었다. 11월 23일 확인 시 RP5 SSH 연결이 키 교환 전에 재설정되어 자연발화 CPU·Conv2와 긴 낭독 4개의 대응 결과를 회수하지 못했다. 긴 음원 12개 전체의 개선 여부, 역순 재실행, 종료 반복 검증 및 장치·클럭 복원 상태는 이번 정리에서 미확인이다.

1. **긴 음원 대조를 먼저 끝낸다.** 기존 실행 상태와 산출물을 회수하고, 같은 확정 PCM의 CER·첫 표시·최신 반영 공백·확정 지연을 비교한다. 100개에서는 Conv2 단독의 오류가 가장 적었고 추가 투영의 확정 추론 이득은 0.63%였다. 정확도와 자막 반응성 모두 긴 자료에서 확인한 뒤 기본 경로 변경 여부를 결정한다.
2. **첫 자막을 위한 부분 요청 선택을 우선한다.** 확정만으로 첫 자막이 나온 구간의 제출 시각, 열에 따른 부분 요청 연기, 확정 작업과의 충돌을 점검한다. 5초 입력 결합 경로의 CPU 음성 prefill은 722ms, decode는 1,279ms로 두 단계가 전체 호출의 62.4%다. CPU 최적화도 이 두 단계에 집중한다.
3. **NPU 포팅 확대는 보류한다.** 두 HEF가 함께 동작할 때 투영의 동기 시간이 늘어나는 원인과 Conv2 입력·출력 재배열 비용이 다음 NPU 측 진단 대상이다. 18층 전체나 자동회귀 LLM을 Hailo-8L에 올리는 작업은 우선순위가 낮다.

구현은 `746272c`, Hailo 객체 해제 순서 수정은 `f0eca50`에 반영했다. 초기 빌드에서는 전사를 기록한 뒤 HailoRT 버퍼 소멸 중 간헐적으로 비정상 종료했다. 여기에 인용한 네 경로의 고정 PCM·100개 스트리밍은 수정본에서 정상 종료한 기록이다. 후속 자연발화 8개를 포함한 다섯 스트리밍의 Host 원시 파일을 저장된 SHA-256과 대조했다.

## 재현과 검증 범위

RP5에서 실험 드라이버와 펌웨어를 활성화하고 [선택 라이브러리 빌드](../../../native/README.md#hailo-8l-합성곱-실험-재현)를 마친 뒤 다음과 같이 기존 공통 평가기를 호출했다. `out`은 매번 새 실행 경로다. 장치 준비·정리, CPU 상한 임시 적용·복구와 앞서 설명한 시작 온도 확인은 평가기 바깥에서 수행했다.

```bash
sdk_run="$PWD/runtimes/qwen3-opt/hailo8l-q8-20261120-01"
preload="$PWD/runtimes/qwen3-opt/hailo-projection-20261120-02/hybrid.so"
out="results/optimization/opt3/새실행ID/fixed-both"
flock results/listener/inference.lock .venv/bin/python scripts/edge_asr.py tools thermal-run \
  --output "$out" --timeout-s 1800 --temperature-policy operational --skip-temperature-admission -- \
  env LD_PRELOAD="$preload" EDGE_ASR_HAILO_LAYER=a.conv2d.2.weight \
  EDGE_ASR_HAILO_HEF="$sdk_run/hef/conv2_linear.hef" \
  EDGE_ASR_HAILO_PROJECTION_HEF="$sdk_run/hef-extra/conv_out_row.hef" \
  .venv/bin/python scripts/edge_asr.py tools replay-qwen3 \
  --config configs/gguf_realtime.toml --manifest data/evaluation/edge100-20261109-01/manifest.jsonl \
  --vad-model models/silero-vad-k2-20261029/silero_vad.onnx --gap-s 0 --vad-threshold 0.3 \
  --vad-preprocess rms26-floor80 --vad-max-speech-s 5 --max-segment-s 5 --partial-mode continuous \
  --continuous-policy headroom --partial-after-s 0.6 --partial-min-new-s 1.0 --partial-tail-margin-s 0.2 \
  --partial-thermal-policy pace --cancel-partial-for-final --token-stream --drain-timeout-s 30 \
  --queue-capacity 4 --silence-policy skip-zero --output "$out"
```

4 GiB 주소 공간 제한과 운영체제 열 보호를 유지했다. CPU 기준은 preload 없이 실행하고, 단독 실험은 해당 HEF만 선택했다. 모델·HEF·ELF와 원시 전사·텐서는 로컬 실험 디렉터리에 보존한다.
