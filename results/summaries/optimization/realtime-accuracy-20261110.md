## 고정한 조건과 구현

Qwen3-ASR-0.6B GGUF Q8_0·2T·기존 `.venv`·같은 가중치/bridge·greedy·context512·출력128을 유지했습니다. 같은 Zeroth60·FLEURS40,891.1448125초·14,258,317프레임·정답3848자·같은 순서(manifest SHA `75ba1226dddfa0defb97f6fdbba89c31a762b541beb41299cdb0ac8490c45a06`)를 추가 무음0초·100ms·1배속으로 공급했습니다. 입력 도중에도 부분/최종 추론을 계속하며 파일 경계로 상태를 초기화하지 않았습니다.

모델1회 로딩·첫 추론1회·추가 워밍업3회·부분 첫1초/이후2초·문맥0·입력 큐10청크·최종 큐4개·대기 부분1개·EOF 배출30초·외부1800초·4GiB·온도 대기 없는 운영 정책도 유지했습니다. 두 전체 대조는 모든 ASR을 새로 실행했습니다.

기존 [AudioPreprocessor](../../../src/edge_asr/audio_policy.py)의 인과적 RMS 알고리즘을 재사용했습니다. VAD 입력만500ms 과거 창·목표 -26dBFS·최대24dB 증폭·상승0.3초·현재 블록 peak0.98 제한으로 처리하며 floor는 -80dBFS입니다. 원음이 작은 구간을 위한 실험값이며 표준 권장값이나 모든 마이크 조건의 검증값이 아닙니다. [SegmentPipeline](../../../src/edge_asr/segmentation.py)은 VAD 신호와 ASR 파형을 분리하고 각512프레임 창의 시간축을 유지합니다.

**ASR에 사용할 전체 처리 파형의 SHA는 기존 identity 원음과 같습니다.** VAD와 분할이 달라 실제 ASR 요청의 시작·끝은 달라졌습니다. 기존 세 전처리 정책·모델·패키지·원음·결과를 보존했으며 새 VAD 처리 기본값은 여전히 `identity`입니다.

## 진단과 짧은 대조

RP5의 전체 VAD 확률을 저장하고 기존214개 구간의 좌표·PCM을 정확히 재현했습니다.5초 이후 판정 강화가 적용된 종료는76회였습니다.9.55초의 `zeroth-137_003_2281`에서 전달된 부분은2.832초였고 뒤5.612초는 구간 밖이었습니다. 이것은 음향 정답 주석에 따른 누락률이 아닌 입력 전달 범위입니다.

미출력 `fleurs-14278025439467391857`은 최고 확률0.364였지만0.3을 넘는 창은2개로 시작 지속 조건을 통과하지 못했습니다. 저장 확률의 Host 재분류에서0.1/0.2만으로도 미출력은 남았습니다. 기본 RMS floor -60dBFS도 미출력을 해소하지 못했고 -80dBFS 진단은 최고 확률0.915·4.024초 방출을 관측했습니다. 이 단계는 VAD 실제 추론/재분류이며 ASR·지연 측정과 구분합니다.

길이별3개와 미출력·큰 악화·batch 무오류 사례를 합친 고유6개를 사전에 고정했습니다. 새 연결 맥락60.62375초·정답280자이며 manifest SHA는 `b9dabb0e87600d49c6b9d07184eee5170497db7dd1f15fe6a52f186583444b80`입니다. 후보 사이에서 한 항목씩 바꾸어 실제1배속 전사를 실행했습니다.
