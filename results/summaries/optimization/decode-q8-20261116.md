# Q8 GEMV 정수 누적 분리 선별

2026-11-16. **계산 결과와 전사는 유지했지만 반복되는 속도 개선은 확인하지 못했습니다.** Q8 행렬·벡터 곱의 정수 누적을 둘로 나눈 후보에서 후속/확정 decode 합계 감소는 두 교차 구간 각각 0.001%·0.414%였습니다. 사전 3% 기준에 미달해 운영 기본에 적용하거나 연속 평가로 확대하지 않았습니다. [전체 JSON](decode-q8-20261116.json), [사전 조건](../../../docs/research/qwen_realtime.md#q8-gemv-정수-누적-분리--2026-11-16-사전-조건).

## 바꾼 부분

고정 upstream `7d7f028`의 Q8 4x4 GEMV는 이미 ARM NEON·DOTPROD를 사용합니다. 원래 소스와 RP5 바이너리에서 8개의 정수 dot이 같은 누적값을 차례로 갱신하는 것을 확인했습니다. [후보 코드](../../../native/gguf/q8_gemv.cpp)는 앞/뒤 4개를 두 int32 누적값으로 계산하고 float 변환 전에 합칩니다. 블록별 scale·float FMA 순서·가중치 배치·양자화는 유지합니다. 후보 disassembly에서도 두 누적 레지스터와 정수 합산을 확인했습니다. 이는 계산 경로의 확인이며 속도 개선을 보장하지 않습니다. 근거는 [고정 upstream 구현](https://github.com/ggml-org/llama.cpp/blob/7d7f0287530bc8981690f361d8c1627dbae1c99a/ggml/src/ggml-cpu/arch/arm/repack.cpp#L1771)과 [ARM intrinsic 정의](https://arm-software.github.io/acle/neon_intrinsics/advsimd.html)입니다.

운영 엔진을 덮어쓰지 않고 `runtimes/qwen3-opt/decode-q8-20261116-02/libedge_q8_gemv.so`를 별도 빌드했습니다. 원래 `-O3`·Cortex-A76 ISA 조건을 사용하며 실제 실험 자식에만 preload했습니다. 끔은 원래 함수로 전달하고 켬은 후보로 계산합니다. 해당 심볼의 모든 GEMV에 적용되므로 token decode 전용 변경이 아니며 다른 단계의 잔여 행에도 영향을 줄 수 있습니다. GEMM은 변경하지 않았습니다.

## 검증과 측정 조건

RP5 합성 packed 입력 **72조건**에서 원래/후보의 float 출력 비트와 출력 버퍼 경계가 모두 일치했습니다. 폭 32·64·128·896·1024·3072, 출력 열 4·12·256·19000에 임의값·0·int8 극값을 조합했습니다. 이는 실제 ARM 커널의 수치 검사이며 ASR 성능 측정은 아닙니다.

이후 소스 `425ec05bdf1b538c04b44e41d84cc03b02d074a1`, 실행 `decode-q8-20261116-02`에서 기존 [재프로파일링](reprofile-q8-20261116.md)의 최초 0.612초·후속 2.276초·확정 4.504초 PCM을 그대로 사용했습니다. Q8 text/audio·생성2T/음성·prefill3T·prefix KV·기존 bridge/엔진·최대 생성 길이를 고정했습니다.

공통 `qwen/benchmark.py` reproduction으로 12라운드×3개=36호출을 실행했습니다. 모델은 한 번 로딩하고 1~4라운드는 준비, 5~8은 **끔/켬/켬/끔**, 9~12는 **켬/끔/끔/켬**입니다. 모든 호출 사이에는 측정 타이머 밖의 같은 2초 휴지를 두었습니다. 이는 연속 입력의 갱신 간격이 아닙니다.

## 실제 고정 PCM 결과

아래는 준비 후 각 PCM·조건별 4회 평균입니다. 첫 4자 표시·음원 종료 뒤 반환 지연과 다른 **호출 내부 native 시간**입니다.

| PCM | 전체 호출 끔→켬 | decode 끔→켬 |
| --- | ---: | ---: |
| 최초 0.612초 | 398.164→398.969ms | 55.830→55.154ms |
| 후속 2.276초 | 1667.864→1667.545ms | 835.312→836.021ms |
| 확정 4.504초 | 3229.543→3225.799ms | 1900.341→1893.940ms |

| 교차 구간 | 후속/확정 decode 합계 감소 | 전체 native 합계 감소 | 최초 전체 비용 증가 |
| --- | ---: | ---: | ---: |
| 5~8라운드 | 0.001% | −0.164% — 증가 | +0.834% |
| 9~12라운드 | 0.414% | 0.286% | −0.429% — 감소 |

두 구간 모두 decode 3%·전체 native 1% 감소 기준에 미달했습니다. 최초 비용 증가 5% 이내 조건은 통과했습니다. 미세한 차이를 통계적 우열이나 일반적인 효과 0으로 해석하지 않습니다.

실제 36호출 모두 성공했고 보존 PCM별 전사·token ID가 같았습니다. 측정 라운드의 조건별 총 GEMV 호출 수는 최초 25,024·후속 131,808·확정 226,752로 끔/켬이 같습니다. 끔에서는 전부 원래 함수로 전달됐고 켬에서는 전부 후보가 실행됐습니다. 후보가 선택되지 않아서 변화가 작았던 경우는 아닙니다.

## 온도·오류·보존

실제 모델 평가의 시작/최고/종료 온도는 **59.50/73.80/72.15°C**, 관측 현재 제한 플래그는 **0**이었습니다. 측정 호출의 최고 RSS는 양쪽 모두 1659.20MiB였습니다. 장비 잠금·600초/4GiB operational guard·시작 온도 대기 생략·기본 열 보호를 유지했습니다. 고정 휴지와 작은 표본의 결과이며 장시간 연속 열 상태를 대표하지 않습니다.

최초 `decode-q8-20261116-01`은 upstream 헤더의 미사용 static 함수 경고를 오류로 처리해 빌드 단계에서 실패했습니다. 합성 검사나 모델 추론은 시작하지 않았습니다. 원래 엔진이 쓰는 `-Wno-unused-function`을 맞춘 새 빌드/실행 ID `-02`로 다시 진행했고 `-01`의 실패·빌드 영수증·자산 불변 기록은 보존했습니다.

Host 전체 433개 중 430개 통과·선택 native 검사 3개 생략, 새 ELF 모의 검사·CI 범위 Ruff·공유 설정·M1 원본 해시를 확인한 뒤 main commit/push→RP5 동기화→별도 빌드/검사를 진행했습니다. 첫 Ruff 명령은 보존 실험까지 검사해 기존 경고를 발견했으며 해당 원본을 고치지 않고 CI 범위 `src tests scripts native`로 확인했습니다. Host 모의 검사와 RP5의 합성 커널 검사·실제 ASR 추론을 구분합니다.

보호 **890파일** 전후 불변·새 원시 **24파일** Host/RP5 해시 일치·분석 JSON 독립 byte 일치·동일 부팅을 확인했습니다. 문서 정리 뒤 구조/링크 검사 6개도 통과했습니다. 기존 측정 웹의 61기록/23프로필과 유휴 상태를 유지했습니다. 이 고정 PCM 진단을 새 연속 청취 결과로 등록하지 않았으며 새 CER·연속 표시/마이크 지연은 미측정입니다.

## 판단과 다음 단계

이번 결과는 **정수 누적 의존성 하나를 줄이는 것만으로는 현재 Q8 decode를 충분히 가속하지 못했다**는 선별 결과입니다. 가중치 로드·캐시·메모리 대역폭·작업 분할 중 어느 것이 지배적인지는 아직 직접 계측하지 않았으므로 특정 원인으로 단정하지 않습니다.

다음은 새 커널 변형을 더 만들기 전에 출력층과 나머지 행렬의 **CPU/캐시 계측 및 작업 분할**을 구분하는 것입니다. RP5에는 Cortex-A76 PMU 장치가 있으나 `perf` 실행 파일은 없고 `perf_event_paranoid=2`였습니다. 실제 프로세스에서 사용 가능한 계측 권한/방법부터 확인하며 기존 패키지는 변경하지 않았습니다. 이후 유효한 후보만 동일 PCM→연속 입력 순으로 검증합니다. encoder는 그 다음 순위로 유지합니다.

공유 Q8 설정·기존 모델·운영 엔진은 그대로입니다. 실험 코드는 재현용으로 보존하고 원시/빌드는 각각 `results/optimization/opt3/decode-q8-20261116-02/`, `runtimes/qwen3-opt/decode-q8-20261116-02/`, 수치 검사/독립 분석/해시는 같은 ID의 `results/maintenance/`에 둡니다.
