## 구현 범위

소스 `e9656cc`의 기존 어댑터·bridge·연속 실행기를 확장했습니다. 새 bridge는 `runtimes/qwen3-opt/prefix-20261112-01/bridge/`에 빌드했고 기존 고정 엔진6개·Q8 text/audio·Python 환경은 유지했습니다. 기존5/6인자 생성 ABI1을 보존하고 선택 setter·기능 `text_prefix_cache_v1`을 추가했습니다. 항목 생략 시 기본은 끔이며 기존 빌드도 계속 사용합니다.

실제 tokenization에서 음성 앞 prefix는9토큰이었습니다. token ID·위치가 일치하면 그 prefix 이후 sequence를 제거하고, 오디오·뒤쪽9 text 토큰·이전 생성 결과를 다시 계산합니다. 오디오 embedding이나 이전 전사를 캐시한 것이 아닙니다. `prefix_cache.h`가 일치/실패 상태를 관리하며 prefix 변경·제거 실패·호출 실패 시 전체 초기화로 복귀합니다. 요청·실제 캐시 상태·단계 시간은 Python에서도 검사하고 오류 원시를 보존합니다. [native 구현](../../../native/gguf/bridge.cpp), [상태 정책](../../../native/gguf/prefix_cache.h), [어댑터](../../../src/edge_asr/qwen/gguf.py).

앞/뒤 text 평가·`mtmd_encode_chunk`·음성 embedding의 LLM 평가를 구분해 계측했습니다. 같은 upstream chunk 순서와 평가 함수를 사용하며 기존 `audio_and_prefill_s`도 보존합니다. 새 빌드의 항목 생략6개 실행에서 이전2/3의 최종15구간·전사·토큰 ID가 같음을 먼저 확인했습니다. 과거 다른 빌드의 시간을 이번 캐시 끔 대조로 대신하지 않았습니다.
