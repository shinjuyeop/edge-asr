# P8 부분 전사 스케줄링 실험

2026-11-25 · Raspberry Pi 5 8GB · Qwen3-ASR-0.6B Q8 GGUF · Hailo-8L Conv1·2·3/GELU

부분 전사 후보는 고정 100개와 독립 자유대화에서 P8의 확정 PCM·토큰과 CER를 지켰다. 고정 100개에서 새 본문 없는 부분의 계산 시간은 당일 P8 대비 35.7% 줄었다. 첫 본문과 최신 갱신 공백은 목표에 미달했고, 약 30분 부하에서는 부분 요청 증가로 전체 추론이 10.7% 늘었다. T와 P8을 주 청취 구성으로 유지하고 후보는 비교용으로 보존한다.

## 기존 요청이 지연된 이유

고정 100개에서 T의 226개 확정 구간과 P8의 158개 확정 구간을 전수 조사했다. P8의 첫 본문 p95 사례 `zeroth-149_003_0057`에서 원음 시작부터 요청을 제출하기까지 7.728초, 제출 후 워커 대기 0.003초, 추론 시작 후 첫 본문까지 1.693초였다. P8은 29개 원음에서 확정 호출이 첫 본문을 표시했다. [기존 경계 대조](boundary-20261124.md) · [이전 지연 분석](batch-litert-20261125.md)

대기는 구간별로 합산했다. P8에서 이전 확정과 0.1초를 넘게 겹친 구간은 136개, 이전 부분은 5개, 열 보류는 27개, 확정 임박 보류는 8개였다. 워커 점유와 열 보류는 시간상 겹칠 수 있다. 표시를 생략한 접두부 토큰의 첫 토큰부터 마지막 토큰까지의 합은 T 55.39초, P8 77.38초였다. 이는 콜백 시각 범위다. 취소 호출에 든 시간은 새 본문을 이미 낸 호출까지 포함한다. 저장된 WAV에서 T 175건과 P8 184건의 부분 입력 float32 해시를 재현했다.

## 후보가 결정하는 방식

1. 워커가 유휴이고 확정 큐가 비면 현재 음성 범위에서 첫 본문을 우선한다. PCM이 쌓여 첫 요청이 늦었을 때는 기존 P8c에서 시험한 1.2초 상한을 적용한다. 최근 실제 호출의 음성 단계와 첫 본문까지 걸린 시간으로 비용을 갱신한다. 취소됐어도 첫 본문이 표시됐다면 비용 산정에 쓸 수 있다.
2. 후속 요청은 이전 표시보다 PCM 끝이 전진하고 문자·숫자 본문도 달라졌을 때만 최신 반영 시각을 갱신한다. 이후 쌓인 음성량을 이미 보인 접두부의 재생 예상 시간과 비교한다. 예상 공백이 사용자 목표인 4초에 닿으면 음성량 기준에 못 미쳐도 후속을 검토한다. 동일 PCM의 후속 토큰·순수 삭제·구두점은 새 음성으로 세지 않는다.
3. 본문이 있는 구간에서는 저확률 VAD 창이 96ms 연속되면 후속을 쉼이 끝날 때까지 보류한다. 구간 상한까지 남은 여유 및 82°C 이후의 기존 열 기반 간격 조정, 90/85°C 보류·복귀 조건을 적용한다. 대기 부분 PCM은 하나이며 실행 전에 최신 범위로 교체한다. 확정은 기존 유한 FIFO가 먼저 처리하고 진행 중인 부분은 토큰 콜백에서 취소 가능하다.

부분 요청에만 적용되는 선택 프로필이다. 비교한 후보는 기존 P8c의 1.2초 첫 입력·1.0초 후속 최소 새 음성과, 비용·표시 상태를 함께 보는 정책 두 가지다. P8c의 이전 6개 파일럿에서 갱신 공백 p95는 5.03→4.67초였고 확정 26개가 같았다. 별도의 표시 후 대기는 당시 D8 조건에 해당한다. [P8c와 D8 기록](boundary-20261124.md) · [후보 프로필](../../../configs/listener_hailo_partial_budget.toml)

## 실험 조건

- 원래 냉각 구성과 펌웨어 열 보호에서 1.5GHz 상한을 걸고 CPU 온도가 73.5°C 이하인 2초 간격의 표본 3개가 모일 때 시작했다. 로딩·워밍업 뒤 첫 1배속 입력 온도를 별도로 기록했다. RP5 추론 잠금으로 동시에 한 실행만 돌렸다.
- 실행별 동일 16kHz PCM과 공급 순서, 0초 연결 간격, Q8 GGUF와 CNN HEF, 생성 2·음성/Prefill 4스레드, P8 VAD와 최대 8초 경계를 사용했다. 확정 PCM 시간 범위·float32 SHA-256, 확정 원문·토큰열·`ko_cer_v1`을 비교했다.
- 1단계는 알려진 난례 3개와 FLEURS·Zeroth의 출처 및 8초 이하·초과 조합에서 해시 순서로 3개씩 뽑은 15개다. 2단계는 기존 목록의 서울 자연발화 두 개와 연속 낭독 한 개다. 고정 100개는 개발·회귀 자료다.
- 파일럿의 첫 P8과 P8c는 시작 커밋 `5d328c0`에서 실행했다. 후보와 P8 복귀 대조, 연속 입력 및 독립 대조의 소스는 `41e2177`이다.
- 서버 발행 시각을 측정했다. 첫 본문과 4글자는 공통 원음 시작 기준이고 확정은 공통 원음 끝 기준이다. 최신 갱신 공백은 요청이 담당한 음성 끝과 실제 본문이 모두 전진할 때만 계산한다. 발음 끝 → 표시는 서울 자연발화의 원래 단어 주석에 정확히 대응한 본문을 두 실행에서 공통으로 비교한다.

## 독립 자유대화 검증

## 재현 방법

입력 순서·원음 해시와 전체 수치는 [측정 요약 JSON](partial-scheduling-20261125.json)에 있다. 동일 Hailo 자산과 장치 세션, 다시 쓰지 않은 새 출력 ID, 1.5GHz와 같은 시작 온도를 사용한다. 아래 코드는 장치 세션 안에서 기존 프로필을 동일 `replay-qwen3` 인수로 해석하는 방법이다. 실행 뒤 원래 클럭 상한을 복원한다. [Hailo 장치 준비와 잠금](../../../docs/guides/listener.md) · [공통 평가 절차](../../../docs/guides/qwen3_optimization.md)

```bash
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 .venv/bin/python - \
  configs/listener_hailo_partial_budget.toml \
  data/evaluation/edge100-20261109-01/manifest.jsonl \
  results/optimization/opt3/my-partial-budget <<'PY'
import subprocess
import sys
import tomllib
from pathlib import Path

from edge_asr.qwen.viewer.runs import hailo_worker_prefix, replay_args

profile_path, manifest, output = map(Path, sys.argv[1:])
profile = tomllib.loads(profile_path.read_text())
root = Path.cwd()
cli = [sys.executable, "scripts/edge_asr.py", "tools"]
subprocess.run([
    *cli, "thermal-run", "--output", str(output), "--timeout-s", "2100",
    "--temperature-policy", "operational", "--skip-temperature-admission", "--",
    *hailo_worker_prefix(root, profile), *cli, "replay-qwen3",
    *replay_args(root, profile, output, manifest),
], check=True)
PY
```

P8은 `configs/listener_hailo_boundary.toml`, T는 `configs/listener_hailo_continuity.toml`을 선택한다. P8c는 P8 프로필 뒤에 `--first-snapshot-cap-s 1.2 --partial-min-new-s 1.0`을 `replay-qwen3` 인수로 추가한다. 결과는 `tools subtitle-metrics --run <출력 폴더> --boundary-errors --output <요약 JSON>`으로 재집계한다. 서울 자연발화는 `--seoul-manifest data/evaluation/longform-20261117-01/natural.jsonl`을 추가한다.

## 채택 판단과 다음 병목

후보는 재현 가능한 비교 프로필로 보존한다. 낮은 첫 지연이 중요하면 T, 높은 경계 정확도가 중요하면 P8을 사용한다. 고정 100개에서 후보는 첫 본문 p95 4~5초와 최신 갱신 공백 p95 4초 목표에 미달했다. 서울 자연발화의 같은 주석 단어는 일부 늦게 표시됐고, 30분 부하에서는 계산 시간이 늘었다. P8c는 파일럿에서 첫 표시가 소폭 빨랐으나 새 본문 없는 비용이 커져 확대하지 않았다.

우선 고정된 P8 확정 PCM과 토큰열을 이용해 Q8 Decode, 그다음 오디오 Prefill의 점유를 줄이는 쪽을 검증한다. 부분 단계만 줄여서는 기존 확정이 워커를 비울 때까지 지연되는 꼬리를 줄이기 어렵다. 먼저 동일 PCM의 단계별 실측과 토큰 동등성을 확인한 뒤 1배속에서 첫 본문·단어 반영·확정이 함께 개선되는지 본다. 새 경계 복구는 기존 P8이 남긴 경계 오류를 줄이는 별도의 정확도 과제로 남겨 둔다.
