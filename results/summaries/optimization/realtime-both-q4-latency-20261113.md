# Q4 지연 경로 분석

2026-11-13. **양쪽 Q4는 첫 글자 이후 token decode를 줄였지만, 첫 요청용 음성 수집과 audio/prefill을 줄이지 못했습니다.** 첫 표시의 병목은 약1초 입력 대기와 약0.62초의 첫 token 준비이며, 최종 반환에는 직렬 모델 호출 대기도 남습니다. [집계 JSON](realtime-both-q4-latency-20261113.json), [원래 Q8/Q4/Q8 대조](realtime-both-q4-20261113.md).

## 범위

새 모델 추론 없이 기존 `realtime-both-q4-20261113-01`의 소스 `b5c500f` RP5 실제 기록을 재집계했습니다. 같은6개·60.62375초·첫 부분 요청6개·최종15호출과 전체30/32/28호출을 구분합니다. Q4는 text Q4_K_M/audio Q4_0, 앞뒤 Q8은 text/audio Q8_0입니다. 기존 원시50파일 해시가 같고 Host/RP5 독립 집계가 byte 단위로 일치합니다.

`published_s`는 RP5 이벤트 발행 기준입니다. GUI/SSH 전달 지연과 음향 정답 시작/끝은 미측정입니다. VAD가 소유한 구간 시작·끝은 음향 정답 경계가 아니며, 아래 차이를 실제 단어 인식 지연으로 부르지 않습니다. 서로 다른 집단의 p95를 더하지 않고 한 호출의 시계로 지연 합계를 검산했습니다.

모델 준비는 재생 중 지연과 별도입니다. Q4의 관측 로딩은1.398초, 준비용 첫 추론2.275초·추가 워밍업3회 합계6.724초였습니다. 합계약10.397초는 해당 계측 부분만 더한 값이며 자산 해시·입력 준비·웹/SSH 처리를 포함한 준비 버튼의 전체 시간이 아닙니다. 이미 자산을 해시한 뒤 로딩한 기록으로, 저장장치의 완전한 cold start도 아닙니다. 아래 첫 표시 시간에는 이 준비가 포함되지 않습니다.

## 첫 자막까지

첫 표시가 가장 늦은 `fleurs-14941719265693149665`는 Q4에서4.186초였습니다. 이 수치를 모두 모델 계산 지연으로 해석하면 안 됩니다.

| 같은 사례의 시간 성분 | Q4 |
| --- | ---: |
| 파일 시작→VAD 소유 구간 시작 | 2.464초 |
| 첫 요청에 모은 실제 PCM | 1.028초 |
| PCM 끝→요청 제출 —입력 전달·VAD 처리·스케줄 | 0.079558초 |
| 제출→모델 호출 시작 | 0.000456초 |
| native 호출 시작→첫 생성 token | 0.613820초 |
| 첫 생성 token→첫 비어 있지 않은 이벤트 발행 | 0.000259초 |
| 합계 | **4.186155초** |

앞2.464초는 파일에서 VAD 소유 구간이 시작하기 전 위치 차이입니다. 무음 또는 VAD 검출 지연 중 어느 쪽인지 음향 라벨 없이 분리하지 않습니다. 이 사례의 **VAD 소유 구간 시작→첫 표시**는1.722초이며6개의 Q4 평균은1.691초입니다. 파일 시작 기준 지표도 기존대로 유지하며, 새 정의로 이전4.19초를 대체하지 않습니다.

첫 요청6개는 모두 같은1.028초 PCM이며 첫 token부터 표시됐습니다. `partial_after_s=1`이므로 Q4로 가중치를 줄여도 이 입력 수집 대기는 그대로입니다. 첫/4자 표시 사이에 더 생성하거나 다음 요청을 기다리는 시간도 있어 첫 token 속도만으로4자 표시를 보장하지 않습니다.

| 첫 요청6개의 평균 —같은 PCM | 앞 Q8 | Q4/Q4 | 뒤 Q8 |
| --- | ---: | ---: | ---: |
| audio encoder | 0.314초 | 0.317초 | 0.317초 |
| LLM 음성 embedding prefill | 0.164초 | **0.206초** | 0.169초 |
| audio 뒤 공통 text prompt 평가 | 0.093초 | 0.093초 | 0.097초 |
| 호출 시작→첫 생성 token —위 단계 포함 | 0.572초 | **0.616초** | 0.584초 |
| 첫 요청의 모델 큐 대기 | 0.26ms | 0.34ms | 6.35ms |

**Q4의 decode 가속은 첫 token이 준비된 뒤에 주로 적용됩니다.** bridge는 audio encode→embedding prefill→text suffix 평가를 끝낸 뒤 첫 token을 뽑고, 이후 token을 생성할 때 `token_decode_s`를 누적합니다. 첫 요청에서 encoder는 거의 같고 embedding prefill이 약37~41ms 늘어 첫 표시 개선이 없었습니다. 공통 prompt suffix도약93ms가 남습니다.

## 최종·연속 갱신의 계산 비용

같은 최종15구간의 좌표/PCM은 같지만 Q4의 전사·token 수가 달라 순수 커널 속도 대조는 아닙니다.

| 최종15호출 합계 | 앞 Q8 | Q4/Q4 | 뒤 Q8 |
| --- | ---: | ---: | ---: |
| audio encoder | 8.450초 | 8.665초 | 8.591초 |
| LLM 음성 embedding prefill | 4.329초 | **5.754초** | 4.439초 |
| 공통 text suffix 평가 | 1.456초 | 1.470초 | 1.525초 |
| token decode | 13.642초 | **9.605초** | 14.009초 |
| 전체 추론 | 28.200초 | 25.759초 | 28.864초 |

Q4에서 encoder33.64%·embedding prefill22.34%·text suffix5.71%·decode37.29%입니다. encoder+embedding만 합쳐도55.98%라 decode 가속만으로 첫 응답이나 전체 지연이 크게 줄지는 않습니다. Q4의 embedding prefill은 앞뒤 Q8보다약30~33% 길었습니다. 연산자별 프로파일이 없으므로 dequant·행렬 커널·메모리 대역폭 중 무엇이 원인인지는 확정하지 않습니다. Q4/뒤 Q8에 열 제한도 관측됐습니다.

Q4의 부분17호출은17.163초로 전체42.922초의약40.0%입니다. 최종만의25.759초와 구분해야 합니다. 부분/최종 모두 audio encoder와 embedding prefill을 다시 수행하며, 현재 KV 재사용은 음성 앞 고정 text9토큰에 한정됩니다. 후속 요청 수가 앞Q8의5회·뒤Q8의3회에서 Q4의7회로 달라져 전체 합계는 앞보다작고 뒤보다큽니다. 연속 갱신에서는 추가 재전사 비용도 관찰해야 합니다.

## 최종 결과의 큐·종료 대기

Q4의 최종15호출 모델 큐 대기는 평균0.494초·p50 0.192초·p95 2.027초였습니다. 가장 오래 기다린 job11은0.248초 PCM을 처리하는 데0.452초가 걸렸지만 앞선 final job10이 아직 실행 중이어서2.027초를 먼저 기다렸습니다. 앞 job10은4.024초 PCM을2.617초에 처리했습니다. 이 사례는 부분 요청이 아닌 **앞선 최종 호출**이 막은 것입니다.

동일 job11의 구간 끝→제출0.350초 +큐2.027초 +추론0.452초 +발행 잔여 약0.00007초 =구간 끝→최종 발행2.829초입니다. 현재 worker는 모델 하나를 직렬 호출하고, 이미 실행 중인 호출은 중단하지 않습니다. 최종 우선순위가 있어도 실행 중 호출은 기다립니다.

VAD 소유 구간 끝→제출의 Q4 p50/p95는0.323/0.392초입니다. 종료 판단·100ms 입력 전달·스케줄이 섞여 있고 실제 발화 끝 기준은 아닙니다. **최종15구간 끝→발행 p95는3.065초**, 기존 **원음6개 파일 끝→최종 발행 p95는1.780초**로 집단과 기준이 다릅니다. 이번 분석은 기존1.780초를 수정한 것이 아닙니다.

반대로607개 입력 청크의 수집 큐 대기는 평균0.813ms·p95 1.384ms·최대4.975ms, 최대 오디오 백로그0.1초였고 드롭0입니다. 초 단위 최종 모델 큐와 입력 수집 큐를 혼동하지 않습니다.

## KV·전처리·출력과 다음 검토

고정 text prefix KV는 Q4의32/32호출에서 적중했습니다. prefix 재평가 합계는0초, KV 정리 합계는0.000680초, native 전처리는0.014156초, token callback 합계는0.116277초입니다. 이 계측 범위는 큰 병목이 아닙니다. 가중치 Q4와 KV 양자화는 별개이며 현재 K/V는F16입니다. 음성 KV 재사용·KV dtype 비교·GUI/네트워크 전달 최적화를 이번에 측정한 것은 아닙니다.
