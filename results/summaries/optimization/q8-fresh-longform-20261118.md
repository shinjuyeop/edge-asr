# Q8 긴 음원 1배속 가변 갱신

Q8에서 말하는 동안 새 음성을 빨리 반영하도록 첫 부분 요청을 0.6초부터 허용하고, 작업자가 빌 때 최신 범위로 갱신하는 청취 프로필을 추가했다. 긴 음원 12개에서 고정과 가변의 최종 CER는 모두 **12.03%(384/3,192자)**였고, 233구간의 경계·PCM·상태·확정 전사·토큰 ID가 전부 같았다. 양쪽 모두 입력 드롭과 모델 실패는 0건이었다. | 자료 | 방식 | 최근 1초에 새 음성을 반영한 표시가 있었던 시간 | 표시가 1초 이내 음성까지 반영한 시간 | 2초 이상 구간별 최신 반영 최대 공백 p50 / p95 | 2초 이상 중 종료 전 부분 표시 | 철회한 문자 수 |

| 자연발화 | 가변 | 16.8% | 5.6% | 2.51 / 5.00 | 53/77 | 86 |

발화 중 지난 1초 안에 같은 구간의 새 음성으로 자막이 갱신된 시간 비율은 가변에서 자연발화 16.8%, 낭독 25.6%였다. 반면 자연발화에서 2초 이상인 구간 중 발화가 끝나기 전에 부분 자막이 보인 구간은 65/77→53/77로 줄었다. 5초 구간 7개는 작업자가 빌 때 이미 입력이 2.7~4.2초까지 들어왔고, 남은 시간에 부분 추론을 완료하기 어렵다고 판단해 첫 부분 표시 없이 확정으로 넘어갔다. 같은 호출의 토큰이 빠르게 보이는 정도와 매초 새 음성이 반영되는 정도는 다르다.

## 자연발화의 추가 대조

가변에서 작업자가 늦게 빈 긴 구간 7개를 확인한 뒤, 더 공격적인 요청으로 놓친 첫 표시를 회복할 수 있는지 자연발화만 다시 재생했다. 우선 `latest` 모드에 1.4초 끝 여백을 적용한 실행 01은 기존 입력 검증의 최대 0.5초를 넘어 워밍업 후 재생 전에 종료됐다. 이 실행에는 평가 CER와 지연이 없다. 새 ID `q8-fresh-reserve-20261118-02`로 `continuous_policy=latest`, `partial_tail_margin_s=0.5`를 적용했다. 새 후보·열 조절·첫 0.6초·새 음성 1초·확정 우선은 같은 조건이다.

과거 비용에 따른 확정 여유를 고정 0.5초로 바꾸면, 자연발화 최신 음성 반영 공백 p95는 고정 4.59초·비용 기반 가변 4.52초에서 **4.21초**로 줄었다. 반면 가장 긴 공백은 5.41초였고 첫 표시 p95는 **8.63초**, 확정 p95는 **4.60초**였다. 2초 이상 구간 중 종료 전에 부분 표시가 있었던 수는 47/77로 줄었고, 부분 138회 중 77회가 취소됐다. CPU 66.9%, 추론 448.06초, 입력 중 열 제한 399.5초였다. 167개 확정 PCM·전사·토큰 일치와 입력 드롭 0건을 확인했으나, 첫 표시·확정 대기·열 부담이 늘어 낭독으로 확대하지 않았다. 지원되지 않은 실행의 원시와 재측정 원시 13파일을 각각 보존했다.

## 실행 조건과 판정 기준

소스 `6af9cb6`의 RP5(Cortex-A76 4코어, RAM 8GB)에서 고정과 가변을 각각 자연발화 8개 467.428초, 연결 낭독 4개 265.229초에 실행했다. 순서는 자연발화 가변→고정, 낭독 고정→가변이었다. 각 자료 안에서 파일 사이 추가 무음 없이 100ms씩 1배속으로 음성을 공급했다. 같은 공유 Q8 모델·bridge·고정 접두부 KV·생성 2스레드·음성/prefill 3스레드·토큰 표시·5초 VAD/ASR 상한과 같은 채점기를 사용했다. 파일 앞 최대 5초로 최초 추론 및 추가 워밍업 3회 후 측정했고, 고정 냉각과 운영 열 정책·60°C 시작 기준을 적용했다. [모델 설정](../../../configs/gguf_realtime.toml) · [음원 구성](../../../docs/research/longform.md)

고정은 첫 1초·후속 간격 4초다. 가변은 첫 후보에 0.6초, 후속에 새 음성 1초를 요구한다. 기존 연속 처리기가 대기 후보 하나를 최신 범위로 교체하고 작업자가 빌 때만 음성을 읽는다. 최근 부분 추론의 길이와 시간을 기존 비용 추정기에 넣고, 예상 추론 시간과 0.2초 여백을 더해 5초 경계까지 들어갈 때만 실행한다. 이력이 없으면 새 음성 1초를 비용 대신 사용한다. 열 상태에 따라 후속에 필요한 새 음성을 최대 1.4초로 늘린다. 먼저 발화가 끝나서 확정이 대기하면 실행 중인 부분 추론은 다음 토큰 경계에서 취소할 수 있다. 이미 소비한 계산도 총량에 포함한다. `partial_interval_s`는 고정 모드에서만 쓰며, 가변의 1초는 최소 새 음성 길이다. [가변 프로필](../../../configs/listener_q8_headroom.toml) · [스케줄러](../../../src/edge_asr/qwen/realtime/continuous.py)

- 첫 표시와 첫 4자는 원음 시작부터 해당 파일에만 귀속할 수 있는 첫 서버 표시까지의 시간이다. 자연발화 8개·낭독 4개의 파일 p95는 각각 가장 늦은 파일이다. 물리 화면 시각과 음향 단어별 지연은 측정하지 않았다.
- **최신 음성 반영**은 표시할 문자열이 바뀌고, 그 호출이 받은 마지막 음성 프레임이 이전에 표시된 최댓값을 넘어선 경우다. 같은 음성의 추가 토큰이나 같은 글자 재발행은 제외한다. 전체 트랙의 갱신 사이 벽시계 간격은 시작·끝과 내부 쉼을 포함한다.
- **발화 중 1초 지표**는 VAD가 해당 ASR 구간에 배정한 시간만 분모로 삼는다. 같은 구간에서 최신 음성을 반영한 표시가 나온 뒤 1초 안에 해당하는 시간을 합쳤다. 별도로, 그 표시에 실제 사용된 음성 끝이 현재 입력 시각에서 1초 이내인 시간도 합쳤다. 구간 첫 표시 전의 시간은 분모에 남는다. 길이 2초 이상인 구간의 최대 공백에는 구간 시작과 종료도 넣었다. 두 지표 모두 부분 자막의 정확도나 단어별 정답을 재지는 않는다.
- 확정 지연은 같은 성공 구간의 소유 음성 끝에서 확정 결과 발행까지다. 전체 입력 끝→배출 완료 시간에는 마지막 대기를 포함한다. CER는 자료별 배포 정답 전체에서 계산하고, 합계에는 오류 수와 정답 문자 수를 더한다.
- 총 추론 시간은 부분·확정·취소의 경과시간 합이다. CPU는 재생 및 생산자 CPU초를 4코어와 재생 경과시간으로 나눈 값이다. 펌웨어 현재 제한 시간은 입력 중 약 1초 간격 표본에서 근사했다. 각 조건은 자료별 한 번씩 측정했다.

## 검증

Host에서 고정 native 헤더로 477개 테스트, Ruff 검사와 서식, M1 보존 해시 및 모델 설정 검사를 통과했다. RP5에서 연속 처리 테스트 15개를 통과했고 양쪽에서 기존 긴 음원 자산 69개를 검증했다. 실행 ID는 `q8-fresh-longform-20261118-01`이다. 네 조건의 원시 파일 49개 SHA-256이 Host/RP5에서 일치했다. 100ms 청크마다 예정 시각과 마지막 음성 프레임을 대조하고, 정답 manifest와 전체 확정 이벤트로 별도의 편집거리 계산을 검산했다. 1초 발화 지표는 같은 이벤트를 10ms 시간 격자로 다시 계산해 연속시간 계산과 0.15%p 이내에서 일치했다. RP5 청취 서버와 개발 PC의 SSH 전달을 통해 기록 5개의 자막 이벤트·점수와 WAV 프레임 수·재생 PCM 해시도 대조했다. 실제 화면과 사람의 청취 평가는 진행하지 않았다. 마이크→화면 지연, 부분 전사의 단어별 정확도, 더 긴 부하는 이번 실측 범위 밖이다.
