# Q4 부분 음성 창·KV 캐시 — 2026-11-18

완료 음성 창과 음성 KV를 재사용하는 선택 스트리밍 경로를 구현했습니다. 같은100개에서 갱신 공백 중앙값은 **3.419→2.612초(23.6% 감소)**, CER는12.42%로 같았습니다. 그러나 최종 반환 p95는 **1.830→2.339초**, 전체 추론은 **599.95→777.49초(29.6% 증가)**여서 기본 전환 기준에는 미달했습니다. 기존 Q4 최대3회와 공유 Q8은 유지하며 새1.99초 창은 청취 가능한 실험 프로필로 제공합니다.

## 구현과 적용 범위

기존 Q4_0 text/output·Q8 audio·KleidiAI OFF·생성2T/음성·prefill3T·고정9토큰 text prefix KV를 유지했습니다. 별도 bridge의 **부분 요청**에 독립 음성 창을 적용하고, 완료 창의 embedding과 해당 LLM KV를 재사용합니다. 새 입력은 꼬리 창부터 인코딩하고 LLM은 바뀐 음성 이후를 다시 계산합니다. 확정·일반 batch 호출은 원래 전체 음성 경로입니다.

`qwen/audio_windows.py`가 요청별 활성화를 담당하고, 기존 worker의 부분/확정 구분·구간 초기화·실패 처리를 재사용합니다. `native/gguf/audio_window_cache.h`는 완료 PCM을 바이트 비교하며, 변경/축소/구간 이동/오류/취소/확정 뒤에 초기화합니다. 20ms 미만 꼬리는 앞 창과 함께 계산하여 음성을 버리지 않습니다. 실험 입력은5초 이내입니다. 현재1024차원에서 영구 PCM/embedding 캐시 용량은844,288바이트(약0.805MiB)이며, 일시 계산 버퍼·기존 LLM KV는 별도입니다.

**원래 전체 encoder의 수치 동등 캐시나 학습된 streaming ASR는 아닙니다.** 창별 정규화·반사 padding·attention 문맥이 달라져 부분 전사가 바뀔 수 있습니다. `partial_audio_window_cache=false`도 독립 창 분할은 유지하며, 완료 창만 다시 계산합니다. 같은 창 처리의 캐시 정확성과 원래 전체 encoder의 전사 정확도를 구분했습니다. 기존 log-Mel preload와 동시 사용은 금지합니다.

설계 참고는 [antirez/qwen-asr의 완료 창/prefill 재사용](https://github.com/antirez/qwen-asr/tree/924694251d9e0f18e5d86bbd06aa3ab5f870002d)입니다. 그 BF16 런타임을 도입하지 않고 기존 GGUF bridge를 확장했습니다. [공식 Qwen3-ASR streaming 코드](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_asr.py)는 누적 입력을 사용하는 vLLM 경로이며 이번 RP5 실행 경로가 아닙니다.
