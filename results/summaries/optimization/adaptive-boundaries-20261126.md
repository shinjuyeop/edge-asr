## A와 B의 실행 구조

**A · 음향 기반 분할.** 소유 2.4초 이후부터 이미 도착한 원음으로 짧은 쉼을 확인한다. 32ms 창 네 개 이상의 저확률 구간과 VAD 회복이 필요하다. 쉼 평균 에너지가 이전 128ms와 첫 회복 32ms 중 낮은 쪽의 20% 이하여야 쉼 내부를 선택한다. 접수된 쉼 창 내부에서 최저 에너지 창의 중앙을 사용한다. 쉼이 없으면 5초에서 자르고, VAD가 종료를 준비 중이면 최대 128ms를 기다려 짧은 끝 조각을 앞 구간에 포함할 수 있다. 2.4초는 호출 고정비가 있는 모델을 너무 자주 실행하지 않기 위한 하한이며 5초는 연속 음성의 상한이다. 두 값은 이 단계에서 반복 탐색하지 않았다. 쉼 확인까지 들인 시간은 실제 발행 지연에 포함했다.

**B · 선택적 중첩과 지연 확정.** A와 같은 소유 경계를 사용한다. 강제 절단 결과가 두 글자 이상의 마지막 어절과 종결부호로 끝났을 때 최종 발행을 최대 3초 보류한다. 이미 표시한 자막은 남고 마지막 어절만 교체될 수 있다. 다음 동일 VAD 구간의 기존 부분 요청 하나에 직전 구간에서 최대 384ms를 빌려 준다. 빌린 음성의 출력은 화면에 따로 붙이지 않는다. 빌려 읽은 결과와 다음 소유 PCM의 확정이 두 어절에서 합치하고, 직전 마지막 어절이 그중 첫 어절의 엄격한 접두부일 때만 직전 조각을 철회한다. 같은 완전한 어절의 반복, 추가 내용이 있는 대조, 모호한 정렬에는 기존 전사를 보존한다. 시간 만료·다른 확정·EOF에 남은 전사를 배출한다. 기존 부분 호출이 필요하므로 탐침이 없는 경계에서는 기존 전사가 남는다.

Qwen의 Encoder와 오디오 Prefill은 PCM이 늘거나 달라지면 다시 계산한다. 고정 텍스트 KV는 공통 기준 그대로다. 저장된 고정·서울의 T/P8에서 완료한 부분 354건을 같은 세그먼트 확정과 대조했다. PCM SHA가 같은 사례는 0건이었고 시작점이 같으면서 끝이 100ms 이내인 부분도 0건이었다. 같은 PCM이 아닌 KV·임베딩의 재사용이나 일반 확정 재실행을 생략하는 변경은 실험에 들어가지 않았다.

## 채택과 다음 순서

빠른 자막에는 T를, 경계 정확도에는 P8을 유지한다. A는 고정 100개와 서울에서 기존 경계 일부를 개선했으나, 고정 100개의 첫 본문·갱신·확정 목표를 모두 넘겼고 서울의 실제 단어 표시와 낭독 정확도에 손해가 있었다. B는 현재 Qwen 출력과 직렬 실행 순서에서 안전한 복구에 쓸 근거를 얻지 못했다. A와 B는 재현·대조용 프로필로 보존한다. 이 단계의 결과로 기본 채택 후보가 없어 30분 안정성은 실행하지 않았다.

같은 P8 확정 PCM·토큰을 고정해 Decode와 오디오 Prefill의 점유를 먼저 줄인다. 현재 첫 표시의 꼬리는 제출 전 워커 점유가 지배적이다. 그 다음에는 실제 양쪽 발음을 지지하는 근거가 확보된 강제 경계만 수정 대상으로 삼는다. Qwen에 신뢰할 만한 단어 시각이 없는 상황에서는 단순 문자 겹침으로 확정 결과를 바꾸기 어렵다.

## 재현과 원시 기록

기준 프로필은 T와 P8이며 [A](../../../configs/listener_hailo_adaptive_pause.toml)와 [B](../../../configs/listener_hailo_boundary_repair.toml)는 선택 실행이다. [기존 프로필 기반 RP5 재현 절차](partial-scheduling-20261125.md#재현-방법)에서 프로필과 manifest를 교체한다. 고정·장문·독립 목록, 입력 해시, 통계와 실제 측정 커밋은 [실험 요약 JSON](adaptive-boundaries-20261126.json)을 참고한다.

원시는 Host `/d/shin/edge-asr`와 RP5 `~/projects/edge-asr` 아래 `results/optimization/opt3/adaptive-boundaries-20261126-01/`에 있다. VAD 모의·PCM 추출·청취·해시 검산은 Host의 `results/maintenance/adaptive-boundaries-20261126-01/`에 있다. 저장 결과만 재생하려면 개발 PC에서 아래 명령을 실행하고 [청취 화면](http://127.0.0.1:8765/)에서 기록과 원음을 선택한다.

```bash
run=results/optimization/opt3/adaptive-boundaries-20261126-01
.venv/bin/python scripts/edge_asr.py tools listen-qwen3 --port 8765 \
  --manifest results/maintenance/adaptive-boundaries-20261126-01/pilot.jsonl \
  --run "$run/pilot-T" --run "$run/pilot-P8" \
  --run "$run/pilot-A" --run "$run/pilot-B"
```

실험 코드 `87bead9`은 Host Python 518개와 Node 8개, Ruff, 공통 설정·M1 자산 검사를 통과했다. main에 반영한 코드로 RP5 후보를 실행했다. 개발 PC 포트 8765에서 T·A·B의 원음과 이벤트 로딩을 확인했다. [코드 커밋](https://github.com/shinjuyeop/edge-asr/commit/87bead98a6013155f8e0bcd7b2eed8efb32a2fe0) · [실험 코드 CI](https://github.com/shinjuyeop/edge-asr/actions/runs/45749501843)

RP5에서 회수한 원시 파일 140개와 양쪽 장비의 입력 파일 9개를 SHA-256으로 대조했다. 원래 CPU 상한 2.4GHz와 `ondemand`를 확인했고 임시 Hailo 모듈을 해제했다. 실행 전 설치되어 있던 펌웨어 해시는 그대로였다. Git에는 실험 소스와 통계·입력 해시를 기록했다.
