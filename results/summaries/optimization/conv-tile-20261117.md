# FP16 합성곱 타일 선별 — 2026-11-17

**4×4 타일 후보가 고정 PCM 선별과 원래 무-preload 앞뒤 대조를 모두 통과했습니다.** 무-preload 대조 대비 encoder 시간은13.2~13.3%, 전체 native 호출은4.0~4.5% 줄었습니다. 유효 선별54회와 추가 대조36회 모두 기존 전사/token ID가 같고 실패0입니다. 주 평가는 여전히 Qwen 단독1배속 연속 입력이며, 이번 결과는 그 안의 연산 후보를 고르는 진단입니다. 새 CER·연속 첫 자막·장시간 성능은 미측정이고 운영 기본은 유지합니다.

## 바꾼 부분

기존 FP16 합성곱2/3에서 한 번에 계산하는 결과 묶음을4×6에서4×4로 줄였습니다. 열 작업 묶음도12→18타일로 바꿔 약72열 단위를 유지합니다. [최소 패치](../../../native/gguf/conv_sgemm.patch)는 고정 upstream 사본의2줄만 바꾸며, FP16 FMA/축약·원래 threadpool·동적 작업 분배를 재사용합니다. [선택 래퍼](../../../native/gguf/conv_sgemm.cpp)는 FP16×FP16→FP32·3T·n480/k4320과 확인한 여섯 m값에서만 대체합니다. 나머지는 원래 함수로 전달합니다.

Q8 text/audio·생성2T/음성·prefill3T·고정 text prefix KV·기존 engine/bridge·입력은 같습니다. 직전 FP16 내적 후보와 Q8 prefetch는 켜지 않았습니다. 원래 함수 S, 같은 소스를 재컴파일한4×6 C,4×4 F를 구분해 재컴파일 효과를 대조했습니다. [고정 SGEMM 구현](https://github.com/ggml-org/llama.cpp/blob/7d7f0287530bc8981690f361d8c1627dbae1c99a/ggml/src/ggml-cpu/llamafile/sgemm.cpp#L565), [사전 조건과 보완 기록](../../../docs/research/qwen_realtime.md#fp16-합성곱-타일-선별--2026-11-17-사전-조건).

36회 전사/token 동일·실패0, 최대 RSS는 A1654.61/F1655.27/B1655.44MiB였습니다. 앞뒤 순서·열 상태·소표본 변동이 남아 있으며, 반복 횟수는 서로 다른 한국어 발화 수가 아닙니다. 잘린 세 PCM에 새 정답을 부여하지 않아 CER을 계산하지 않았습니다.

## 실제 코드와 비용에서 확인한 점

유효 교차 선별의 두 합성곱 작업자 CPU 합은 원래 대비 **40.13% 감소**했습니다. 이는 병렬 작업자 합이며 단일 wall 지연이 아닙니다. encoder 전체에는 다른 연산이, 전체 호출에는 prefill/decode가 남아 있으므로 전체 감소율과 구분합니다.

원래 CPU 바이너리와 재컴파일6열 모두8원소 내부 반복에서24개의 FP16 FMA와 **12개의 스택 벡터 쌍 저장**을 확인했습니다.4열은16개의 FMA를 수행하며 같은 내부 반복에 스택 저장이 없습니다. 원래 루프70명령·후보44명령은 각각24/16출력을 계산하므로 단순 명령 수 비율을 속도 비율로 해석하지 않습니다. 반복 스택 저장 제거가 유력한 개선 원인입니다. 캐시/주소 계산/컴파일러 처리의 기여율을 따로 계측하지 않았으므로 이를 DRAM 대역폭이나 단일 원인으로 확정하지 않습니다. 어셈블리와 루프 추출 기록을 별도 보존했습니다.
