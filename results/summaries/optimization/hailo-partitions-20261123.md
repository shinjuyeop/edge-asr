# Qwen Q8의 Hailo-8L 연산 분배와 실시간 자막 지연

2026년 11월 23일 · Raspberry Pi 5 실측 · 실행 ID `hailo-partitions-20261123-01` · 동일 Qwen3-ASR-0.6B Q8 GGUF. [검산·계측 요약 JSON](hailo-partitions-20261123.json)

**첫 자막과 갱신 속도를 우선하면 Conv1·2·3 + GELU 묶음, 정확도를 우선하면 CPU Conv1 + NPU Conv2·3, 두 지표를 함께 보면 Conv2 단독을 권한다.** 공유 Q8 CPU 설정은 그대로 사용했고 후보는 선택 preload로 실행했다.

- **속도**. CNN 세 층만 묶은 경로가 첫 표시 중앙값 2.92초, p95 7.24초였다. 실클럭이 비슷했던 선행 CPU는 7.48초, 8.34초였다. 동일 확정 native 합은 607.67→508.69초(16.3% 단축), 오류는 419→450자였다.
- **정확도**. Conv2·3 묶음의 오류는 389/3,848자(CER 10.11%)로 이 평가에서 가장 적었다. 첫 표시 중앙값은 6.72초였고 확정 추론 합은 559.79초였다. Conv2 단독과의 정확도 차이는 원음 100개에서 6자였다.
- **균형**. Conv2 단독은 CER 10.27%, 첫 표시 중앙값 3.67초였다. Conv2·3 묶음보다 첫 표시가 3.05초 빨랐고 최신 음성 반영 공백 p95도 5.99→5.33초였다.
- **투영까지 통합한 결과**. 16×1 방식 단일 HEF의 확정 합은 513.11초, 별도 HEF 두 개는 508.46초, 기존 세 층 묶음은 508.69초였다. 전체 요청 합은 기존 묶음 671.19초에서 단일 HEF 654.11초로 줄었다. 이때 부분 요청도 132→115회로 줄었고 첫 표시와 최신 음성 반영은 늦어졌다.

당일 선행 CPU는 210개 확정에 607.67초, CPU 재시도는 687.37초가 걸렸으며 토큰은 210개 모두 일치했다. 실클럭이 1.49 GHz 아래였던 입력 표본은 각각 0.0%, 30.2%였다. 세 층 묶음의 단축 폭은 선행 CPU 대비 16.3%, 더 뜨거웠던 CPU 재시도 대비 26.0%였다. CPU와 NPU의 순수 연산 분배 효과를 판단할 때는 실클럭이 비슷했던 당일 선행 대조와 1·3·5초 앞뒤 CPU 대조를 우선한다.

연산 표는 11월 20일 같은 PCM의 연산 계측값을 재사용했다. 연산별 귀속과 병목 진단용이다. 새로운 구성과의 전체 호출 속도비는 위의 새 PCM 대조에서 계산한다. 5초 CPU decode에서 어휘 출력층은 토큰당 17.31ms였다. K/V는 F16 각 28 MiB다. 고정 텍스트 prefix hit 때의 정리와 위치 관리는 CPU에 두고, 생성 중 K/V 읽기·쓰기는 decode에 포함했다. 단계별 전용 RSS와 실제 PCIe 패킷 바이트·장치 SRAM 최고 점유량은 측정되지 않았다. [계측 오버헤드·CPU 클럭·5초 토큰별 시간](hailo8l-q8-20261120.md)

5초 PCM은 16 kHz mono float32 320,000 B, STFT는 501프레임이다. Mel 128밴드를 100프레임 단위로 패딩하면 6청크와 78개의 Encoder 토큰이 된다. 첫 블록의 FP32 입력·출력은 각 279,552 B, 14×78×78 attention 점수는 340,704 B, 78×3,584 FFN 활성은 1,118,208 B다. 이는 shape에서 계산한 논리 텐서 용량이다. llama.cpp가 커널을 결합하거나 임시 버퍼를 재사용할 수 있어 RSS 증가와 일치하지 않는다.

GGUF의 CNN 합성곱 및 CNN 출력 투영 원본 weight는 FP16, 최종 MLP와 텍스트 선형층은 Q8에서 복원했다. 표의 ONNX 상수 용량은 장치 SRAM 사용량과 다르다. 같은 HEF 파일에서도 컨텍스트가 바뀌면 장치의 배치·전송 비용이 추가될 수 있다.

주파수 패킹용 고정 항등 합성곱은 파싱과 양자화까지 통과했으나 DFC 자원 할당 중 vector 범위 검사에서 실패했다. 해당 후보에는 HEF·장치 지연·전사 결과가 없다.

CNN 투영의 원래 열 인덱스는 채널×16+주파수이다. 동일 행렬을 16×1 합성곱으로 표현해 Transpose/Reshape 파서 제한을 피했다. 다른 두 표현은 주파수 16개를 재배치한 뒤 같은 1×1 투영을 적용했다. 세 층 CNN의 정밀도·보정 변형 세 개는 기존 파싱 HAR을 재사용했다. 일반 전치·reshape와 시간축을 먼저 둔 reshape는 UnsupportedShuffleLayerError였다. A16/W8 지시는 이 Conv에서 DFC가 거부했다. A16/W16은 Conv1·2의 내부 정밀도를 바꾸고 외부 vstream 형식은 장치 보고값을 사용했다.

첫 Encoder 블록은 LayerNorm → 14헤드 Q/K/V → scaled attention/Softmax → 출력 투영·잔차 → LayerNorm → FFN·원래 Erf GELU → 잔차를 한 HEF에 담았다. 기존 attention 일부 HEF의 입력·두 번째 정규화 경계를 대조하고 전체 블록 출력을 검산했다. 26·52·78토큰에 해당하는 정적 HEF만 선택하고 다른 길이는 원래 CPU 블록을 실행한다. 블록 1개에서 1초와 5초의 전체 효과가 서로 달랐고 수치 오차도 관측되어 2~4개 및 전체 18층으로 확대하지 않았다. 최종 MLP는 마지막 정규화 뒤 896→896→1,024이고 CNN 뒤 7,680→896 투영과 별개다.

LLM은 첫 층의 Q/K/V 가중치를 행으로 이어 1,024→4,096으로 실행했다. RoPE와 attention, KV 위치·재사용, 28층의 생성 순서는 기존 llama.cpp가 관리한다. 기존 FFN up은 음성·텍스트 prefill 및 1토큰 decode에서 실제 HEF를 실행한 기록이 있다. 전체 151,936×1,024 어휘 행렬은 외부 FP32 가중치로 ONNX 검산을 통과했고 세 decode 샘플에서 argmax가 일치했다. 16 GiB 과정은 메모리 할당에서 중단됐고 29 GiB 주소 공간으로 재시도해 양자화까지 통과했다. 최종 할당은 출력 concat 자원 배치에서 Agent infeasible로 종료됐다. 단일 Q/K/V의 이득을 28층 decode 가속률로 환산하지 않았다. Hailo-8L은 전체 LLM을 지원하는 GenAI 장치로 분류되지 않는다. [공식 Raspberry Pi 장치표](https://www.raspberrypi.com/documentation/accessories/ai-hat-plus.html) · [기존 FFN·DFT/Mel 실측](hailo8l-q8-20261120.md)

### 양자화 오차가 전달되는 위치

## 재현과 검증

부팅 디스크와 외부 PCIe 장치 식별값, 격리한 펌웨어·도구 버전은 환경 기록에 있다. [장비·런타임 구성](../../../docs/reference/environment.md)

고정 llama.cpp `7d7f028`, 생성 2스레드·음성/prefill 3스레드·고정 텍스트 prefix KV. 동일 모델·실행기·설정·PCM 해시와 소스 커밋, HEF 해시 및 원시 측정 파일 해시는 JSON에 있다. 단계별 진단과 기본 성능 평가는 분리했다. 변경은 선택 preload와 Host 추출 및 진단에 한정한다. [GGML·HailoRT 연결](../../../native/gguf/hailo_conv.cpp) · [그래프 추출](../../../native/gguf/export_audio_boundaries.py) · [경계 캡처](../../../native/gguf/qwen_boundary_dump.h)

저장된 전사는 `results/optimization/opt3/hailo-partitions-20261123-01/` 아래에 있다. `fixed-separate`는 CNN과 투영의 별도 HEF, `fixed-fused`는 단일 16×1 HEF, `fixed-tail`은 CPU Conv1과 NPU Conv2·3, `fixed-cpu`는 CPU 대조의 중단 기록, `fixed-cpu-retry`는 같은 설정의 재시도다. Conv2 단독과 세 층 묶음은 선행 실행 `hailo-cnn-stack-20261123-01/fixed-conv`와 `fixed-stack`으로 재생할 수 있다. [저장된 실행 청취 방법](../../../docs/guides/listener.md)

스트리밍은 별도 HEF → 단일 16×1 HEF → Conv2·3 → CPU 순서였다. 1·3·5초는 각각 첫 회를 제외한 세 번의 반복 평균으로 비교하고, 단일 HEF 두 후보는 1초에 50%, 3·5초에 각 25% 가중치를 둔 상대 지연으로 골랐다. Conv1을 CPU에 남긴 보완 후보에서는 추가 투영 없이 Conv2·3의 정확도를 검증했다. 첫 오디오 블록과 최종 MLP는 짧은 PCM에서 일관된 추가 이득이 작아 100개 평가로 확대하지 않았다.

**다음 최적화 우선순위**

1. 정확도 우선 경로의 첫 부분 요청 제출을 앞당긴다. Conv2·3의 첫 표시 p95에 해당하는 원음은 제출까지 6.23초, 큐에서 0.002초, 실행 시작 후 표시까지 1.89초였다. 이 한 건의 병목과 나머지 원음의 제출 조건을 대조하고, 다음 실험에서는 모델 연산 분배를 고정한 채 첫 요청 정책만 바꿀 수 있다.
2. CPU decode와 음성 prefill을 우선 프로파일링한다. CNN 세 층 묶음에서 확정 decode 271.84초가 native의 53.4%를 차지했다. Q8 어휘 출력·FFN의 메모리 읽기와 스레드 분할을 같은 토큰·전사에서 비교한다.
3. Conv2·3 경계의 정확도 차이를 독립적인 긴 자연발화와 낭독에서 확인한다. 추가 CNN 투영을 붙인 5초 PCM은 3,142→3,062ms였다. 이 구성의 100개 CER는 미측정이다.

**검증 상태**. 추론 소스 `2796e6e`를 Host에서 검사한 후 main에 push하고 RP5에서 빌드했다. 16개 DFC 후보 중 11개의 새 HEF를 컴파일해 보드에서 실행했고, 보관한 attention 세 shape와 LLM FFN HEF도 다시 실행했다. 서로 다른 14개 고정 PCM 실행(기준선·재대조 포함)의 전사와 토큰을 확인했다. 신규 후보 세 개의 완주와 CPU 대조·재시도 상태는 1배속 기록에서 검산했다. `c389872`의 Host 추출기는 세 가지 융합 ONNX를 실험 파일과 바이트 단위로 재현했다. Host 회귀 테스트 489개, Ruff 정적·포맷 검사, C++ 경고 오류 빌드와 GitHub Host CI가 통과했다. HEF·모델·원음·원시 추론 파일은 실험 경로에 보관했다.

RP5에서 해시를 구한 원시 파일 72개의 Host 복사본을 검산했다. 실험 종료 후 CPU 상한 2.40 GHz와 임시 드라이버·펌웨어 해제를 확인했다. 장치가 보고한 온도·과전류 보호 설정은 켬이었다. 종료 후 조회한 장치 온도는 TS0 50.0°C, TS1 49.9°C였다. 부하 중 NPU가 성능 제한에 머문 시간은 미측정이다.
