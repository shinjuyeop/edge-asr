# Q4 prefill 실행 경로·4스레드 선별

2026-11-13. **Q4의 음성·prefill 스레드를3→4로 늘려 소폭 개선을 확인했습니다.** 고정 PCM 선별에서 앞 대조 대비 LLM prefill은약8~9%·첫 token은약9~10% 줄었습니다. 같은6개 연속 입력에서는 첫 표시 p95 약4.19→4.12초, CER21.07%·최종 전사/token ID·완료율은 같았습니다. 프로세스 CPU 시간은약7~8% 늘었습니다. [집계·해시](prefill-q4-20261113.json), [사전 조건](../../../docs/research/qwen_realtime.md#q4-prefill-실행-경로-선별--2026-11-13-사전-조건).

## 바꾼 조건

실제 추론 소스는 `b850d0caa5e05d28f6492aadae053c6a770bc71a`입니다. 기존 text Q4_K_M/audio Q4_0·같은 가중치·기존 prefix bridge·생성2T·context512·출력128·greedy·고정 text prefix KV를 유지했습니다. **선택된 변경은 `num_threads_batch=3→4` 하나**이며 audio encoder·LLM prefill·공통 prompt 평가에 함께 적용됩니다. prefill만의 독립 최적화라고 부르지 않습니다.

새 [Q4 비교 설정](../../../configs/quantization/q4_prefill_realtime.toml)은 측정한4T 설정과 파싱 결과가 같습니다. 기존 [Q4 3T](../../../configs/quantization/q4_both_realtime.toml)·Q8 공유 기본·기존 환경/패키지·모델·원음·원시는 보존합니다. 새 프로파일링 callback이나 KV 변경은 사용하지 않았습니다.

고정 소스의 KleidiAI Q4_K 선택표에는 SME2/FP16 커널만 있고 RP5 CPU feature에는 SME2가 없어 **해당 Q4_K 가속 경로**는 정적으로 제외했습니다. 다른 dtype의 KleidiAI 지원과 구분합니다. 검토용 고정v1.32.0 archive는 별도 보존했으며 설치/활성화하지 않았습니다.

대신 기존 repack ON/3T·ON/4T와 별도 repack OFF/3T·OFF/4T를 비교했습니다. OFF 엔진은 `runtimes/qwen3-opt/q4-norepack-20261113-01/{engine,bridge}/`에 새로 만들었습니다. 같은 고정 llama.cpp `7d7f0287530bc8981690f361d8c1627dbae1c99a`·같은 컴파일러/기존 CMake 옵션이며 CPU C/C++ FLAGS는 같고 define에서 `GGML_USE_CPU_REPACK`만 빠졌습니다. 기존 Ninja·새 Makefiles의 생성 방식 차이와 실제 flags 검증도 JSON에 남깁니다. CMake의 컴파일러 캐시 형식 FILEPATH→STRING 정규화로 첫 확인이 멈췄지만 경로/값은 같았고, 초기 기록을 보존한 채 검증 후 빌드했습니다. OFF 엔진은 느려져 후보에서 제외했고 운영용으로 채택하지 않았습니다.

## 실패 기록·검증·청취

첫 연속 시도는 worker가 입력/추론을 완료했지만 실험 래퍼가 반환 dict를 종료값으로 전달해 exit1이 됐습니다. guard 미검증 원시는 `control-before/`에 보존하고 위 비교에는 쓰지 않았습니다. 완료/실패·진단/연속의 종료코드 모의4건을 확인한 뒤 **새 `realtime2/`의3실행**을 다시 측정했습니다. 기존 CLI/평가기 소스의 동작 변경은 없었습니다. 첫 실행/래퍼 원본·실패 campaign·새 완료 campaign을 모두 보존합니다.

Host GGUF/고정 헤더29개·문서 링크1개가 통과했고 새 공개 설정과 측정 설정의 파싱 동등성·Ruff/포맷166파일·M1 원본·deploy 구문을 확인했습니다. 이번은 core 코드 변경이 없어 전체 회귀를 다시 실행하지 않았습니다. Host 모의/문법·설정 검사와 **RP5 실제 진단80호출 및 유효 연속94호출**을 구분합니다. 준비 호출은 진단80회에 포함된 앞4라운드와 연속의 별도 워밍업으로 기록합니다. 모든 유효 모델 호출·입력 드롭은 실패0입니다.

## 현재 판단

**Q4 안의 개발 비교에는 기존 repack ON·생성2T/음성prefill4T를 후보로 제공합니다.** 현재 Q8 공유 기본은 유지하며100개 자동 확대·실사용 채택은 하지 않았습니다. Q4의59/280오류를 유지한 것이고 이전 Q8의50/280오류와 정확도가 같아진 것은 아닙니다. 다른 실행/스레드 조건의 이전 Q8보다 우수하다고 선언하지 않습니다.

현재 repack을 끄는 방향은 제외합니다. 첫 자막을 더 줄이려면 입력 수집 대기와 첫 요청의 유효 내용, 또는 실제 ARM 행렬 커널 내부를 별도로 확인해야 합니다. 이번 결과에서 미측정 성능·마이크/장시간 안정성·전력 개선을 채우지 않습니다.
