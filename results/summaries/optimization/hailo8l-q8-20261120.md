# Raspberry Pi 5의 Qwen3-ASR Q8과 Hailo-8L 실측

2026-11-20 KST · 실험 `hailo8l-q8-20261120-01` · [측정 요약과 자산 해시](hailo8l-q8-20261120.json)

**Hailo-8L에서 Qwen의 두 번째 합성곱을 실제로 가속했고, 기존 Qwen 실행기로 100개 원음의 전사까지 완료했다.** 5초 고정 PCM 전체 호출은 CPU 3,415→하이브리드 3,194 ms였다. 1배속 운영 상태에서 호출 시간 합계는 782.34→770.05초(1.57% 감소), 같은 확정 PCM의 native 합계는 645.22→635.05초(1.58% 감소)였다. 최종 CER은 10.89%→10.27%, 첫 자막 p95는 8.82→8.78초였다. 같은 확정 210개 중 78개에서 토큰열이 바뀌었다. 온도와 CPU 주파수도 시간에 따라 변했다. 최신 음성 반영 공백 p95는 5.23→5.25초로 늘었다. 운영 기본은 Q8 CPU로 두고, Conv2를 정확도·냉각 조건 재검증 대상으로 보존한다.

운영 상태의 4 GiB 주소 공간 제한과 기본 열 보호를 유지했다. 고정 입력은 600초, 스트리밍은 1,800초 timeout을 적용했다. 각 실행에는 다른 추론이 겹치지 않도록 공통 lock을 걸었다. 측정 중 열 제한과 기존 데스크톱 부하가 있었고, 운영 온도 정책으로 실행 순서를 고정했다. 통제 냉각 상태에서의 속도나 모집단 신뢰구간은 이 실험의 측정 범위 밖이다.

### Encoder 내부와 토큰 수

노드별 동기화로 스케줄링과 fusion도 달라질 수 있다. 같은 PCM에 별도 계측 bridge를 연결해 원래 ggml 노드 순서대로 벽시계와 프로세스 CPU 시계를 읽었다. 후반 4라운드에서 계측 끔·켬·켬·끔을 사용했다. 아래 비율은 **계측을 켠 해당 길이 전체 호출** 대비다. 총 CPU 시간은 병렬 작업자 시간을 합한다. 원본·계측 끔·켬·텐서 추출·특징 추적에서 길이별 greedy 토큰 일치를 확인했다.

5초 **동일 호출**에서 첫 토큰 뒤 4·8·12·17번째 토큰까지 각각 229.3, 541.6, 849.7, 1,242.3 ms가 더 들었다. 5초의 CPU decode에서 어휘 출력 행렬 한 곳이 평균 **17.31 ms/토큰**이었다. 원본 5초에서 자동회귀와 음성 prefill이 합계 약 54.5%였다. F16 K/V는 각 28 MiB, 합계 56 MiB(28층, KV head 8, head 폭 128, context 512)다. 음성 창 사이 KV는 재사용하지 않는다. [이전 Q8 단계 재측정](reprofile-q8-20261116.md)과 [Q8·Q4 장문 대조](decoder-pair-stream-20261118.md)는 입력 정책과 열 이력이 달라 이번 A/B 계산에서 제외했다.

## 3. 단계별 Hailo-8L 판정

AI Kit와 Hailo-8L AI HAT+는 기능상 동등하다. 공식 장치표는 Hailo-8L을 INT8 13 TOPS로 표기하고 LLM을 미지원으로 분류한다. Hailo-10H의 GenAI·온보드 8 GB 경로는 별도 제품에 해당한다. Hailo-8 계열 공식 도구 조합은 DFC 3.x·Model Zoo 2.x다. 8L에도 정적으로 매핑된 Transformer 사례는 있어 Qwen의 실제 서브그래프를 따로 검사했다. 메모리는 파일 크기, 텐서 크기, 실행 RSS로 나눴다. text/mmproj에 실제 저장된 텐서는 각각 798,801,920 / 214,374,976 B다. Conv1·2·3 원래 weight는 8,640 / 4,147,200 / 4,147,200 B, CNN 출력 투영은 13,762,560 B다. 블록 하나의 ONNX FP32 상수는 36.80 MiB, 그중 FFN 서브그래프가 24.52 MiB이고 embedding 서브그래프는 6.57 MiB다. LLM layer 0의 FFN up 원본 Q8은 3,342,336 B, FP32 ONNX는 12 MiB, HEF는 5,374,329 B였다.

5초 Conv2의 호스트 FP32 양방향 텐서는 총 46,080,000 B, UINT8 논리 데이터는 11,520,000 B다. 이는 청크 6개 × (1,536,000 입력 + 384,000 출력) 원소다. 실제 PCIe 패킷·내부 패딩·프로토콜 헤더와 칩 내부 SRAM 최고 점유량은 미계측이다. 고정 입력 하나를 여러 행·청크로 제출했으며 길이별 HEF가 필요한 블록에서는 별도로 export했다.

## 4. ONNX 검산, 정수 양자화와 실제 HEF

원래 GGUF weight와 RP5 native의 실제 입출력을 캡처했다. 원래 FP16 또는 Q8_0 weight를 ONNX FP32로 복원한 뒤 Host ONNX Runtime CPU와 RP5 출력의 shape, max absolute error, RMS와 상대 L2를 검사했다. 해석 축은 CNN NCHW, 시퀀스는 시간×특징 순서다. 무편향 Conv는 원래 bias를 다시 더해 같은 위치에서 비교했다. 상대 L2는 오차 벡터의 L2를 원래 출력 L2로 나눴다.

원음 첫 표시는 원음 시작부터 처음 관측한 서버 자막 이벤트까지, 공백은 입력 중 표시 문구가 달라지면서 처리 음성 끝 프레임이 전진한 간격(처음·끝 포함), 확정은 구간 끝부터 최종 결과 발행까지다. 발화 단어와의 음향 정렬·브라우저 렌더 시간은 미계측이다. 1배속은 벽시계로 음원 길이만큼 재생하므로 추론 합계, 사용자 지연과 배출 잔여를 따로 제시했다. 부분 호출 수는 같은 스케줄러에서도 처리 속도에 따라 달라질 수 있다.

성공한 동일 PCM 확정 210개 중 원시 전사 일치 132개, 정규화 전사 일치 143개, 출력 토큰열 일치 132개였다. 구간 3 `이제 사람들은 컴퓨터 화면에 메시지를 쓰고 연필깎이를 가까이 할 필요가.` → `이제 사람들은 컴퓨터 화면에 메시지를 쓰고 연필깎기를 가까이 할 필요가.`. 구간 5 `지구가 마치 움직이지 않은 것처럼 느껴지기에 언뜻보기에 맞는 말 같기.` → `지구가 마치 움직이지 않은 것처럼 느껴지기에 언뜻보면 맞는 말 같고.`.

Pi PMIC의 VDD_CORE 전류×전압을 입력 시계 200–500초의 같은 구간에서 약 1초마다 읽었다. 이 레일은 SoC 일부만 포함한다. HailoRT 전력 측정은 장치가 `HAILO_UNSUPPORTED_OPCODE(48)`를 반환했다. 외부 전력계 자료가 없어 NPU 자체 전력·전체 시스템 전력·문장당 에너지 변화는 미측정이다. 칩 실행은 HEF별 완료, 하이브리드 콜백과 4절의 하드웨어 지연 기록으로 확인했다.

## 7. 후속 우선순위

1. **CPU의 자동회귀 decode를 우선한다.** 같은 5초 PCM에서 17토큰에 1.35초였고 매 토큰 어휘 출력 행렬 한 곳에 17.31 ms가 들었다. 원래 greedy 토큰·CER를 대조하며 Q8 출력 projection과 FFN GEMV의 메모리 읽기·스레드 분할을 측정할 차례다. CPU에서 이미 검증한 FP16 Conv 타일도 같은 사용 조건의 선택지다. [기존 CPU 4×4 실측](conv-realtime-20261117.md)
2. **NPU 후속은 Conv2의 전송·보정과 CNN 출력 투영으로 한정한다.** 5초 통합 경로에서 Hailo 동기 27.7 ms와 CPU 재배열 44.5 ms가 들었다. Conv2에서는 보정 범위와 입력·출력 버퍼 형식을 검토한다. 다음 통합 후보는 CNN 출력 투영이다. 5초에서 독립 CPU 노드 101.39 ms, NPU 동기+재배열 6.78 ms, 상대 L2 2.30%였다. 이 이득은 아직 전체 실행기에 연결해 재지 않았다. 첫 attention의 상대 L2 6.94–7.48%는 18층으로 확대하기 전에 누적 오차와 CER 검증이 필요하다. 같은 PCM의 토큰, 100개 원음의 CER, 최신 반영 공백·첫 자막·확정 p95를 같이 확인해야 한다. 온도·실클럭 편차 때문에 냉각 상태를 맞춘 순서 역전 반복이 운영 기본 채택의 다음 검증이다.
3. **큐 대기와 첫 자막을 별도로 줄인다.** CPU에서 첫 자막 p95는 8.82초였고 확정 큐 대기 p95는 5.55초였다. 서로 다른 사건의 분위수여서 직접 빼지 않는다. 고정 prefix는 warm hit 100%여서 KV 지우기보다 부분·확정 요청의 충돌을 우선 검토한다.
4. DFT·Mel, 단일 LLM FFN 행렬, 정확 GELU를 포함한 전체 Encoder와 8L 전체 LLM 포팅은 보류한다. DFT·Mel은 왕복이 CPU보다 느렸고, FFN 한 노드만으로 상태 관리와 반복 호출을 포함한 LLM 전체 가속을 입증할 수 없다.
