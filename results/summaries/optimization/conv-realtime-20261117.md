## 입력 길이와 선택 연결

정확히5초인 PCM은 끝 프레임 패딩으로6청크가 됩니다. 첫1~5청크 빌드는5초를 원래 함수로 전달하는 점을 경계 실측에서 확인했습니다. 이를 숨기지 않고 별도 ID `conv-realtime-20261117-01`로 보존했으며, 후속 빌드에 m4800/1248을 추가했습니다. 다른 shape·dtype·stride·스레드는 원래 함수로 전달합니다.

첫 빌드의 합성48조건/96비교·실제34호출은 수치/전사/token 동등·실패0입니다. 직후 집계가 호출 목록을 상세 결과로 읽은 오류는 원시를 보존하고 `predictions.jsonl` 재집계로 복구했습니다. 연속 입력 전에 두 번째 빌드로 전환했습니다.

후속 빌드는 합성56조건/112비교의 출력 비트·입력·경계를 유지했고,20ms 및1~5초±1프레임/6초 초과의17입력×원래/후보34호출도 전사/token 동일·실패0입니다. 정확한 초 경계에서 청크가 증가함과 범위 밖 전달을 확인했습니다. 이 진단에는 CER을 부여하지 않습니다.

`conv_kernel_manifest`로 선택한 별도 빌드와 그 하나의 `LD_PRELOAD`·`EDGE_ASR_CONV_CPU`가 필요합니다. 해시·커밋·전역 심볼을 검사하며 실제 호출의 shape/작업자별 수락을 기록합니다. 원래 대조는 preload를 사용하지 않습니다.

## 해석과 검증

전사·최종 PCM·token·완료율과 계산 시간, 첫 표시/첫4자/갱신 공백을 따로 판단합니다. 6개 p95는 사실상 최댓값이며 같은 개발 음원의 반복입니다. 순차 운영 열·클럭 차이가 있어 통계적 유의성이나 순수 커널의 인과 효과를 확정하지 않습니다. 단위 호출이 빨라져도 적응 정책이 다른 부분 요청을 수락할 수 있어 전체 호출 비용/자막 지연은 같은 비율로 줄지 않습니다.

Host 실측 연결 구현439개 중435개 통과·선택 native4개 생략,6청크 수정 후 명시 헤더/관련39개 통과입니다. 종료 복원 보완은 전체440개 중436개 통과·4개 생략입니다. RP5 모델 없는 ELF 검사 뒤 빌드·수치·실제 추론을 직렬 실행했습니다. 원시146파일의 Host/RP5 해시와 독립 재집계, 보호1227파일 불변·단일 부팅·4GiB 제한을 확인했습니다. 온도 시작 대기는 생략하고 유한 실행 제한·전압/장비 검사는 유지했습니다.

세 조건의 최종210구간은 기존100개 기록과 PCM·전사·token까지 같고, 실패·입력 드롭·첫 또는4자 미표시가0입니다. 첫 표시는 문장부호를 포함하고 첫4자는 문자·숫자4개입니다. 음원 시작 기준 서버 이벤트 발행 시각이며 음향 단어 정렬/브라우저 렌더 시각은 아닙니다.

Host/RP5 공유 파일 대조1226개와 장비별 환경 파일을 구분했습니다. `.venv/pyvenv.cfg`는 각 장비의 Python 버전·경로가 달라 교차 대조에서 제외했으며 덮어쓰지 않았습니다. 실측 중 RP5 보호1227파일의 전후 해시는 모두 같습니다. Host에서 뒤이어 수정한 소스는 실측 커밋8d49d98의 Git 내용으로 따로 검증했습니다.

## 종료 복원과 청취

후속 소스74846de에서 선택 모델 종료 시 원래 커널(mode0)을 복원하도록 보완했습니다. `conv-close-20261117-02`의 같은 프로세스에서 후보→종료→기본으로2회 실제 전사해 PCM·전사·token 동일, 종료 직후 mode0/빈 집계, 후속 기본 호출의 원래 경로 수락을 확인했습니다. 이 검사는 성능/CER 비교가 아닙니다. 첫 시도 `conv-close-20261117-01`은 준비 폴더를 guard 출력으로 지정해 기존 폴더 보호에 걸렸고 추론0회로 종료됐습니다. 로그를 보존하고 새 ID의 비어 있는 하위 출력 경로에서 검증했습니다. 별도 원시26파일도 Host/RP5 해시가 같습니다.

측정 웹의 **기록**에서 `conv-realtime-20261117-02/full100-before`, `full100-tile4`, `full100-after`를 선택합니다. 기존61기록/23프로필을 유지하며 **64기록/23프로필**로 갱신했고, 세 기록의100개 지표·이벤트 API와 후보 WAV 응답을 확인했습니다. 새 라이브 실행 프로필과 공유 기본은 추가/변경하지 않았습니다.

6개·100개 사전 기준을 통과한 선택 엔진 후보로 보존합니다. 첫4자/갱신 공백 개선은 관측했지만 첫 자막 p95 변화는17~77ms였습니다. 다음은 같은 원음의 청취와 사용자 발화가 가능한 때의 USB 마이크 확인이며, 첫4자 지연의 긴 꼬리와 장시간 안정성은 계속 검증합니다.
