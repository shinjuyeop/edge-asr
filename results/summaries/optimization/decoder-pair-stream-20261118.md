# 긴 음원 1배속 스트리밍에서 같은 빌드의 GGUF Q8·Q4 비교

RP5에서 자연발화 8개와 낭독 4개를 1배속으로 재생했다. 최종 연결 CER는 Q8 **12.03%(384/3,192자)**, Q4 **15.73%(502/3,192자)**였다. 같은 성공 구간의 확정 지연 p95는 자연발화 3.80→2.79초, 낭독 4.18→2.88초로 Q4가 짧았다. 최신 음성을 반영한 자막 사이의 최대 공백은 각각 5.25→5.22초, 5.64→5.32초였다. 이번 조건에서 정확도 기준은 Q8, 확정 응답 속도 비교 기준은 Q4로 둔다. [기계 판독 요약·명령·원시 해시](decoder-pair-stream-20261118.json)

## 실제 스트리밍 지연

모든 지연의 단위는 초다. 토큰과 완료 이벤트 중 실제 표시할 내용이 생기거나 바뀌었을 때의 서버 발행 시각을 사용했다. 확정 p95의 공통 성공 표본은 자연발화 162구간, 낭독 64구간이다.

자연발화에서 Q4는 첫 표시 중앙값을 0.60초, 확정 p95를 1.01초 줄였다. 그런데 최신 음성 반영 공백 p95는 4.68→5.01초로 늘었다. 낭독에서는 이 공백이 5.33→5.17초로 줄었다. 자연발화 전체의 마지막 구간(166번)에서 Q4는 반복 생성 후 실패해 입력 종료 2.45초 뒤에 응답했다. 같은 구간에서 Q8은 0.65초 뒤에 성공했다. 따라서 공통 성공 구간의 지연과 실패를 포함한 최종 대기를 함께 본다.

## 재현 조건

RP5(Cortex-A76 4코어, RAM 8GB)에서 소스 `9d70b77`과 실행 ID `decoder-pair-stream-20261118-01`을 사용했다. Seoul Corpus 자연발화 8개(467.428초)와 Zeroth-Korean 연결 낭독 4개(265.229초)를 각각 파일 순서대로 이어 재생했다. 파일 사이에 무음을 추가하거나 상태를 초기화하지 않았다. 각 자료×모델에서 첫 음원의 앞 5초로 최초 추론 1회·워밍업 3회를 수행한 뒤 측정을 시작했다. 자연발화는 Q8→Q4, 낭독은 Q4→Q8 순서로 한 번씩 실행했다. [음원 구성과 정답 출처](../../../docs/research/longform.md)

`tools replay-qwen3`의 독립 입력 프로세스가 16kHz PCM을 100ms씩 해당 프레임의 실제 시각에 공개했다. 두 모델에서 같은 Silero VAD(임계값 0.3, rms26-floor80), VAD/ASR 최대 5초, 첫 부분 요청 1초·후속 간격 4초, 대기 확정 최대 4개, 토큰 표시·접두부 재표시 보류를 사용했다. 입력 시계는 이전 요청의 추론 완료를 기다리지 않는다. 네 실행의 생산자 로그에서 청크마다 끝 프레임÷샘플레이트와 예정 시각이 같고, 실제 전달 시각이 그 이후임을 확인했다. [입력 시계 구현](../../../src/edge_asr/streaming.py)

같은 KleidiAI OFF bridge, Q8_0 음성 encoder, 한국어 greedy, 생성 2스레드·음성/prefill 3스레드, 고정 텍스트 접두부 KV 캐시를 사용했다. Q4는 decoder와 출력층이 Q4_0, Q8은 양쪽이 Q8_0이다. Q8 설정은 보존한 `decoder-q4-20261117-01/configs/q8-off.toml`의 사본이며 전체 모델 설정·빌드와 모델 해시는 JSON에 있다. 고정 냉각과 기존 펌웨어 보호를 사용했다. 각 실행의 열 정책은 `operational`, 시작 허용 온도는 60°C였다. [Q4 설정](../../../configs/quantization/q4_0_head_realtime.toml)

## 측정 범위

- **연결 CER**는 자료별로 원래 정답과 시간순 확정 전사를 연결해 `ko_cer_v1`로 계산했다. 실패로 빈 자막이 남은 곳도 정답 분모에 포함했다. 합계는 두 자료의 오류 수 합을 정답 문자 수 합으로 나눴다.
- **첫 표시**는 파일 시작부터 그 파일에만 귀속되는 첫 표시 가능 이벤트까지의 시간이다. 첫 4자는 문자·숫자가 4개 이상인 첫 표시다. 자연발화 8개·낭독 4개에서 파일 p95는 각 자료의 최댓값이다.
- **텍스트 변경 공백**은 입력 중 서버에서 표시 가능한 자막이 실제로 바뀌는 사이의 시간이다. **최신 음성 반영 공백**은 바뀐 자막에 사용한 요청의 마지막 프레임이 지금까지 표시한 최댓값을 넘어설 때만 갱신으로 센다. 두 지표 모두 파일 경계를 가로지르는 자막을 포함해 자료 전체의 시간축으로 계산하며, 내부 무음과 재생 시작·끝 공백을 포함한다. 이는 단어별 음향 정렬이나 물리 화면 시각과 다른 측정이다.
- **확정 지연**은 두 모델에서 모두 성공한 같은 구간의 끝부터 서버의 확정 응답까지다. **전체 입력 끝→처리 완료**는 마지막 입력 프레임부터 모든 대기 요청 배출과 최종 반환까지다. 총 추론 시간은 실제로 실행한 부분·확정 요청의 추론 시간 합이다.
- CPU는 재생·생산자 프로세스의 CPU초 합을 (재생부터 최종 반환까지의 경과초×4)로 나눈 값이다. RSS는 주 프로세스 표본 최댓값, 제한 시간은 입력 중 펌웨어 현재 제한 비트를 약 1초 간격으로 관측해 직전 값을 적분한 근사치다.

모델별로 자연발화와 낭독을 각각 한 번씩 측정했다. 실행 순서와 열 상태의 영향이 남는다. 이번 평가는 고정 WAV 재생과 서버에서의 이벤트 발행을 다룬다. 마이크 수집부터 브라우저 표시까지의 지연, 음성 시각별 부분 CER, 더 긴 부하에서의 안정성은 별도 측정 대상으로 남는다. 배포 ONNX INT8의 동일 자료 1배속 기준선은 이전 실행을 참조한다. [ONNX INT8·GGUF Q8 기준선](longform-backends-20261118.md)

## 결과 검증

두 모델에서 원음·순서·VAD·설정·워밍업 PCM·확정 233구간의 경계와 PCM 해시가 일치했다. 과거 독립 호출과 비교한 확정의 원시 텍스트 일치는 Q8 233/233, Q4 233/233이었고 토큰 ID 일치는 Q8 233/233, Q4 233/233이었다. 원래 manifest와 이번 서버 확정 이벤트로 독립 편집거리를 계산해 오류 수를 검산했다. RP5에서 보존한 원시 파일 49개의 SHA-256이 Host 사본과 모두 일치했다.
