# M3-5 제한 교체의 저장 기록 재생

2026-11-03. 기존 연속 Zip 전사를 유지하면서 M3-4의 구조 후보만 Refine 원문으로 교체하는 두 정책을 Host와 RP5에서 재생했다. **KSS 전체 CER는 개선됐지만 5개 발화가 악화돼 자동 교체를 채택하지 않는다.** 이번 단계는 모델 없는 이벤트 재생이며 새 ASR 추론·실시간 입력·실제 자막 교체·UI 실행은 없다.

## 입력과 고정 정책

- 재생 구현 커밋: `b981084a092103e47cbe59f23648a063bdb38850`.
- 실제 입력 기록의 소스 커밋: `fcc942af41f33b31f3df6e564afd407a593ff759`. [M3-4 RP5 기록](m34-continuous-token-20261103.md)의 KSS 개발 50개·합성 120초 1개·디지털무음 6개를 사용했다.
- [사전 계획](../../docs/archive/model-comparison/m35_guarded_splice.md)의 `zip_only`와 `guarded_replace_v1`만 비교했다. 기존 구조 후보 34개(KSS 29/합성 5)와 보류 66개를 유지했다. 결과를 보고 범위를 늘리거나 사례를 제외하지 않았다.
- 각 기기에서 3기록×2정책=6회 재생, 57개 원본×2=114개 선택 결과를 평가했다. 독립 발화 114개가 아니며 이미 사용한 개발 자료의 재평가다.
- 세션·원본·작업·좌표·payload 해시·실제 수신 성공·원래 토큰 앵커를 확인하고, 기존 audit에서 후보가 준비된 순서대로 적용했다. 정답은 출력 확정 뒤 `ko_cer_v1` 채점에만 사용했다.
- 교체할 때마다 원본 Zip의 좌표로 조립했다. Refine 공백·문장부호·반복을 그대로 유지했고, 문구 필터나 중복 제거를 적용하지 않았다. 실제 서비스의 기본 모드는 바꾸지 않았다.

| 자료 | 원본 수 / 정답 문자 | Zip CER | 제한 교체 CER | 오류 수 변화 | 개선 / 동률 / 악화 |
| --- | --- | --- | --- | --- | --- |
| KSS 개발 | 50 / 756 | 11.64% | 8.33% | 88→63 | 13 / 32 / 5 |
| 기존 합성 장문 | 1 / 519 | 11.18% | 10.60% | 58→55 | 1 / 0 / 0 |
| 디지털무음 | 6 / 0 | null | null | 0→0 | 양쪽 모두 빈 전사 |

| 자료·정책 | 치환 S | 삭제 D | 삽입 I |
| --- | --- | --- | --- |
| KSS Zip | 71 | 11 | 6 |
| KSS 제한 교체 | 46 | 9 | 8 |
| 합성 Zip | 44 | 12 | 2 |
| 합성 제한 교체 | 43 | 10 | 2 |

KSS 삽입 오류는 6→8자로 늘었다. 구조 후보 통과와 비선택 문자열 보존이 모든 발화의 정확도 개선을 보장하지 않는다. 합성 장문은 기존 자료를 연결한 1개 입력으로, 자연 장문 전체에 일반화할 수 없다. 빈 정답의 CER는 0으로 바꾸지 않았다.

악화한 KSS 5개를 모두 남긴다. 아래 입력 좌표는 원본 WAV 시작 기준이며, 이들 모두 Refine 한 개가 최종 캡션 전체를 대체했다.

| 원본 ID | Zip→교체 오류 수 | 오류 증가 | Refine 입력 범위(초) | 원본 앞에서 포함하지 않은 길이 |
| --- | --- | --- | --- | --- |
| `kss-train-01001` | 2→4 | +2 | 0.380→4.9284375 | 380ms |
| `kss-train-01011` | 0→1 | +1 | 0.124→1.31625 | 124ms |
| `kss-train-01035` | 0→3 | +3 | 0.124→3.8010625 | 124ms |
| `kss-train-01036` | 0→1 | +1 | 0.380→4.273125 | 380ms |
| `kss-train-01041` | 3→6 | +3 | 0.540→3.9009375 | 540ms |

예를 들어 `01011`의 Zip `팔이안움직여.`는 Refine 원문 `살이 안 움직여`로 바뀌었다. `01041`의 교체 결과는 `일 내 에 한번 대구로 찾아가겠습니다`다. 어휘 오인식과 입력 문맥의 영향이 모두 가능하다. 입력 앞부분이 제외됐다는 좌표만으로 실제 음소가 잘렸다고 확정하지 않는다. 다만 **디코더 토큰 시각으로 정한 문자 범위와 Refine이 실제 받은 음성 범위가 같은 내용을 담는다는 보장이 부족하다.** 전체 캡션이 선택되면 비선택 문자 보존 검사를 통과해도 선택 범위 내부의 손실은 막지 못한다.

이 사례 ID를 금지하거나 텍스트를 사후 교정하지 않았다. Refine 자체의 `요구 세하세요` 같은 출력도 그대로 보존했고, 병합 경계에서 생긴 중복으로 임의 분류하지 않았다.

## 보존·경계·표시 변경

34개 후보가 모두 재생에서 등록됐고 마지막에도 유지됐다. KSS 27/50개 원본과 합성 1개 원본의 최종 문자열이 바뀌었다. 기존 보류 66개는 교체하지 않았다. 실제 겹침 거부·접두부 수정·앵커 오류 사례는 이 입력에서 발생하지 않았으며, 해당 복원 동작은 모의 테스트로 검증했다.

| 자료 | 재생 교체 수 | 최종 유지한 Zip 원문 문자 / 교체한 원문 문자 | 문자열 변경 횟수 Zip→교체 | 정규화 접미부 수정 사건 / 제거 문자 합 |
| --- | --- | --- | --- | --- |
| KSS | 29 | 407 / 396 | 379→408 | 22 / 249 |
| 합성 장문 | 5 | 521 / 63 | 283→288 | 2 / 25 |
| 디지털무음 | 0 | 0 / 0 | 0→0 | 0 / 0 |

문자 소유·출처·해시를 각 조립에서 검증했다. 두 정책 합계 6,386회의 검사에서 **비선택 Zip 문자열의 기계적 누락·변경은 0**이었다. 위 원문 문자 수는 공백/문장부호를 포함하므로 정규화 CER의 문자 수와 다르다. 접미부 제거 합은 표시가 바뀔 때 정규화 최장 공통 접두부 뒤에서 지운 길이의 합이며, 실제 삭제 오류나 화면 깜빡임 횟수가 아니다.

Refine 앞뒤의 정규화 접미사/접두사 겹침 2자 이상은 0건, 인접 문장부호 쌍은 0건이었다. KSS 최대 겹침은 1자였다. 이 진단은 같은 글자의 우연한 반복을 포함하며 실제 음성의 중복 단어를 판정하지 않는다. 경계 경고가 없어도 KSS 삽입 오류와 개별 악화는 발생했다.

## 시각과 미측정 항목

여기서 시각은 기존 native audit의 `assessed_ns`에 따른 **저장 기록의 가용 시점**이다. 재생 실행시간을 실제 인식·병합 지연으로 사용하지 않았다.

| 자료 | 소유 구간 끝→재생 교체 등록 p50 / p95 | 원본 오디오 끝 전 등록 |
| --- | --- | --- |
| KSS | 0.277 / 0.990초 (n=29) | 4/29 |
| 합성 장문 | 1.240 / 1.603초 (n=5) | 5/5 |
| 디지털무음 | null (n=0) | 등록 없음 |

첫 표시 trace 시각은 두 정책이 같은 Zip 스냅샷으로 시작하므로 동일했다. KSS p50/p95는 0.852641/1.456388초, 합성 단일 관측은 0.843360초다. 이는 M3-4의 실제 모델 반환 시각과도 계측 지점이 다르며 과거 첫 부분 지표를 소급 수정하지 않는다. 새 native RTF·CPU·RSS, 실제 교체 적용 지연, UI 표시 지연, 음향 정렬 지연은 모두 **null/미측정**이다. 실제 live 교체는 0회다.

## 검증과 보존

- Host: 279개 단위 테스트, 39.318초, 통과. RP5: 279개, 64.954초, 통과. 새 어댑터 로딩이나 실제 모델 추론 성공의 증거로 취급하지 않는다.
- 다른 길이의 교체·미래 Zip 추가·역순/인접/겹침·중복·접두부 수정·잘못된 앵커·철회·실패/드롭/누락/빈 Refine·늦은 원본 결과·세션/해시 오류를 모의 검증했다. 정답을 바꿔도 타임라인/판정/최종 출력이 같은지 확인했다.
- Host/RP5의 의미 산출물 39개가 SHA256으로 일치했다. 플랫폼·실행시간이 다른 `execution.json` 3쌍은 동일성 비교에서 분리했다.
- 기존 실제 입력 원시 66개를 대조했다. RP5 보호 대상 비 Markdown 파일 5,404개가 변경·누락 없이 유지됐고 모델·가상환경·설치 패키지·시스템 설정이 그대로임을 전후 감사로 확인했다. 추적 소스 변경은 새 재생 기능과 문서에 한정했다.
- 상세 수치·입력/산출물/증거 해시는 [JSON 요약](m35-guarded-splice-20261103.json)에 기록했다. 이전 M1/M2/M3 결과와 기본 평가 설정은 보존했다.

원시는 Git 제외 경로 `results/merge-replays/m35-guarded-splice-20261103-01/{host,rp5}/`에 보관했다. 각 정책의 `timeline.jsonl`, `decisions.jsonl`, `finals.jsonl`, `scores.jsonl`, `boundaries.jsonl`에 교체 원문·개별 점수·복사 증거가 있다. 계획·테스트·전후 감사는 `results/maintenance/m35-guarded-splice-20261103-01/`에 있다. 두 기기에 같은 재생 증거를 보존한다.

## 다음 판단

연속 Zip을 유지한 교체의 구현·재현성 검증은 완료했고, `guarded_replace_v1`의 자동 채택은 보류한다. **다음은 입력 음성 범위와 교체 문자 범위의 불일치를 분리하는 검증**이다. 먼저 악화/개선/동률 사례를 함께 사용해 토큰 시각·원음 범위·실제 전사 범위를 분석하고, 앞뒤 문구를 보존하는 별도 정책의 허용 조건과 실패 조건을 실행 전에 고정해야 한다. 원본 앞부분을 포함하지 않은 Refine으로 전체 캡션을 덮어쓰는 상황을 검증 항목으로 둔다.

v1을 사후 수정하거나 개발 결과를 최종 독립 평가로 부르지 않는다. 새 정책은 별도 ID로 모델 없는 재생·개별 악화·경계 검사를 거친 뒤, 별도 1배속 실제 병합에서 적용 지연·CPU/RSS·드롭/백로그를 측정한다. 자연 장문·마이크·사람 검수 음향 경계·독립 평가·장시간 운영과 UI는 여전히 미검증이다.
