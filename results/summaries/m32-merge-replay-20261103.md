## 정확도와 선택

`zip_only`는 Zip 최종 유지, `refine_complete`는 모든 제출 작업의 성공/비어 있지 않은 연결 전사를 요구하는 Refine 선택, `agreement_only`는 추가로 Zip과 `ko_cer_v1` 정규화가 같을 때만 선택한다. 작업 없음/실패/누락/드롭/빈 결과는 이유와 함께 Zip으로 fallback한다. 정답은 선택 후 채점에만 사용하며 임의 단어 필터·중복 제거·발화별 유리한 모델 선택은 없다.

## 지연과 자막 변경의 한계

현재 Zip partial은 파일 전체의 누적 문자열이며 단어/문자 오디오 시간이 없다. 따라서 VAD 프레임 좌표로 일부 문자열을 잘라 교체하지 않는다. 부분 전사는 그대로 표시하고 **파일 종료와 모든 제출 Refine 결과가 확정된 뒤 전체 파일을 선택**한다. 다른 파일의 늦은 결과가 현재 파일을 덮지 않도록 ID별 상태를 보존한다.

아래는 원래 Zip 반환/child `ended_ns`를 가용 시각으로 삼은 **trace 유도값**이다. parent의 실제 수신·병합 적용·화면 표시 시각이 아니며, 과거의 구간 끝→Refine 반환 p95와도 다른 지표다. `agreement_only`도 비교하려면 모든 결과를 기다려 아래 Refine 선택 결정 시점과 같다. Zip 문자열 자체는 그동안 계속 표시된다.

| KSS 정책 | Zip 최종→선택 추가 대기 p50/p95 | 파일 오디오 끝→선택 p50/p95 | 첫 Refine 준비→선택 p95/최대 |
| --- | --- | --- | --- |
| 고정5초 | 0.102 / 0.176초 | 0.256 / 0.343초 | 0.055 / 0.737초 |
| VAD0 | 0.085 / 0.141초 | 0.244 / 0.336초 | 2.360 / 3.522초 |
| 후속200ms | 0.085 / 0.139초 | 0.243 / 0.332초 | 2.357 / 3.507초 |

KSS 첫 표시 문자열과 trace 시점은 세 선택 정책에서 같았다. 합성 장문은 고정/VAD0/후속 각각 첫 Refine 준비 뒤 **115.395 / 117.604 / 117.565초**를 기다렸다. 파일 끝 뒤 선택은 각각0.100 / 0.282 / 0.253초로 짧아 보여도 중간 교정 지연을 감춘다. 모두 같은 장문1개의 단일 유도값이며 p50/p95는 null이다. 파일 끝만 기준으로 실제 실시간 교정이 충분히 빠르다고 결론내리지 않는다.

변경 횟수는 실제 화면이 아닌 재생 상태의 원문 문자열 변화다. 일치 선택의 추가 변경은 정규화로 지워지는 공백·문장부호 등이며 CER 개선은 없다. JSON에는 정규화 공통 접두사 뒤 지운 접미부도 남긴다. 완전 Refine의 해당 제거 문자수는 KSS 고정412/VAD각419, 합성각508자다. 접미부 전체 교체의 부담을 보는 공학 지표이며 Levenshtein 오류수·실제 렌더링 비용이 아니다. 이 입력에서 Zip 유지 경로의 정규화 접미부 제거는0이었다.

실제 병합 dispatch/UI 지연, 음향 정렬 인식 지연, VAD 부분 교체 CER, 새 ASR RTF·CPU·RSS는 **미측정/null**이다. 재생 스크립트 wall은 실행 메타데이터에만 기록하고 ASR 처리량으로 사용하지 않는다.

## 다음 구현 범위

다음은 **동일한 VAD 구간을 Zip과 Refine이 명시적으로 가리키는 별도 온라인 실험**이다. 기존 연속 Zip 기준선과 이번 원시는 그대로 둔다.

1. Zip 결과에서 구간/토큰 시간 정보를 실제 API가 제공하는지 확인하고, 제공하지 않으면 구간별 인식 상태를 사용하는 별도 모드를 설계한다. 상태 reset·tail·종료 정책 변경은 인식 결과를 바꿀 수 있으므로 기존 기준선과 같은 것으로 취급하지 않는다. 누적 문자열을 시간 비율로 자르지 않는다.
2. 세션/구간 ID와 소유/문맥 PCM 해시를 두 경로에서 일치시키고 `job 제출→child 완료→parent 수신→병합 적용` 시각을 추가한다. VAD가 끝을 늦게 판정하는 동안의 미래 청크·새 구간 소유도 명확히 한다. 큐 상한/드롭/실패/종료 배출을 함께 검증한다.
3. Host에서 늦은 결과·다음 구간 전환·취소/실패·반환 역순·경계 중복/누락을 검증한 뒤 RP5 Zip1T+Sense2T+VAD1T의 별도 ID로 같은 개발/무음/합성 입력을 실행한다. 실제 첫 부분·구간 확정·parent 병합 지연, CER·개별 악화·자막 변경량, 드롭/백로그·CPU/RSS·온도를 함께 기록한다.
4. 정답에 의존한 선택은 사용하지 않고, 먼저 구간별 정확한 교정과 지연을 확보한다. 자연 장문·마이크·사람 검수 경계·장시간 운영·독립 평가가 남아 있으므로 M3 전체나 Hybrid 배포 완료로 표시하지 않는다.
