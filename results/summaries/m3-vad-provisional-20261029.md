# M3 VAD 구간 주석·RP5 예비 비교 — 2026-10-29

**기존 Silero VAD의 실제 RP5 실행 160/160건과 워밍업 2건이 완료됐고, Host 재채점이 일치했다.** 짧은 목표 발화의 전체 누락은 배포 라벨 기준 원음 9/64, RMS 4/64였다. 그러나 RMS에서 새로 누락된 발화 1개와 무음 구간 검출 증가도 있어 **RMS/VAD 정책을 채택하지 않는다**. 이번 결과는 배포 라벨 기준 예비 비교이며 이번 프로젝트에서 사람이 청취·파형 검수를 완료한 정답 평가는 아니다.

## 입력·보류·주석

이전 검수 WAV 98개는 수정하지 않았다. 성능을 보기 전에 `s05/s10/s15/s20/s25/s30/s35/s40`의 18개를 보류하고, 나머지 32명 화자의 초단문 64개·장문 11개 및 미검수 잡음 5개를 개발용으로 고정했다. 보류 18개는 실제 추론과 워밍업에 사용하지 않았다. 원래 음소 라벨의 파일명/해시와 16kHz 절취 프레임을 추적한다. 모델 학습 중복 없는 최종 평가 세트라고 주장하지 않는다.

배포 논문 음소 표에 있는 36개 표기만 예비 음성, `<SIL>`만 예비 비음성으로 매핑했다. 면접자 발화·웃음·호흡·잡음·불명확 라벨은 ignore로 보존했다. 잡음 WAV 5개는 말소리 포함 여부가 미검수여서 전 구간 ignore다. VAD 출력을 정답으로 쓰거나 전사/모델 출력에 필터를 적용하지 않았다.

개발 WAV 총 **345.844초** 중 예비 음성은 **128.788초**, 명시적 비음성은 **11.338초**, 제외 구간은 **205.717초**다. 제외 구간을 비음성으로 취급하지 않는다. 클립의 앞뒤 자연 문맥을 포함한 주석이며, 화자·환경 전체의 정확도로 일반화할 수 없다.

## 구간 결과

‘음성 누락’은 알려진 음성 프레임 중 검출 소유 구간에 포함되지 않은 비율, ‘비음성 검출’은 알려진 비음성 프레임 중 검출된 비율이다. 허용 폭은 0프레임이며 겹친 예측은 합집합으로 집계한다. 전체 누락은 선택한 목표 발화 안의 알려진 음성 프레임과 검출의 교집합이 없는 경우다. 음성 프레임 비율은 목표 발화뿐 아니라 WAV 안의 다른 알려진 음성 문맥도 포함한다.

장문의 비음성 분모는 **0.478초뿐**이다. 비음성 검출 길이는 원음 0.024초, RMS 0.150초이므로 비율만으로 큰 일반적 성능 차이를 주장하지 않는다. 초단문의 비음성 분모는 10.860초다. 잡음 행은 **오탐률이 아니다**. 두 조건 모두 `noise-free-sound-0002`에서 반환했으며 소유 구간 길이는 원음 0.344초, RMS 0.760초였다. 실제 말소리 포함 여부를 확인해야 한다.

전체 누락 판정이 사라진 사례는 6개, 두 조건 공통 누락은 3개, RMS에서 새로 누락된 사례는 1개다. 새 누락 `seoul-s17f24f1-u0032`의 목표 음성 3,350프레임 중 원음은 3,222프레임과 겹쳤고 RMS는 0이었다. 이를 분석하기 전 RMS가 모든 초단문에 유리하다고 결론 내릴 수 없다. 모든 원시와 `review-focus.json`을 보존했으며 실패 조사 목록을 평가 표본의 사후 교체에 사용하지 않는다.

원음에서는 초단문 WAV 56/64개에서 구간이 반환됐지만 목표 발화 전체 누락은 9개였다. **파일 어딘가에서 검출됐다고 해당 짧은 발화를 잡았다는 뜻은 아니다.** 구간 기준 채점을 추가한 이유다.

## 실행·자원·냉각

실측 코드 커밋은 `c4ec5c8`이다. 같은 기존 1T Silero 파일과 Python 환경에서 원음→RMS 순서로 실행했다. 설정은 threshold 0.5, 최소 음성 0.1초, 종료 무음 0.3초, native soft limit 5초, 외부 소유 상한 5초·왼쪽 문맥 200ms, native 버퍼 31초/활성 예산 30초다. 각 정책에 모델 로딩 1회·동일 첫 초단문 워밍업 1회·80개 각 1회이며, 워밍업은 집계에서 제외했다.

각 WAV의 자연 문맥에서 전처리/VAD 상태를 초기화했다. 합성 앞뒤 무음 없이 빠르게 파일을 공급했으므로 이전 KSS·1배속·연속 입력 결과와 조건이 다르다. 새 ASR 추론이나 Hybrid 동시 실행은 하지 않았다.

RTF 분모는 문맥 포함 WAV 345.844초다. 호출에는 공통 PCM/구간 해시·RSS 샘플러 등 계측 비용이 포함되며 원본 WAV 읽기/해시·채점·모델 로딩은 제외한다. OS 파일 캐시 상태는 통제하지 않았으므로 로딩 시간을 최초 부팅의 cold start 비용으로 해석하지 않는다. **ASR RTF나 실제 입력 지연이 아니다.** 작은 RTF 차이를 속도 개선으로 해석하지 않는다.

1Hz 관측 CPU0 클럭은 원음 2.4GHz, RMS 1.5~2.4GHz였고 시작 온도도 같지 않았다. 두 실행은 기존 53°C 이하 시작·75°C 중단·현재 제한/새 이력/결측 감시와 600초/4GiB 외부 제한을 통과했다. 관측 현재 제한은 0, 기존 이력 `0xe0000`은 유지됐다. 순간 제한·주변 온도·열평형까지 통제한 것은 아니다. 과거 Zipformer 2T 냉각 중단은 해결됐다고 보지 않는다.

각 실행 TID 관측 10회에서 5개 스레드가 보였다. 동일 주 TID의 인접 표본 9구간 CPU는 약 100.04%/99.69%였다. 스레드 수 자체를 활동 코어 수로 해석하지 않으며, 짧게 생성·종료된 스레드의 모든 CPU를 포함하는 측정도 아니다. 이 VAD 결과로 과거 Zipformer의 CPU 324% 원인을 확정하지 않는다.

실제 청취 검수 endpoint, wall 지연, ASR 첫 자막/Refine 지연, 입력 드롭·백로그는 **미측정/null**이다. 빠른 파일 실행의 시간으로 채우지 않았다.
