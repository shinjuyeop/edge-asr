# M3-1 후속: 시작 여유와 강제 분할 후속 문맥 비교

작업 기준일 2026-11-03. **RP5 12/12회·318/318개 원본 평가가 성공했다.** 시작 전용 200ms는 KSS에서 1자 개선됐지만 합성 장문에서 12자 악화됐다. 후속 전용 200ms는 실제 적용된 한 구간에서 전체 오류가 1자 줄었다. **시작 여유를 일괄 늘리지 않고, 후속 문맥은 제한된 실험 후보로 남긴다.** [수치·발화별 비교·증거 JSON](m3-context-split-20261103.json), [사전 고정 계획](../../docs/research/m3_context_split.md).

## 고정 조건과 구현

소스 `70169c1`. Host main push→RP5 소스 동기화→양쪽 테스트→새 ID `m3-context-split-20261103-01` 순서로 실행했다. 기존 모델·WAV·정답·TOML·환경은 유지했다. SenseVoice INT8 **1T**·ko·ITN false·identity·`ko_cer_v1`, 기존 k2 Silero SHA·Python ORT1T를 사용했다. sherpa/core 2.0.1 네이티브 ORT **1.28.2**와 VAD의 Python ORT **1.31.1**을 구분했다.

`SegmentPipeline(context_selection=...)`으로 문맥 위치만 나눴다. 기존 기본 `all`과 과거 요약 형식은 유지했다. 새 선택에서만 VAD span ID·후속 여부·적용 문맥 길이를 기록한다. 자연 종료 뒤 새 시작과 hard_limit 뒤 후속을 구분하며, 이미 확정한 tail보다 VAD 끝이 앞서 마지막 payload가 없는 경우도 검사했다. 소유 경계·VAD 임계값·상태·상한은 바꾸지 않았다.

모든 전사는 구간 순서대로 단일 공백 연결했다. 중복 제거·금칙어·추가 무음·전체 WAV fallback·정답 수정은 없다. 모델은 실행당 한 번 로딩하며 같은 자료의 첫 발화 전체로 ASR3회, VAD 조건은 VAD만 추가3회 워밍업했다. ASR 워밍업36회·VAD24회와 로딩은 측정에서 제외했다. 합성 자료의 첫32초 ASR 워밍업은 약14.8~15.0초로, KSS 첫 발화의 약0.84초와 구분했다.

## 시작 여유와 후속 문맥의 차이

4개 VAD 조건의 소유 경계·순서·종료 이유가 **53개 원본 모두 같았다.** KSS는 자연 종료13개·EOF44개·hard_limit0개, 합성은 자연 종료73개·EOF3개·hard_limit1개였다. 문맥 위치를 바꿔 VAD 상태나 원래 구간을 달리 만든 비교가 아니다.

- **KSS:** 57개가 모두 새 VAD 구간 시작이며 후속은 0개다. 시작200ms와 일괄200ms가 같은 payload/전사를 만들었다. VAD0 대비 5개 개선·6개 악화·39개 동률, 치환-2·삭제-1·삽입+2로 순오류-1자다. 후속200ms는 실제 추가 문맥을 공급하지 않아 VAD0과 50개 모두 동률이다. 이를 KSS에서 후속 문맥 효과를 검증했다고 부르지 않는다.
- **합성 장문:** 시작76개·후속1개다. 시작200ms는 3개 원본 모두 악화, 치환-6·삭제+14·삽입+4로 순오류+12자다. 후속200ms는 120초 원본에서만 1자 개선되고 나머지2개는 동률이다. 치환-2·삭제-1·삽입+2로 삽입 증가도 남았다. 한 번의 후속 적용을 일반적인 장문 개선으로 확대하지 않는다.
- 같은 PCM payload 해시에서 서로 다른 원문 전사가 나온 경우는 0개였다. 시작 여유 때문에 전사가 바뀐 segment는 KSS21개/합성44개, 후속 문맥 때문에 바뀐 것은 합성1개였다. 이 입력에서의 정책 효과 분리 근거이며 모든 환경의 결정성을 보증하지 않는다.

사전 회귀 사례 `kss-train-01041`은 전체/고정5초2자, VAD0/후속200ms6자, 시작/일괄200ms3자 오류였다. 소유 시작은 8,640프레임(0.540초)으로 같고 시작 후보 payload는 5,440프레임(0.340초)부터다. 삭제4자가 사라졌지만 치환이 늘었고 전체 발화와 같아지지는 않았다. 음향 정답 정렬 없이 실제 어느 음소가 잘렸는지 단정하지 않는다.

KSS에서 고유 payload는 원음의 VAD0/후속 **89.68%**, 시작/일괄 **95.57%**다. 합성은 VAD0/후속 **81.84%**, 시작/일괄 **88.96%**다. 시작200ms는 다른 payload와 겹친 원음이 **0프레임**인데도 합성에서 악화됐다. 후속/일괄에만 중복 원음3,200프레임이 있었다. 일괄 후보의 전체 회귀를 이 중복 하나로 설명하거나 임의의 텍스트 제거로 덮지 않는다.

소유 상한은 80,000프레임, 허용 payload 상한은 83,200프레임이다. 합성에서 시작/일괄은 실제 최대83,200프레임, 후속 후보는 적용된 tail이 짧아 최대80,000프레임이었다. 후속 후보에서 실제5.2초 payload를 관측했다고 표시하지 않는다. PCM ring 관측 최대는 문맥0의96,000프레임/200ms 후보99,200프레임으로 유한 상한 안이었다. 입력 WAV 전체를 메모리에 읽는 파일 평가 도구 전체가 무제한 입력에 대해 유한 메모리라는 뜻은 아니다.

## 판단과 다음 구현

**VAD 시작200ms를 일괄 채택하지 않는다.** 일부 시작 회귀는 줄었지만 KSS 전체 발화 기준선을 넘지 못했고 합성3개 모두 악화됐다. 후속200ms는 상한/원음/상태 계약을 만족한 실험 후보지만 개선 근거가 실제 적용1회/오류1자에 한정된다. 기존 기본 설정과 자동 전사 교체 정책은 유지한다.

다음은 **VAD0 대조군과 후속200ms 후보를 Zip1T+Sense2T의 온라인 동시 계측에 연결**하는 작업이다. 이 단계의 지연을 단독 batch 수치로 추정하지 않는다.

1. 실제 bounded VAD를 입력 처리 경로에 놓고 로딩/워밍업·512프레임 VAD 비용을 기록한다. 파일 경계가100ms 청크 중간에 있을 때 원본별 입력 버퍼로 재조립하고 프레임 누락/압축을 거부한다. 미리 계산한 VAD 계획만 재생해 온라인 비용을 생략하지 않는다.
2. Refine job에 원본 절대 좌표의 소유/문맥/실제 공급 위치를 기록한다. 대기2구간·드롭/누락 기록·오류 회수를 유지한다. 문맥이 있는 큐의 실제 payload 메모리와 소유 오디오 백로그를 구분한다. 빈 VAD는 원본 정답에 대한 빈 가설로 남기며 fallback/금칙어로 덮지 않는다.
3. 구간 끝→VAD 방출→제출→큐 대기→인식 반환을 분리하고 Streaming 첫 부분·CPU/RSS·열·드롭을 측정한다. VAD의 알고리즘 끝점과 사람이 정렬한 실제 음향 끝점을 구분한다. Zip+VAD가 같은 PID에 있으면 그 자원 범위를 명시한다.
4. 이후에 실제 결과 병합·수정/악화율·자막 안정성을 검증한다. 자연 장문/잡음/무음·보류 자료·마이크·장시간 운영은 별도다. 지금 자료를 최종 독립 평가로 재사용하지 않는다.

이번 **비실시간 정확도 정책 검사**에서 Streaming 첫 부분·실제 endpoint·Refine 반환 지연·입력 드롭/백로그·최종 병합 CER는 미측정/null이다. 입력 파일 평가가 모두 성공했다고 온라인 VAD나 최종 Hybrid 배포가 검증된 것은 아니다.
