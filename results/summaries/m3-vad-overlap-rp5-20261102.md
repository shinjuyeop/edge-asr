# M3 후속 — 중첩 공학 입력의 30초 초과 VAD 활성 검증

2026-11-02. **실제 ARM64 모델의 연속 활성이 30초를 넘는 공학 조건을 재현하고 원시 대조를 완료했다.** 실험용 bounded 경로는 구간 상한·PCM·재귀 상태·버퍼 검사를 통과했다. 기존 native의 30초 안전 예산은 같은 입력에서 중단을 수행했다. 자연 장문 정확도·마이크·Hybrid 배포 완료를 의미하지 않으며 기본 경로와 임계값은 바꾸지 않았다. [상세 JSON·해시](m3-vad-overlap-rp5-20261102.json).

## 입력과 조건

소스 `03ac6d5`, RP5 aarch64/Python 3.11.18, NumPy 2.4.6, sherpa/core 2.0.1, Python ORT 1.31.1을 사용했다. native 내장 ORT는 1.28.2다. 모델은 기존 k2 Silero v4 SHA `9e2449e1087496d8d4caba907f23e0bd3f78d91fa552479bb9c23ac09cbb1fd6`다. 모델·VAD·구간 처리 코드는 이전 `e90854d`와 바이트 일치를 확인했다.

앞선 45초 반복/90초 접합 입력의 미충족 기록은 그대로 보존했다. 이번에는 기존 KSS 개발 50개, 총 164.919초를 목록 순서대로 연결했다. 90초 입력을 만들면서 1/2/3트랙과 위상 `floor(기저 프레임 수 × i / 트랙 수)`를 사전에 고정했다. 입력 샘플의 산술 평균을 ties-to-even으로 PCM16 정수화하며 추가 gain·limiter·필터·무음 제거를 하지 않았다. 두 트랙 위상은 `[0, 1319352]`, 세 트랙 위상은 `[0, 879568, 1759136]` 프레임이다.

모델 출력으로 원본/위상을 선택하지 않았으며 세 조건 모두 보존했다. 트랙 수는 독립적인 화자 수가 아니다. 자연 발화·정확도·최종 독립 평가로 쓰지 않고 전사 정답은 null이다. KSS 출처·리비전·CC BY-NC-SA 4.0 라이선스와 원본/파생 해시는 각 manifest에 보존했다. 보류 집합이나 불확실한 청취 메모를 정답으로 쓰지 않았다.

1트랙→2트랙→3트랙 순서로 각 bounded→native를 실행했다. 각 실행은 identity/rms26 × 3/5/8초 소유 구간 상한의 6조건, 워밍업 0회·조건별 1회다. 기존 53°C 이하 3회 연속 시작, 75°C/현재 제한/새 이력/결측 중단, timeout 600초·주소 공간 4GiB 제한을 유지했다. 1T VAD·ondemand governor·빠른 WAV 입력이며, 실시간 지연이나 반복 처리량 비교가 아니다.

## 실제 결과

| 입력 | bounded 원음 최대 활성 | bounded RMS 최대 활성 | bounded 완료 | native 완료 / 안전 예산 중단 |
| --- | --- | --- | --- | --- |
| 1트랙 대조군 | 6.948초 | 6.948초 | 6/6 | 6 / 0 |
| 2트랙 중첩 | 9.988초 | 9.988초 | 6/6 | 6 / 0 |
| 3트랙 중첩 | **37.572초** | **34.788초** | **6/6** | **0 / 6** |

36개 호출 중 **30개 완료, native 안전 예산 실패 6개, 기타 실패 0개**다. native의 실패 6개는 성공으로 재분류하지 않았다. 이 경우 외부 실행 제한은 통과했지만 worker는 `completed_with_failures`, 개별 호출은 `failed`·불완료로 남아 있다.

표의 활성 길이는 512프레임 창의 VAD 오디오 시간축이다. EOF 창에는 최대 511프레임의 0 패딩이 포함될 수 있으며 벽시계 지연이 아니다. 3트랙의 두 정책 모두 30초를 충분히 넘는다. native는 다음 창이 예산을 넘기기 전, 관측 최대 활성 29.988초에서 `native_active_budget_exhausted`로 중단했다. 부분 처리된 native의 시간·메모리를 90초 전체 완료한 bounded와 처리량 개선 수치로 비교하지 않는다.

bounded의 18개 호출은 모두 90초, 1,440,000프레임을 처리했다. 각 호출은 실제 NN 2,813창을 계산했고 세션 reset 차이는 1, h/c 상태는 1,024바이트였다. 강제 구간이나 자연 종료마다 NN을 reset하지 않았다. 3트랙의 6조건 모두 30초 초과 활성과 3/5/8초 소유 구간 검사를 동시에 통과했다.

Host에서 원본·공통 PCM·각 소유/문맥 payload 해시를 다시 대조했다. 구간 겹침이 없고 소유 상한·최대 200ms 문맥을 지켰다. 링버퍼 용량은 3/5/8초에서 각각 67,200/99,200/147,200프레임이며 관측 피크는 용량 이하였다. bounded 내부 파형 보관은 0, 완료 큐 피크는 1 이하였다. 이것은 VAD가 비음성으로 생략한 프레임이나 실제 단어 누락이 없다는 뜻이 아니다.

완료한 native 출력은 bounded와 의미 필드·PCM이 같았고, 안전 예산으로 중단한 native도 중단 전 이벤트가 bounded의 같은 앞부분과 일치했다. 실제 시계 시각은 비교에서 제외했다. 3트랙 bounded의 관측 최대 RSS는 조건별 78.94~80.44MiB였으며, 입력 전체 WAV와 참조 PCM·모델 세션까지 포함한 프로세스 표본이다. 장기 누수 부재나 메모리 절감률로 일반화하지 않는다.

## 냉각·연결 중단·보존

여섯 실행 모두 당시 저장한 열 감시와 주소 공간 제한을 통과했다. 실행별 감시 최고 온도는 62.80~65.00°C이고 새 제한 이력은 관측하지 않았다. 이는 VAD 1T 검사이며 기존 Zipformer 2T 고부하 냉각 실패가 해소됐다는 근거가 아니다.

실험 완료 후 결과 회수 도중 SSH가 `No route to host`로 끊겼다. 사용자 전원 재시작 후 접속을 복구하고 **원시 파일 42개 전부**가 남아 있음을 확인했다. RP5와 회수한 Host 파일의 SHA-256이 모두 같았으며 실험은 다시 실행하지 않았다. 재부팅 후 센서와 제한 이력은 별도 `cooling-after-reboot.json`에 보관하고, 이전 부팅에서 실행한 실험의 제한 여부를 판단하는 근거로 사용하지 않았다. 단절 원인은 미확인이다.

기존 `.venv/models/data/results/experiments` 비 Markdown **4,009개**를 전후 대조해 변경·누락 0을 확인했다. Python 실행 파일·버전과 NumPy/sherpa/core/Python ORT 버전도 같았다. 새 모델 다운로드·패키지 설치·OS 설정 변경은 없었다. 기존 **Host 190개·RP5 190개 테스트 통과 로그**도 회수해 확인했다. mock 테스트와 위 실제 모델 검증을 구분한다.

원시는 Host와 RP5의 `results/preflight/m3-vad-overlap-20261102-01`, 파생 WAV/출처는 `data/evaluation/m3-vad-overlap-20261102-01`, 계획·보존 영수증·회수 체크섬·분석 소스·단절 시점 checkpoint는 `results/maintenance/m3-vad-overlap-20261102-01`에 보관한다. 원본·기존 실행을 덮어쓰지 않으며 Git에는 코드·문서·작은 요약만 관리한다.
