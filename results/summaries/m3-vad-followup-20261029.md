# M3-0 후속: 실제 VAD·연속 전처리 검증

2026-10-29, 실행 ID `m3-vad-20261029-01`. **Silero VAD의 RP5 로딩·실행은 확인했지만, 실시간 구간 정책은 채택하지 않았다.** 원음 입력은 연속 저음량 발화를 놓쳤고, 공통 RMS 입력은 합성 잡음 오탐이 증가했다. 최대 음성 길이 설정도 강제 상한이 아니었다. 팬·히트싱크는 설치되어 있고 변경 없다는 사용자 답변을 기록했으며, 이전 고부하 냉각 실패가 해결된 것으로 보지 않는다. Hybrid 동시 실행은 보류한다.

## 검증 범위와 재현 근거

- Host에서 자료·코드를 준비하고 main push → RP5 pull 후 실행했다. 초기 API 검사는 `df3a7fb`, 주요 실측·전처리 회귀는 `fad62a4`, 후속 1배속 연속 입력 확인은 `bbcea5a`에서 실행했다.
- 원시 기록은 두 장비의 `results/preflight/m3-vad-20261029-01/`, 파생 입력은 `data/evaluation/m3-vad-20261029-01/`에 보존한다. Git에는 코드·문서·작은 요약만 포함한다.
- 기존 Python 3.11.18, NumPy 2.4.6, sherpa/core 2.0.1을 유지했다. sherpa 네이티브 ORT는 **1.28.2**, 별도 Python onnxruntime 패키지는 **1.31.1**이다. 패키지 설치·갱신은 하지 않았다.
- 별도 Silero VAD ONNX만 `models/silero-vad-k2-20261029/`에 추가했다. 기존 ASR 모델은 그대로다. 출처·MIT 라이선스·다운로드 파일 해시를 로컬 `provenance.json`/`LICENSE`에 보존했다. SHA-256은 `9e2449e1087496d8d4caba907f23e0bd3f78d91fa552479bb9c23ac09cbb1fd6`이다.
- 설정은 CPU 1T, 16kHz, 512프레임(32ms), threshold 0.5, 최소 음성 100ms, 종료 무음 300ms. 파일 앞 0.5초·뒤 1초 무음을 붙이고 파일마다 VAD를 reset했다. 연속 입력 파일 내부에서는 reset하지 않았다.
- 빠른 파일 입력 166개 × 3/5/8초 후보 × 2개 전처리 = **996행**. 사전 계획한 1배속 22개 × 2정책 = **44행**. 초기 KSS 50개 × 3후보 = **150행**. 연속 누락 발견 후 설정을 바꾸지 않고 1배속 연속 입력 2행을 추가했다. **총 1,192행**이며 독립 발화 1,192개가 아니다.
- 명시적인 VAD 워밍업 제외는 하지 않았다. 후보별 모델을 한 번 로드하고 로딩 시간을 별도 기록했다. ASR batch RTF와 비교하는 성능 순위 실험이 아니다.

## 검출: 단일 파일 지표만으로 판단하면 안 되는 이유

각 정책의 166개는 KSS 50개 × 원음/24dB 감쇠/감쇠+잡음 150개, 기존 무음 6개·장문 3개, Gaussian 잡음 6개, 연속 입력 1개다. 장문은 KSS 파일 연결 자료로, 무중단 자연 발화의 검증을 대신하지 않는다. 같은 개발 자료를 길이 후보별로 재사용했다. 이미 본 FLEURS를 최종 평가로 다시 사용하지 않았다.

| 항목 | 원음 VAD 입력 | RMS -26dBFS 후보 입력 |
| --- | ---: | ---: |
| 음성 파일 전체 누락(각 길이 후보) | 0/154 | 0/154 |
| 연속 파일 안 개별 발화 구간 전체 누락 | **5/9** | **0/9** |
| 순수 무음 오탐 | 0/6 | 0/6 |
| 합성 잡음 오탐 | **2/6** | **4/6** |
| 사전 정책 채택 기준 | 실패 | 실패 |

연속 입력은 짧은 원본 3개를 원음→감쇠→감쇠+잡음 순서로 연결한 약 20.705초 파일이다. 원음 VAD는 원음 3개를 검출했지만 감쇠 3개 중 2개와 감쇠+잡음 3개 모두를 놓쳤다. 이 결과는 3/5/8초 빠른 입력에서 같았고, **5초 설정의 1배속 재확인에서도 5/9 대 0/9**였다. 1배속과 빠른 입력의 반환 프레임 구간이 일치했다. 원음 연속 파일에도 일부 구간이 반환되므로 파일 전체 누락 수는 0으로 나타난다.

개별 파일 reset 조건의 감쇠 발화는 검출됐지만 연속 조건에서는 누락됐다. 상태·입력 위치·앞선 문맥의 영향이 원인 후보이며, 원인을 분리하는 실험은 하지 않았다. RMS가 모든 단어를 보존했다는 의미도 아니다. 현재 누락 지표는 원본 WAV 범위와의 겹침 여부이며 음소·단어 정렬이 없다.

잡음은 3초 Gaussian 입력 -55/-45/-35dBFS 각각 2개 seed다. 원음은 -35dBFS 두 개, RMS는 -45/-35dBFS 네 개에서 짧은 음성 구간을 반환했다. 길이 후보·1배속 검사에서도 같은 입력들이 오탐했다. 같은 잡음을 반복한 결과를 독립 표본으로 합치거나 실제 환경 오탐률로 일반화하지 않는다. 금칙어 필터나 사후 threshold 변경은 없다. **어느 VAD 입력 정책도 기본값으로 채택하지 않았다.**

실제 짧은 KSS 10개에서 가장 짧은 원본은 약 0.926초다. 200ms 안팎의 “네”·“응”, 실제 마이크 잡음·다화자, 단어 경계 잘림은 별도 검증이 필요하다.

## 길이 설정은 강제 상한이 아님

| VAD 길이 설정 | 원음의 실제 최장 구간 | 설정 초과 구간 수 | RMS의 실제 최장 구간 | 설정 초과 구간 수 |
| --- | ---: | ---: | ---: | ---: |
| 3초 | 6.112초 | 111 | 4.960초 | 102 |
| 5초 | 6.112초 | 8 | 5.824초 | 4 |
| 8초 | 6.564초 | 0 | 5.848초 | 0 |

[설치된 v2.0.1의 구현](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.1/sherpa-onnx/csrc/voice-activity-detector.cc)을 확인하면 `max_speech_duration` 초과 시 threshold를 0.90, 종료 무음을 0.1초로 바꾸며 정확한 프레임에서 강제 절단하지 않는다. 8초에서 이번 자료의 초과가 0이었다고 상한 보장을 뜻하지 않는다.

파일 진단 버퍼를 최대 입력 길이+3초로 확보하고 180초 초과 파일을 거부하도록 보완했다. 이 방식은 실시간 서비스의 유한 링버퍼가 아니다. Refine를 일정 간격 안에 시작하려면 **도착한 활성 음성 프레임을 별도 소유 범위로 확정하는 강제 구간 처리**가 필요하다. 완료된 VAD 구간을 사후 분할하는 것만으로는 처리 시작 지연을 제한할 수 없다. 현재는 이 처리기·결과 병합을 구현하지 않았다.

## 지연·자원·냉각

사전 계획한 1배속 짧은 원음 KSS 10개에서 VAD 반환 시각을 **원본 WAV 끝**과 비교했다. 실제 음성 끝 정렬이 없어 아래 값은 대리 지연이다.

| 1배속 입력 정책 | WAV 끝 기준 p50 / p95 | VAD 계산 RTF | 전체 호출 시간 기준 평균 CPU | 관측 최대 프로세스 RSS |
| --- | ---: | ---: | ---: | ---: |
| 원음 | 0.275 / 0.329초 | 0.01281 | 1.49% | 67.88 MiB |
| RMS | 0.275 / 0.329초 | 0.01307 | 1.52% | 68.42 MiB |

지연의 표본은 정책별 10개, 나머지 자원 집계는 무음·잡음을 포함한 22개다. 계산 RTF의 분자는 입력 대기를 제외한 VAD 호출·구간 회수 시간, 분모는 앞뒤 무음과 512프레임 반올림을 포함한 실제 공급 오디오다. WAV 읽기·파생 RMS 생성·ASR·Refine는 제외한다. CPU 분모에는 1배속 대기가 포함된다. RSS는 Python/NumPy와 파일 버퍼를 포함하므로 모델 가중치만의 메모리가 아니다.

빠른 입력의 계산 RTF는 0.00867~0.00888, 평균 CPU는 약 100%, 관측 최대 RSS는 90.41~114.80 MiB였다. 다른 입력 속도·동적 클럭 조건이므로 RTF 차이를 최적화 효과로 해석하지 않는다. 입력기는 같은 스레드에서 기다리는 형태다. 지각 도착 시각을 기록했지만 독립 수집 큐가 없으므로 **드롭·백로그는 null**이다. 실제 음성 끝 기준 지연, 첫 자막, Refine 확정 지연도 측정하지 않았다.

연속 입력 RMS의 감쇠+잡음 세 구간은 WAV 끝 대리 지연이 0.470/0.522/0.564초였다. 짧은 원음 10개의 p95만으로 전체 조건을 대표하지 않는다. 원음의 한 검출 구간은 대리 지연 -0.036초이며 원시 값과 null 누락 값을 그대로 보존했다.

| 실행 | 시작 온도 | 최대 관측 온도 | 현재 제한 비트 |
| --- | ---: | ---: | ---: |
| 빠른 입력 원음 / RMS | 52.35 / 52.35°C | 61.70 / 62.80°C | 모두 0 |
| 1배속 짧은 입력 원음 / RMS | 52.90 / 50.70°C | 55.65 / 53.45°C | 모두 0 |
| 1배속 연속 입력 원음 / RMS | 49.60 / 51.25°C | 52.35 / 52.35°C | 모두 0 |

외부 600초 timeout·4GiB 주소 공간 제한을 실제 PID에서 확인했고 모든 이번 VAD 실행은 통제 조건 안에서 완료했다. 1Hz 온도/클럭/팬·TID CPU 기록을 남겼다. 과거 제한 이력 `0xe0000`은 유지됐고 새로운 비트는 관측되지 않았다. 표본 사이 짧은 제한이나 기존에 켜진 이력 비트의 재발은 배제할 수 없다. 고정 클럭·실내 온도·열평형이 같다는 뜻은 아니다.

이전 [M3-0 결과](m3-0-preflight-20261029.md)의 Zipformer 2T 76°C 중단을 뒤집지 않는다. 사용자 보고는 “팬·히트싱크 설치, 변경 없음”이며 접촉·풍량·통풍의 실제 적정성은 원격으로 확인하지 못했다. 가벼운 VAD 성공으로 ASR 동시 실행의 냉각을 승인하지 않는다.

## 구현·회귀·보존

- `AudioPreprocessor.process_block()`에 gain/RMS 상태를 유지하고 `reset()`으로 새 세션을 시작하는 계약을 추가했다. 기존 파일 `preprocess()`는 호출마다 초기화하며 출력 계약을 유지한다. 100ms가 모여야 계산하는 수집 지연은 사라지지 않는다.
- Host에서 과거 파생 PCM 450개, 기존 파일 API, 새 블록 API가 바이트 일치했다. RP5에서도 기존 450개 출력과 새 구현이 모두 일치했다. 별도 전처리 계산 RTF는 원형 0.02543, gain12 0.02544, RMS 0.02546이었다. 이미 읽은 PCM의 파일 단위 계산으로, 실제 수집·ASR와 결합한 지연은 아니다.
- VAD에는 미리 생성한 RMS WAV를 공급했다. 연속 전처리 API와 VAD를 하나의 1배속 파이프라인으로 연결한 실측은 아직 없다. 새 ASR CER·RTF를 측정한 것으로 기록하지 않는다.
- **Host 134개 테스트 통과(4.993초), RP5 134개 통과(8.994초)**. RP5의 실제 VAD 1,192행과 단위 테스트를 구분한다. 기존 ASR 테스트는 통과했으며 이번 후속 작업에서 기존 ASR 추론을 다시 실행하지 않았다.
- 기존 모델·환경·데이터·과거 결과 **3,801개 파일 해시 일치**, 설치 패키지 목록/버전 동일, 삭제·변경 0. 초기 고정 원시 48개도 후속 작업 뒤 동일했다. RP5에서 마지막으로 고정한 **67개 기록을 Host로 옮겨 해시 일치**를 확인했다. 해시 목록 자체의 SHA-256은 `bd7eedfd8216853672cab2e7831cbd3d9d34e840e874702e1584f2e176a0476f`다.
- 변경 범위: `src/edge_asr/audio_policy.py`, `src/edge_asr/vad_probe.py`, `scripts/m30_vad_probe.py`, 새 자료 준비·집계 스크립트, 관련 테스트 4개 파일, 한국어 안내·이번 요약. 기존 설정·모델·M1/M2/M3-0 원시 결과는 수정하지 않았다.

## 다음 순서와 완료 기준

1. **짧은 응답·잡음·연속 문맥 검증을 먼저 보완한다.** 현재 누락/오탐 사례를 고정 회귀 목록에 유지하고, 출처·라이선스를 기록한 추가 개발 자료와 사람 검수 음성 경계를 준비한다. threshold와 종료 무음 후보는 새 실험 전에 고정하며, 현재 실패 기록을 덮어쓰지 않는다. 보지 않은 최종 평가 자료는 별도로 유지한다. 원음/RMS 중 어느 쪽도 현재 승인하지 않는다.
2. **활성 프레임 구간 처리기를 Host에서 구현한다.** 단조 프레임 번호, `[start,end)` 소유 범위, 별도 200ms 왼쪽 문맥, VAD 종료와 무관한 3/5/8초 강제 상한, 최대 버퍼 크기, flush 계약을 분리한다. 경계별 소유 프레임 중복·누락 0, 반환 구간 상한 준수, 문맥과 소유 범위의 분리, 버퍼 상한을 테스트한다. 단어 보존 합격은 정렬 자료에서 별도 확인한다.
3. **전처리+VAD+구간 처리기만 1배속으로 검증한다.** 100ms 전처리 블록을 512프레임 VAD 입력으로 다시 묶고 남은 프레임을 보존한다. 세션 내 gain/VAD 상태 유지, 독립 수집 큐의 도착·처리 시각, 입력 드롭/백로그를 계측한다. 두 ASR가 나중에 같은 전처리 PCM을 받도록 저장하며 Refine 구간별로 다시 정규화하지 않는다.
4. **냉각 원인을 확인한 후 M3-1 동시 실행으로 넘어간다.** 팬 동작·방열판 접촉·케이스 통풍·주변 온도를 확인하거나 재현 가능한 저부하 운용 조건을 정하고, 기존 외부 감시로 재검증한다. 통과 전 고부하 비교를 재개하지 않는다. 이후 Zipformer 1T+SenseVoice 1T, 1T+2T, 2T+1T를 각각 새 ID로 실행한다.
5. **M3-1 범위는 계측용 동시 실행기까지다.** 모델별 독립 프로세스/한 번 로드, Streaming 큐와 Refine 대기 큐 분리, 포화 시 skip 이유·프레임 범위 기록, enqueue/start/finish 시각, 첫 부분 출력, CPU/RSS/TID·온도·드롭·최대 백로그를 측정한다. 단독 Streaming과 같은 입력으로 비교한다. 첫 통과 기준은 계측 완결·현재 제한 없음·입력 드롭 0·유계 큐·OOM/hang 없음이며, 서비스 지연/허용 skip 기준은 별도로 정한다. 단독 batch 결과로 동시 성능을 예측하지 않는다.
